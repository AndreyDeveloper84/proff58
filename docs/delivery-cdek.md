# Доставка СДЭК по России (DRF-2299)

Решения владельца от 24.09.2026: доставка по всей России, в пункт выдачи и курьером.
Упаковку задают по разделам каталога, у отдельного товара её можно уточнить. Отправление
в СДЭК сайт создаёт сам после оплаты (это следующий шаг, PR C).

## Как считается цена

1. Покупатель выбирает город, затем пункт выдачи или вводит адрес для курьера.
   Чекаут вызывает `POST /api/cart/delivery-quote/`.
2. Сервер берёт серверную корзину и упаковку каждой штуки: сначала у товара, иначе у
   ближайшего раздела выше (`apps/catalog/packaging.py`). Штуки раскладываются по
   посылкам до 30 кг (`apps/delivery/packaging.py`).
3. СДЭК считает тариф «Посылка» (`apps/integration_ship/services.py::cdek_quote`).
   Покупатель платит `total_sum`: доставка с НДС СДЭК и страховкой на стоимость товаров.
   Если настроенного тарифа на маршруте нет, берётся самый дешёвый тариф того же
   режима.
4. Расчёт хранится в кеше 30 минут (`CDEK_QUOTE_TTL`) под `quote_id`. При оформлении
   заказа (`POST /api/orders/` с `delivery_quote_id`) сервер только сверяет, что корзина
   и способ доставки не менялись. К СДЭК внутри транзакции заказа запросов нет.
   - расчёт истёк → 409 `delivery_quote_expired`;
   - корзина или способ изменились → 409 `delivery_quote_stale`.
   В обоих случаях чекаут пересчитывает доставку.

Когда цены нет, заказ всё равно оформляется в статусе «стоимость рассчитает менеджер»
(`manual_required`), онлайн-оплата закрыта до расчёта. Причина лежит в
`delivery_snapshot.reason`:

| reason | Что случилось | Что делать |
|---|---|---|
| `missing_package` | у товара и его разделов не задана упаковка | заполнить упаковку раздела (`manage.py catalog_packaging_report --missing`) |
| `overweight` | одна штука тяжелее 30 кг | посчитать вручную (грузовой тариф) |
| `no_tariff` | СДЭК не возит этот груз по маршруту | посчитать вручную или предложить самовывоз |
| `provider_unavailable` | СДЭК не ответил или отверг ключи (во втором случае в логе ERROR) | проверить `CDEK_*`, посчитать вручную |
| `provider_disabled` | СДЭК выключен настройками | — |
| `no_carrier_quote` | заказ пришёл без расчёта (старый чекаут) | посчитать вручную |

Город, пункт выдачи или адрес попадают в заказ и в этих случаях тоже, так что
менеджеру не нужно переспрашивать покупателя.

## Устойчивость

- Таймауты: соединение 3 с (`CDEK_CONNECT_TIMEOUT`), чтение 7 с (`CDEK_TIMEOUT`).
- После сбоя сети, 5xx, 429 или непонятного ответа сайт минуту не ходит в СДЭК и сразу
  отвечает «СДЭК недоступен». Так зависший СДЭК не занимает потоки сайта.
- Если СДЭК не ответил на запрос пунктов или города, тариф не запрашивается: сразу
  ручной расчёт.
- Сбой кеша (Redis) расчёт не ломает, только замедляет. Исключение — сохранение
  расчёта для оформления: без кеша оформить заказ с расчётом СДЭК нельзя.

## Правила

- Способы получения: `cdek_pvz` (пункт выдачи) и `cdek_courier` (курьер до двери).
  Оплата только онлайн. Слоты своего курьера для СДЭК не выбираются. Юрлицам доставка
  по-прежнему недоступна (ADR-0013 §B.9).
- Адрес заказа сервер собирает из расчёта: «СДЭК, пункт выдачи MSK123, Москва, …».
  Название города берётся у СДЭК по коду, а не из браузера.
- Если пункт выдачи принимает меньше 30 кг, посылки делятся по его пределу. Штука
  тяжелее предела даёт ошибку «выберите другой пункт или курьера».
- Промокод «бесплатная доставка» на СДЭК не действует, пока не включён
  `PROMO_FREE_DELIVERY_EXTERNAL=True`.
- Порог «бесплатно от» своей курьерской доставки к СДЭК не применяется.

## API для чекаута

| Метод | Путь | Что отдаёт |
|---|---|---|
| GET | `/api/delivery/cdek/cities/?q=Пен` | города (от 2 символов), кеш 1 ч |
| GET | `/api/delivery/cdek/points/?city_code=504` | пункты выдачи города, кеш 30 мин |
| POST | `/api/cart/delivery-quote/` | `quote_id`, `status`, `cost`, `period_min/max`, `reason`, `address` |

Если СДЭК выключен или не отвечает, справочники возвращают 503. В ответе расчёта
`free_delivery_promo_applies` говорит, действует ли на СДЭК промокод «бесплатная
доставка»: при `false` чекаут не показывает доставку за 0.

Выпускать эти эндпоинты можно только вместе с чекаутом (PR B). Им нужны точные
`location` в nginx и BFF-роуты во фронте по образцу `cart/promo` и `delivery/zones`,
иначе у вошедшего покупателя POST упадёт на CSRF. Лимиты по IP:
`DELIVERY_LOOKUP_THROTTLE_RATE` (120/мин) и `DELIVERY_QUOTE_THROTTLE_RATE` (30/мин).

## Включение

```env
FEATURE_EXTERNAL_SHIP=True
SHIP_PROVIDER=cdek
CDEK_API_URL=https://api.cdek.ru/v2
CDEK_ACCOUNT=...            # личный кабинет СДЭК → «Интеграция»
CDEK_SECURE=...
CDEK_FROM_CITY_CODE=504     # Пенза
CDEK_SHIP_FROM=warehouse    # магазин сдаёт в пункт СДЭК (136/137); door — СДЭК забирает (138/139)
```

Прод не стартует, если СДЭК включён без адреса API и ключей. Тестовый контур
`https://api.edu.cdek.ru/v2` в проде разрешён только с `CDEK_ALLOW_TEST=True` (для стенда).
В dev пустой `CDEK_API_URL` означает тестовый контур с публичными ключами СДЭК.

Живая проверка клиента против тестового контура:

```bash
docker run --rm --network host -v "$PWD":/app -w /app -e CDEK_LIVE=1 proff58-web:latest \
  pytest -q -p no:cacheprovider apps/integration_ship/test_cdek_live.py
```

## Открытые вопросы владельцу

- Боевые ключи СДЭК.
- Кто везёт посылки в СДЭК: магазин сам (`warehouse`) или СДЭК забирает (`door`).
- Упаковка по разделам каталога: кто и когда заполняет.
- Промокод «бесплатная доставка» на СДЭК: включать ли.
- Бухгалтеру: нужен ли в чеке признак агента за доставку.
