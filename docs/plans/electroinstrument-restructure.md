# Перестройка раздела «Электроинструмент» — детальный план (runbook)

- Статус: **направление утверждено**; команда `catalog_taxonomy_apply`
  реализована (dry-run/commit/rollback). Следующий шаг — **только `--dry-run` на
  staging**; `--commit` — отдельно после подтверждения цифр владельцем.
- Связано: `docs/plans/catalog-taxonomy-redesign.md` (§4 А/А′, §5), ADR-0001
  (tool_type — ось, не дерево), ADR-0007 (дерево мастерится на сайте), PR #230
- Метод: воспроизводимая management-команда `catalog_taxonomy_apply`
  (`--dry-run` по умолчанию → `--commit`), с бэкапом (`var/restructure/`) и `--rollback`

**Зафиксированное временное SEO-решение (по условию владельца):** модели redirect
и canonical/noindex для параметрических URL ещё НЕТ. Поэтому 301 со старых узлов
ведём на раздел **БЕЗ параметра** (`/catalog/elektroinstrument`) — исключаем дубли.
Параметрический таргет (`?attr_power_source=mains|battery`) включаем позже, когда
будет canonical/noindex. Сайт закрыт (`robots Disallow`) — текущий SEO-риск нулевой.
Само создание 301 и обновление seed-маппинга `data/group_mapping.json` (O5/O6) —
отдельные шаги Фазы 3 (команда их в `--commit` пока не делает, только перечисляет).

## 1. Целевое состояние (из утверждённых решений)

```text
Электроинструмент            (elektroinstrument)   ← раздел, плоский
│   • товары-инструменты лежат прямо в разделе
│   • навигация — TypePanel по tool_type (УЖЕ работает: Перфораторы/Дрели/УШМ…)
│   • питание — фильтр power_source (УЖЕ работает: Аккумулятор/Сеть)
│
└── Аккумуляторы и ЗУ          (akkumulyatory-zu)    ← комплектующие, остаётся
        подкатегорией (344); это НЕ ось питания инструмента
```

Убираем: узлы **«Сетевой инструмент»** и **«Аккумуляторный инструмент»** —
разница питания уже покрыта фасетом `power_source`, отдельные ветки не нужны.

## 2. Операции и dry-run-эффект

| # | Операция | Объём | Как |
|---|---|---:|---|
| O1 | Перенести товары «Сетевой инструмент» → «Электроинструмент» (плоско) | 1971 | `Product.category = elektroinstrument`, `category_is_manual=True` |
| O2 | Перенести товары «Аккумуляторный инструмент» → «Электроинструмент» | 694 | то же |
| O3 | «Аккумуляторы и ЗУ» оставить подкатегорией | 344 | без переноса (уже на месте) |
| O4 | Скрыть опустевшие узлы «Сетевой инструмент», «Аккумуляторный инструмент» | 2 узла | `on_site=False` (не удалять сразу — безопаснее; удалить в отдельном шаге после проверки) |
| O5 | 301-redirect со старых slug на раздел | 2 правила | `setevoy-instrument`, `akkumulyatornyy-instrument` → `elektroinstrument` (+ опц. `?power_source=`) |
| O6 | Обновить seed-маппинг `data/group_mapping.json` | N 1С-групп | site_path этих групп → `["Электроинструмент"]`, чтобы будущий импорт не воссоздал старые ветки |

**Итог переноса:** 2665 товаров меняют категорию; 344 остаются; 2 узла скрываются.

> Примечание по TypePanel: чипы «Аккумуляторы»/«Зарядные устройства» в панели
> типов исчезнут вместе с переносом их товаров в подкатегорию-комплектующие
> (панель агрегирует tool_type товаров раздела). Отдельная правка кода не нужна;
> если захотим скрыть комплектующие из TypePanel совсем — отдельный мелкий шаг.

## 3. Спецификация команды `catalog_taxonomy_apply`

```bash
# по умолчанию — БЕЗОПАСНО: только показать план, БД не трогать
python manage.py catalog_taxonomy_apply --section electroinstrument

# применить (в транзакции, с бэкапом для отката)
python manage.py catalog_taxonomy_apply --section electroinstrument --commit

# откатить по бэкапу
python manage.py catalog_taxonomy_apply --rollback var/restructure/electroinstrument-<ts>.json
```

- **`--dry-run` (по умолчанию):** печатает таблицу из §2 с реальными счётчиками
  на текущей БД, НИЧЕГО не меняет. Выходной формат — как таблица «Операции».
- **`--commit`:** всё в одной `transaction.atomic()`:
  1. снимок отката `var/restructure/electroinstrument-<ts>.json`
     (`[{product_id, old_category_id, old_manual}]` + старые узлы/slug);
  2. O1–O6;
  3. `transaction.on_commit` → `product_updated` по перенесённым id (инвалидация
     фасет-кэша/переиндексация), как в bulk-actions админки.
- **Идемпотентность:** повторный `--commit` — no-op (товары уже `manual` и в
  целевой категории; узлы уже скрыты). Сверка по состоянию, не по флагу запуска.
- **`--rollback`:** восстанавливает `Product.category`/`category_is_manual` и
  видимость узлов из снимка.
- **Бэкап-каталог** `var/restructure/` — в `.gitignore` (артефакт рантайма).

## 4. Slug / redirect

- `elektroinstrument` — латиница, не меняется.
- `akkumulyatory-zu` — проверить текущий slug подкатегории; если кириллица →
  латинизировать + 301 со старого.
- Старые `setevoy-instrument` / `akkumulyatornyy-instrument` → 301 на раздел.
- Сайт ещё закрыт (`robots Disallow`) — redirect-долг минимален, но правила
  заводим сразу (модель redirect — в рамках Фазы 3, если ещё нет).

## 5. Проверка на staging (`dev.proff58.ru`) после `--commit`

1. `/catalog/elektroinstrument`: чипов «Сетевой»/«Аккумуляторный» больше нет;
   остался чип «Аккумуляторы и ЗУ».
2. TypePanel (Перфораторы/Дрели/УШМ…) на месте, счётчики пересчитались.
3. Фильтр «Питание» (Аккумулятор/Сеть) работает и даёт прежние выборки.
4. Нет пустых веток и «битых» хлебных крошек.
5. Старые URL дают 301 на раздел.
6. Счётчики в админке (`/admin/catalog/category/`, колонки «Товаров»/«Опубл.»)
   соответствуют ожиданиям (раздел ≈ сумма перенесённого + комплектующие).

## 6. Риски и страховка

- **Необратимость данных** → бэкап + `--rollback`; сначала staging, потом prod.
- **Импорт 1С «отыграет» назад** → снято: переносим с `category_is_manual=True`
  (ADR-0007) + обновляем seed-маппинг (O6), так что и существующие, и новые
  товары идут в новую структуру.
- **Гонка с обменом** → выполнять в окно без активного импорта; команда в одной
  транзакции.
- **SEO** → сайт закрыт, плюс 301; долг минимален.

## 7. Что НЕ входит и делается отдельно

- Удаление (не скрытие) опустевших узлов — после подтверждения на staging.
- Скрытие комплектующих из TypePanel (если решим) — мелкий шаг.
- Остальные разделы (Оснастка/Ручной/Сварка) — следующие итерации Фазы 2.
