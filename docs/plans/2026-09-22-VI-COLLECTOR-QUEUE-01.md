## 2. Правила, общие для всех волн

1. **Один прогон за раз.** Коллектор однопользовательский: один Chrome на хост, следующий пул —
   только после завершения предыдущего.
2. **Каждый новый пул начинается с пилота на 30 SKU.** Выборка детерминированная, по стратам.
   Порог владельца (из BURY-MEDIA-PILOT-01):
   - strict ≥ 70 % → GO на весь пул;
   - 40–69 % → ADJUST (алиас, нормализация артикула), потом повторный пилот;
   - < 40 % → STOP, пул уходит в «другой источник».
3. **Перед пилотом** проверить старые `out-live/*/matches.json` — там уже могут быть
   strict-совпадения для этих SKU.
4. **Apply — только по протоколу revN** (`drills-media-pipeline`): свежая проверка остатка →
   `03-download-validate` → `04-build-manifest revN` → backup + snapshot → io < 20 →
   `05-apply` через `ImagePipeline` → проверка идемпотентности → verify. Применять пачками по мере
   накопления MATCHED, не дожидаясь конца пула.
5. **CAPTCHA = STOP.** Не обходить; продолжение через `--resume` после паузы и решения.
6. **SEO не трогаем.** Товары с фото **не** попадают в индексацию автоматически —
   для этого нужен отдельный гейт и allowlist (`docs/runbooks/seo-indexing-release.md`).

## 5. Решения владельца (2026-09-22)

1. **Волна 1 — весь пул сразу**, без пилота 30. Для волн 2 и 3 пилот остаётся.
2. **Коллектор работает круглосуточно.**
3. **Для групп «Не запускать» (~2 300 SKU) — отдельный трек поиска другого источника.**
4. **Индексация — партиями:** товары с фото попадают в allowlist после гейта, на каждую партию отдельный GO.
