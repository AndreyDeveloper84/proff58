Исходные описания — `docs/plans/2026-09-20-customer-feedback-tasks.md` (UX-01…UX-07,
PERF-01, DATA-01). Здесь — как именно они делаются и какие решения приняты.

## Рамка

- Ветка `feature/customer-feedback-0920` от `origin/dev`, отдельный worktree
  `/home/shiro/proff58-feedback`. Основное дерево содержит чужие незакоммиченные
  правки витрины — их не трогаем.
- Один коммит на задачу (Conventional Commits). Push и PR — только по просьбе.
- Описания задач составлялись по другому дереву. В `origin/dev` поиск уже переведён
  на `SearchShell` + `fetchSearchListingFromApi` (DRF-1166), поэтому часть фактов
  PERF-01 («неуспешный ответ = пустой список») относится только к `fetchSearchFromApi`,
  который страницей поиска больше не используется.
- Baseline фронта: 72 файла / 440 тестов зелёные. `tsc --noEmit` даёт 5 ошибок
  `RouteContext` в трёх route handlers — они есть до правок (нет сгенерированных типов).

## UX-01

`THEME_INIT_SCRIPT`: сохранённый `light|dark` → иначе `light`. Убрать `matchMedia`
из скрипта и подписку `onSystemChange`. Событие `storage` оставить (синхронизация
вкладок). Тест «берёт системную тему» заменить на «системная тёмная не влияет» и
добавить тест на бросающий `localStorage`.

## UX-06

`CartItemRow`: `<span>` → `<input type="text" inputMode="numeric" pattern="[0-9]*">`
(не `type=number`: тот пропускает `e`, `-`, дробь и крутится колесом).

- Черновик хранится локально строкой. Применение — Enter или blur. Escape — откат.
- Единое правило для пустого и невалидного ввода: значение не отправляется, поле
  возвращается к прежнему числу, под полем появляется сообщение
  «Введите целое число от 1».
- Валидно: `/^\d+$/`, `>= 1`, `Number.isSafeInteger`. Ноль не удаляет товар.
- Дедупликация: `submittedRef` хранит последнее отправленное значение. Enter, затем
  blur с тем же числом — один запрос. Значение, равное `line.quantity`, не отправляется.
- Кнопки ± считают от `submittedRef ?? line.quantity`, чтобы не откатить только что
  введённое число.
- `onUpdate` возвращает `Promise<boolean>`: при ошибке поле возвращается к серверному
  значению, под ним — «Не сохранено», причина остаётся в общем `role="alert"` страницы.
  `run()` в `app/cart/page.tsx` начинает возвращать успех.
- Лимита 99 нет. Остаток на этапе корзины backend не проверяет (проверка — при
  оформлении, `apps/orders/services.py`), поэтому фронт её не выдумывает.
- Пробел контракта: `IntegerField(min_value=1)` без верхней границы при
  `PositiveIntegerField` даёт 500 на числе больше 2 147 483 647. Добавить
  `max_value=2_147_483_647` в оба сериализатора количества (`apps/orders/api/serializers.py`)
  и тест на 400. Это технический предел столбца, а не товарный лимит.
- Ширина поля — по числу знаков (`ch`), минимум 3 знака.

## UX-07

Backend (`apps/catalog`):

- `brand_slugs.brands_for_page_slug(slug) -> list[str]`: все видимые бренды, у которых
  `slugify_value(brand) == slug`. Суффиксы `-2/-3` здесь не участвуют, поэтому ссылка
  `/brands/metabo` не зависит от состава брендов — это и есть решение по стабильности.
  Разные написания с одним base-slug («Bosch»/«BOSCH», «Зубр»/«Zubr») сливаются в одну
  страницу — намеренно.
- `ProductFilter.brand_slug` — новый параметр `products/?brand_slug=metabo`
  (OR по `brand__iexact` группы). Существующий `brand` не меняется.
- `facets.build_brand_facets(brands, category=None, stock_status, price_min, price_max)`:
  `total_products`, `price`, `stock`, `categories` (категория товара, счётчик,
  `selected`; ось категории считается без фильтра категории — drill-down как у поиска).
- `GET /api/catalog/brands/<slug>/` → `{brand: {slug, name}, …facets}`. `name` — самое
  частое написание. 404, если бренда нет ни у одного товара (включая скрытые);
  бренд только у скрытых товаров → 200 с `total_products: 0`.
- Тесты: точность (товар с брендом в описании/названии чужого бренда не попадает,
  товар без бренда в названии — попадает), регистр, счётчик = полной выдаче, категория
  сужает, 404/пустой бренд, стабильность slug при добавлении коллизии.

Frontend:

- `app/brands/[slug]/page.tsx` (+ `loading.tsx`, `error.tsx`): заголовок «Товары Metabo»,
  количество, сортировка, пагинация, сайдбар (цена, наличие), чипы категорий со
  счётчиками. URL: `/brands/metabo?category=krugi&sort=price_asc&page=2`.
- `SearchShell` обобщается: вместо `q` — `preserveParams: Record<string,string>` и
  подпись сортировки по умолчанию. Поиск передаёт `{q}`, бренд — `{category}`.
- Состояния: неизвестный slug → `notFound()`; известный бренд без товаров (в том числе
  из курируемого списка главной, даже если API ответил 404) → страница «Товаров
  <Бренд> сейчас нет в каталоге» со ссылкой на поиск по названию и на каталог.
- `HOME_CONTENT.popularBrands` остаётся списком названий; рядом — `popularBrandSlugs`
  с замороженными slug (`metabo`, `resanta`, `dewalt`, …). `PopularBrands` ведёт на
  `/brands/<slug>`. Тест обновить.

## PERF-01

Устройство и время события неизвестны — воспроизведение честно ограничено.

1. Замеры без правок: TTFB `/search?q=<бренд>` и API `products/?search=` на
   proff58.ru, холодный/тёплый, 9 брендов; 20 переходов по плитке бренда в headless
   Chrome (CDP, настоящие Input-события), desktop и мобильный viewport, с троттлингом.
   Фиксируем: дошёл ли click, перекрывает ли что-то элемент, время до смены URL и до
   контента, ошибки консоли.
2. Правки по подтверждённым пробелам: `AbortSignal.timeout` (10 с) на листинг, поиск,
   товар и бренд; `loading.tsx` для `/search`, `/brands/[slug]`, `/catalog/[category]`
   (мгновенная реакция на клик); `error.tsx` с «Повторить» для `/search` и `/brands`
   (ошибка ≠ «ничего не найдено»); `fetchSearchFromApi` перестаёт глотать ошибку.
3. Отчёт `docs/perf/2026-09-20-brands-click-investigation.md`: условия, цифры до/после,
   что не воспроизведено. Повтор сценариев на `/brands/*` после UX-07.

## UX-03

- `components/contacts/CopyContact.tsx` (client): кнопка с видимым текстом контакта,

  подпись остаётся сокращённой `store`).
- Звонок — отдельная ссылка «Позвонить» (`tel:`), видимая подпись.

## UX-02 + UX-04

- Токены: новый `--card` (светлая `#ffffff`, тёмная `#1c2024`) → утилита `bg-card`;

## DATA-01

- Порядок характеристик — по кураторскому `CategoryAttribute.sort_order` с
  наследованием от предков (ближайшая категория первой), затем по имени; `tool_type` —
  последним (дублирует название и раздел). Один и тот же порядок в list и detail API →
  карточка, быстрый просмотр и страница товара совпадают.
- Реализация без N+1: `queries.attribute_order_for_categories(category_ids)` — два
  запроса на страницу (пути предков через `path` treebeard + `CategoryAttribute`),
  результат кладётся в context сериализатора, как `price_map`.
- Фронт: `ProductSpecs` — `<dl>` из 2–3 пар «Название: значение»; домашняя карточка —
  2 пары. Пустые значения не создают строк; `0` и «Нет» сохраняются (тест адаптера).
- PDP: основные параметры (первые 6 в том же порядке) + полная таблица; перенос длинных
  значений, проверка 320–375 px.
- Аудит данных: скрипт по боевому API, выборка ≥ 10 товаров разных разделов →
  `docs/catalog/2026-09-20-specs-audit.md` с примерами API, проблемами (в т.ч. пустой
  бренд при бренде в названии) и правилами исправления. Данные не дописываем.

## UX-05

- `QuickViewProvider` в layout: `open(product, trigger)`. `ProductCard` перехватывает
  только обычный левый клик по фото и названию (без Ctrl/Cmd/Shift/Alt, `button === 0`);
  `href` остаётся настоящим. Кнопки покупки/избранного/сравнения вне ссылок — не задеваются.
- Данные: BFF `GET /api/catalog/quick-view?slug=` → `fetchProductFromApi` без секций
  совместимости; точечный `location` в `docker/nginx/default.conf` (иначе `/api/` уйдёт
  в Django). Ничего не грузится до клика.
- Диалог: мгновенно показывает данные из карточки списка, догружает галерею и
  характеристики. `AbortController` + номер запроса против ответа предыдущего товара.
  Загрузка, ошибка с «Повторить». Фокус-ловушка, Escape, клик по фону, возврат фокуса на
  триггер, блокировка прокрутки фона. Мобильный — на весь экран.
- Покупка — существующий `AddToCartButton` (общий `CartProvider`). «Подробнее о товаре» —
  ссылка на `/product/<slug>`.

## Итоги ревью плана (субагент-архитектор, 20.09.2026)

Принято:

1. **UX-07, бедная точная выдача.** Под точной выдачей бренда — отдельная ссылка
   «Ещё N товаров с „Metabo“ в названии» (счётчик из поиска), список не смешивается.
   Заполнение поля бренда — существующая `catalog_fill_brand` (BRAND-02); `--apply`
   на стенде — решение владельца, в эту работу не входит.
2. **DATA-01, порядок.** `CategoryAttribute.sort_order` загрузчиком не заполняется, а
   порядок блоков `attribute_rules.json` — порядок извлечения, не показа (у дрелей
   первой идёт масса). Вводится курируемый `data/card_attribute_order.json`:
   общий ранжированный список slug + переопределения по `tool_type`. Модуль
   `apps/catalog/attribute_display.py`, без запросов к БД (всё из prefetch).
   Ненулевой `CategoryAttribute.sort_order` не используется — одна схема порядка.
3. **UX-06.** На время запроса поле `readOnly` + `aria-busy`, `disabled` — только у
   кнопок; ref отправленного значения живёт, пока запрос в полёте; ± считают от
   `line.quantity`; шрифт поля сразу 16 px; тест «ввод → клик +».
4. **UX-07, резолв.** Карта «base-slug → написания» по ВСЕМ товарам с признаком
   видимости, в версионном кэше фасетов; фильтр — `brand__in` по точным написаниям;
   две схемы slug (фасет PLP `bosch-2` и страница `bosch`) описаны в докстринге.
5. **DATA-01, потребители.** Порядок считается внутри сериализатора (не зависит от
   забытого context), одинаково для list и detail; «ключевые» = тот же фильтр
   `is_filterable or is_comparable`, detail дополнительно отдаёт остальные после них.
6. **PERF-01.** Причина согласуется с замерами: у `/search` нет `loading.tsx`, переход
   ждёт SSR 2–10 с без индикации. Разложение Next/Django — разницей «страница − API»
   и замером отдельных эндпоинтов; логи nginx и `EXPLAIN` на стенде требуют доступа к
   серверу и остаются рекомендацией.
7. **PERF-01, детали.** Мёртвые `searchProducts`/`fetchSearchFromApi` удалить; таймаут —
   параметр; товар и совместимость — параллельно; общий компонент «Повторить»
   (`router.refresh()` + `reset()`); смена одних `searchParams` — индикация через `isPending`.
8. **UX-07, пустые состояния.** «Бренда нет» — по нефильтрованному счётчику; ноль из-за
   фильтров оставляет оболочку и сброс; сброс фильтров снимает и категорию.
9. **UX-05.** Данные — существующий `GET /api/catalog/compare?slugs=<slug>`, nginx не
   трогаем. Перехват клика включается пропсом/наличием провайдера, карточка работает
   без него. Лайтбокс внутри быстрого просмотра отключён (иначе Escape закрывает оба слоя).
10. **UX-06, backend.** Кроме `max_value` — clamp суммы в `add_to_cart`.
11. **UX-01.** Обработчик `storage` применяет тему к DOM; комментарий о системном
    дефолте переписать.

Принято к сведению: UX-02/UX-04 пересекаются с незакоммиченными правками основного
дерева (Header, Footer, cart, layout, PopularBrands, AddToCartButton) — конфликт при
слиянии решает тот, кто вольёт вторым; `--bg` проверить на `PromoCodeField`.
