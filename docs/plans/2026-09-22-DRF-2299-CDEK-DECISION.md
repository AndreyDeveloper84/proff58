# DRF-2299 — СДЭК: что есть, что нужно для решения, что закрыто без него

Дата: 2026-09-22. Ветка: `fix/delivery-manual-required-no-false-totals`.

## 1. Решение, которое нужно от владельца

Нужна ли интеграция со СДЭК к сдаче, или пока остаётся ручной расчёт менеджером.
Пока решения нет, в коде закрыто только то, что не зависит от него: неизвестная
стоимость доставки нигде не выглядит бесплатной, а платёж на предварительный итог
не создаётся (§3).

## 2. Что есть сейчас

- `apps/integration_ship`: интерфейс перевозчика (`ports.py`: `RateRequest`, `RateResult`,
  `ShipmentResult`, протокол `ShipProvider`) и **только stub** (`providers/stub.py`:
  всегда нулевая цена и фиктивный трек). Реального CDEK-провайдера нет.
- Зона «Пензенская область (СДЭК)» (`is_external`, цена 0) создаётся миграцией и по
  умолчанию **активна**. При оформлении: у товаров нет веса и габаритов
  (`weight_kg`, `length_cm`, `width_cm`, `height_cm`) → `manual_required`, стоимость
  `None`, итог заказа = только товары (ADR-0013 §B.7).
- Доставка B2B не поддерживается (ADR-0013 §B.9), это не менялось.
- Весогабариты у товаров: поля есть, заполненность неизвестна (проверка на стенде —
  запрос ниже).

## 3. Что закрыто этой веткой (без решения по СДЭК)

| Было | Стало |
|---|---|
| Витрина показывала зону СДЭК как «бесплатно» (цена зоны 0) | `cost = null`, в чекауте «стоимость рассчитает менеджер», итог помечен «без доставки» |
| После оформления с ручным расчётом сразу стартовала онлайн-оплата предварительного итога | Чекаут оплату не стартует; API `POST /api/payments/orders/<n>/` отвечает 409 `delivery_pending`; `create_payment` отказывает на уровне сервиса |
| Страница «Спасибо» звала «Оплатить» | Состояние «Заказ принят, стоимость доставки уточняется», без кнопки, сумма помечена «(без доставки)» |
| Менеджер вписывал стоимость, статус оставался «ручной», итог мог не сойтись | Ввод стоимости переводит статус в «Рассчитано» только при согласованном итоге (форма подсказывает сумму); «Рассчитано» без стоимости не сохраняется |

Тесты: `apps/delivery/tests.py`, `apps/payments/test_order_payment.py::TestРучнойРасчётДоставки`,
`apps/orders/tests/test_admin_delivery_manual.py`, `frontend/app/checkout/delivery-zone.test.tsx`,
`frontend/components/order/OrderOutcome.test.tsx`.

## 4. Условия включения зоны СДЭК (даже при ручном расчёте)

1. **Покупателю нечем оплатить после расчёта.** В личном кабинете кнопки «Оплатить»
   нет; оплата доступна только со страницы «Спасибо» (`/order/<номер>/thanks`, гость —
   по токену из адресной строки). Это блокер для включения зоны, а не заметка:
   нужна кнопка оплаты в карточке заказа кабинета и письмо/сообщение покупателю
   после расчёта (отдельные задачи).
2. Ответственный менеджер за ручной расчёт и срок ответа покупателю.
3. Инструкция менеджеру — ADMIN_GUIDE §3.3 «Ручной расчёт доставки» (обновлена).

**Рекомендация до выполнения условий:** выключить зону в админке
(«Доставка → Зоны доставки» → «Пензенская область (СДЭК)» → снять «Активна»).
Уже оформленные заказы с ручным расчётом остаются и требуют дорасчёта — список:

```sql
select order_number, created_at, total, customer_phone
from orders_order where delivery_calc_status = 'manual_required' order by created_at;
```

## 5. Что нужно для интеграции (если решение «делать»)

- Договор и API-доступы СДЭК (account/secure password), тестовый контур.
- Отправитель: город/адрес склада, контакт; ПВЗ или курьер до двери; тарифы.
- Весогабариты у товаров — покрытие оценить на стенде:

  ```sql
  select count(*) filter (where weight_kg > 0 and length_cm > 0 and width_cm > 0 and height_cm > 0) as с_габаритами,
         count(*) as всего
  from catalog_product where is_active and status = 'published';
  ```

  Без габаритов заказ уходит в ручной расчёт — это не ошибка, а правило.
- Объём работ: провайдер `integration_ship/providers/cdek.py` (расчёт тарифа по
  `RateRequest`, при необходимости создание отправления с защитой от дублей),
  настройки sandbox/production, сохранение выбранного тарифа в `delivery_snapshot`,
  обработка недоступности API → `manual_required` с уведомлением менеджера (письмо
  сотрудникам уже есть, DRF-2296), страница доставки и инструкция.

## 6. Гонки, принятые осознанно

- Менеджер ввёл стоимость, пока покупатель на странице «Спасибо» — покупатель увидит
  оплату после обновления страницы.
- Покупатель нажал «Оплатить» на рассчитанном заказе, а менеджер в этот момент вернул
  ручной статус — платёж создастся на прежнюю сумму. Редко; не чинить, знать.

## 7. Решение 24.09.2026 и реализация

Владелец решил подключать СДЭК по-настоящему: вся Россия, пункт выдачи и курьер,
упаковка по разделам каталога, отправление создаётся после оплаты. Как устроено и как
включить — [`docs/delivery-cdek.md`](../delivery-cdek.md). Поля `weight_kg` и прочие
из §2 и §5 так и не появились у товара; вместо них упаковка (`package_*`) у раздела и
товара.
