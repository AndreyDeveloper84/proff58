# Таксономия каталога v2 — канонический верхний уровень

- Статус: **зафиксировано владельцем** (2026-06-24). Пилот — Оснастка.
- Источник структуры: **сайт** (ADR-0007). Группы 1С (`source_group`) —
  невалидны как структура, только weak-signal для маппинга по `external_id`.
- Построено снизу вверх по **живому ассортименту** (`stock > 0`, 6 251 поз.);
  счётчики — `docs/reports/catalog-v2-counts.md` (классификатор round 1).

## Принципы

1. **Одна основная ось на раздел** — реальные узлы дерева ИЛИ navigation facet
   (`tool_type`). Исключение — Садовая (задокументированный hybrid, см. ниже).
2. **Глубина ≤ 2** (Оснастка — исключение, 3 уровня, только для товарных подгрупп).
3. **Бренд / питание / диаметр / материал — фасеты, не узлы.**
4. **SEO-посадочные** = «категория + фасет», не ветка дерева.
5. **Структура ≠ снапшот.** Дерево строим под ВЕСЬ каталог (классифицируем и
   `stock=0`), видимость/порядок — по ЖИВОМУ остатку (поток из 1С `stocks/update`).
   Узлы не появляются/исчезают от дневного среза; пустые-сейчас — мягко скрыты
   с учётом лага оприходования, но узел сохраняется.
6. **Граница Садовая/Силовая:** Садовая = участок/дача/огород; Силовая =
   стройка/мастерская/производство/воздух/энергия.
7. **Четыре сущности 2-го уровня.** В UI они могут выглядеть одинаково (карточки,
   чипы, кнопки), но в коде/миграциях это РАЗНЫЕ сущности — **смешивать запрещено**:
   1. **category node** — реальная подкатегория дерева (`Category`);
   2. **navigation facet** — TypePanel на базе `tool_type` (управляемая ось, не sidebar-фильтр);
   3. **virtual category** — SEO/UX-представление «category + facet» (роут/посадочная);
   4. **scenario landing** — подборка/посадочная страница.
   Защита от ошибки 1С: «раз на экране кнопка как категория — значит категория в базе». Нет.
8. **Navigation facet ≠ обычный фасет.** Для раздела с осью `tool_type` после выбора
   типа меняются выдача, контекстные фильтры и chips, доступен будущий
   SEO-route/canonical. Это виртуальный 2-й уровень, а не рядовой sidebar-фасет.
9. **Порядок разделов и подкатегорий — настраиваемый в админке** через
   `Category.sort_order` (дерево сортируется по `["sort_order","name"]`); навигация
   его уважает. Мерчандайзинговый порядок — решение в админке, не хардкод.

## Второй уровень: механизмы и состав

**Правило выбора механизма.** Реальные узлы дерева — где это разные товарные группы
с разными сценариями и фильтрами. Navigation facet (`tool_type`) — где это управляемая
навигационная ось поверх широкого раздела, а не sidebar-фасет.

**Электроинструмент — navigation facet (виртуальный 2-й уровень).** Перфораторы/УШМ/
Дрели — разные типы, но в дерево их не выносим: после выбора `tool_type` меняются
выдача и контекстные фильтры (≈ как категория), плюс задел под SEO-route/canonical.
Это `navigation facet`, не рядовой фильтр (принцип 8).

**Ручной инструмент — реальные узлы** (разные группы, разные фильтры):
Ключи · Головки, трещотки и воротки · Отвёртки · Пассатижи, плоскогубцы и бокорезы ·
Молотки · Струбцины · Ножи и лезвия · Напильники · Наборы ручного инструмента.

**Измерительный инструмент — реальные узлы:**
Рулетки · Уровни · Лазерные уровни · Дальномеры · Штангенциркули · Угольники ·
Мультиметры · Пирометры и термометры · Детекторы.

**Садовая техника и инвентарь — hybrid.** Узлы 2-го уровня по крупным сценариям:
Садовая техника · Садовый инвентарь · Полив и опрыскивание · Расходники для садовой
техники. Внутри «Садовая техника» — TypePanel (Газонокосилки/Триммеры/Бензопилы/
Кусторезы/Воздуходувки/Культиваторы). Бензопила → сюда; компрессор → §10; автокомпрессор → §4.

**Оснастка — реальные узлы + ограниченный 3-й уровень.** 3-й уровень разрешён ТОЛЬКО
для реальных товарных подгрупп/сильных сценариев:
- Свёрла → по металлу / по дереву / по бетону / универсальные;
- Диски → отрезные / шлифовальные / алмазные / пильные;
- Коронки → алмазные / по бетону / по металлу / по дереву.
А `SDS-Plus/Max`, диаметр, длина, посадка, материал — **фасеты, не узлы**.

**Следствие для классификатора/миграции:** для «узловых» разделов товар получает
`Product.category = подкатегория`; для Электроинструмента — `category = раздел`, а
тип кладётся в `tool_type` (facet); для Садовой — крупный сценарий в `category`, тип
техники в `tool_type`. Команда применения это разводит явно.

## Решения

- **Запчасти** — §14, **не** в Оснастке.
- **Аккумуляторы и ЗУ** — в §14, плюс показываются как связанный раздел на
  страницах Электроинструмента.
- **Автоинструмент** — отдельный раздел (своя аудитория: домкраты/лебёдки/съёмники).
- **Механизм 2-го уровня:** реальные узлы — везде, кроме Электроинструмента
  (navigation facet `tool_type`) и Садовой (hybrid). Ручной и Измерительный —
  **узлы**, не TypePanel (см. «Второй уровень: механизмы и состав»).
- **Порядок разделов** — настраивается в админке (`sort_order`), не хардкод.
- **Порядок работ:** пилот Оснастка (крупнейшая доля) → Ручной → Электроинструмент.

## Открытые вопросы уровня подтипов (решаются на пилоте, не меняют верх)

- Садовая/Силовая для «насос», «компрессор», «пила цепная» — по границе п.6.
- «Аккумуляторы для раций/авто» (часть из 124) — в §14 или флаг non-tool.
- Цепи/шины пильные — Оснастка с cross-link в Садовую.
- «Наборы» — по второму слову (набор бит→Оснастка; набор инструмента→Ручной).
