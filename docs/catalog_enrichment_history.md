# Обогащение каталога — история (что сделано)

Хронология построения каталога. Дорожная карта (что дальше) — в
[`catalog_enrichment_roadmap.md`](catalog_enrichment_roadmap.md).

## Принципы (стандарт проекта)
- Порядок построения: **классификация (`tool_type`) → характеристики (EAV) → фасеты (#25)
  → SEO/AI**. Сначала данные, потом фильтры и AI поверх них.
- KPI: **Precision ≥ 98%** (жёстко), Coverage — цель, набираем итерациями.
- Приоритет источников значений: `manual > import_1c > regex > keyword > llm`
  (карта `source_priority` в `data/attribute_rules.json`).
- `attrs_cache` — read-model; источник истины — `ProductAttributeValue` (см. ARCHITECTURE §4.7).

**Ключевые решения Фазы A:**
- precision-first: лучше отправить в модерацию, чем ошибиться;
- `recategorize` — отдельная корзина «товар не в той категории» (не смешивается с модерацией);
- две стратегии извлечения: `priority_keyword` (матч по названию) и `inherit_1c_subgroup`
  (тип берётся из уже типизированной подгруппы 1С);
- bulk-паттерн как стандарт для всех команд обогащения.

**Каркас, переиспользуемый дальше:** движок `tool_type.py`, команды `load_tool_types`/
`enrich_tool_type`, `services.rebuild_attrs_cache`/`build_facets`, сигналы, `ingest.py`.

**Решения/наблюдения Фазы B:**
- **Уточнение инференса `power_source` (#175):** в `derive.requires_absent` добавлен
  `battery_included` (во всех 4 блоках). «Без АКБ» без распознанного voltage больше не может
  ошибочно стать `Сеть`. Симуляция: 0 регрессий (ни один из 238 inferred-mains УШМ не имеет
  `battery_included`).
- **Инференс `power_source` по атрибутам (#168):** у сетевого инструмента в имени нет слова
  «сетевой» → keyword молчит (power_source ≈1%). Добавлен декларативный `derive`-механизм в
  движок: если есть `power` (Вт) и нет `voltage`/`battery_capacity` → `power_source = Сеть`.
  Новый источник `inferred` (приоритет 10, слабейший) — только заполняет пробел, не затирает
  keyword/1С/manual. Межатрибутная логика, regex её не выражает. На реальных именах: +238 mains
  по УШМ, **0 ложных** (аккумуляторные ловятся по voltage/АКБ и не инферятся). Подключён к УШМ,
  перфораторам, дрелям.
- **Идемпотентный `enrich` (#172):** раньше `enrich` только добавлял/обновлял PAV — после
  ужесточения regex старые значения оставались в БД (на staging 9 ложных `voltage>99`),
  чистились вручную. Теперь повторный `enrich` сам удаляет engine-значения
  (`regex/keyword/inferred`), которых движок больше не извлекает, и чистит `attrs_cache`;
  авторитетные `manual`/`import_1c` и `llm` неприкосновенны (`PRUNABLE_SOURCES`). Само-починка
  вместо ручной чистки.
- **Фикс точности `voltage` (на УШМ, #163-followup):** 1С пишет ватты как «В» без «т» (ЗУБР
  «230мм 2000В» = 2000 Вт) → regex ловил их как напряжение. Ограничили целую часть 1–2 цифрами
  + левый бордер `(?<!\d)` (напряжение инструмента ≤ 99 В); убраны ложные 1400/2000/2100 В и
  сетевые 230 В. Изменение в общем атрибуте — улучшает точность всех типов.
- Имена 1С — бренд+модель+спеки; tool_type присвоен в Фазе A, поэтому покрытие меряется
  `attribute_coverage --tool-type <slug>` по уже типизированным товарам (не по grep названий).
- Низкое покрытие вспомогательных атрибутов (у перфораторов `power_source` 13%, `voltage` 9%,
  `motor_type` 2%) — **name-limited**, не ошибки: сетевые перфораторы и model-only имена не
  несут токенов. Добор — через LLM (`is_ai_feature`), не keyword-костылями. Follow-up'ы —
  в [`catalog_enrichment_roadmap.md`](catalog_enrichment_roadmap.md).
