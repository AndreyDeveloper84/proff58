# Постраничное ТЗ — Checkout (оформление) · Wave 1

Детализация экрана к контракту `../tz-master.md` и `../../design.md` (токены §9).
Самый нагруженный по состояниям экран — рисуем все ветки явно.

---

## 1. Назначение и место в флоу
**Цель:** довести до конца — **B2C оплатить**, **B2B запросить счёт**. Откуда: Корзина,
«Купить в 1 клик» (с PDP, минуя корзину). Ведём к: **Спасибо/Отслеживание**.
Ключевые решения (из `tz-master`): **гостевой checkout без обязательной авторизации и
регистрации**; MAX подключается **опционально после заказа**; **бронь 15 мин** при онлайн-оплате.

## 2. Раскладка (зоны)
**Desktop (≥1024):** 2 колонки — **форма-шаги** (лево) | **сводка заказа** (право, sticky:
состав, суммы, итог, таймер брони, кнопка подтверждения). **Mobile:** секции стеком, сводка —
раскрывающийся блок сверху/снизу + **sticky bottom-bar** (итог + главный CTA).
Формат — одностраничный со смысловыми секциями (не жёсткий пошаговый визард), чтобы можно
было вернуться и поправить.

## 3. Секции формы

### 3.1 Контакты (гость — без регистрации)
Имя, телефон (для связи/уведомления), опц. e-mail. Минимум полей. Подсказка, что регистрация
не требуется. (OTP/MAX — не здесь; предлагаем после заказа.)

### 3.2 Способ получения
Радиогруппа: **Самовывоз из магазина** (главный сценарий — адрес, режим, «сегодня») ·
**Доставка по Пензе и области** (зональная — адрес + оценка стоимости/срока) ·
**[СДЭК/Почта по РФ — Wave 3, placeholder]**. Выбор меняет поля ниже (адрес только для доставки).

### 3.3 Оплата
- **B2C:** ЮKassa (карта / СБП / ЮMoney) · **наличными при получении**.
- **B2B:** безналичный — **счёт-PDF на юрлицо** (реквизиты юрлица), вместо онлайн-оплаты.
- Онлайн-оплата → показать **таймер брони 15 мин**.
- ⚠️ Проверить статус: онлайн-оплата на стенде временно отключалась (см. §12) — уточнить, с
  чем стартует Wave 1.

### 3.4 Согласия и подтверждение
Чекбоксы согласий (обработка ПДн, оферта — со ссылками). Кнопка: **B2C «Оплатить»/«Оформить
заказ»**, **B2B «Запросить счёт»**. Итоговая сумма рядом с кнопкой.

## 4. Состояния (обязательные фреймы)

| Состояние | Что показываем |
|---|---|
| **Loading** | скелет формы + сводки |
| **Базовое (заполнение)** | секции + валидные значения |
| **Ошибки валидации** | подсветка полей + текст под полем; фокус на первую ошибку; кнопка не «молчит» |
| **Самовывоз vs доставка** | адресные поля появляются/скрываются; оценка доставки в сводке |
| **B2C оплата → редирект** | состояние «Переходим к оплате…» / возврат из ЮKassa |
| **Ошибка оплаты** | «Оплата не прошла. Повторить» + альтернативный способ; заказ не теряется |
| **Резерв 15 мин: таймер** | обратный отсчёт в сводке |
| **Резерв истёк (expired)** | «Бронь истекла» → пере-проверка цены/остатка, пересборка (частичная доступность/цена изменилась) |
| **B2B: неполные реквизиты** | валидация полей юрлица; «Запросить счёт» заблокирован до заполнения |
| **Наличные при получении** | без таймера брони; подтверждение заказа сразу |
| **Пустой заказ** | если корзина опустела/сессия истекла → вернуть в корзину/каталог |
| **Error/offline** | сетевая ошибка + retry (не «offline-экран» — PWA нет) |

## 5. Интеракции и микрокопи
- Валидация — по blur и при отправке; ошибки конкретные («Введите телефон в формате …»),
  без извинений, с выходом.
- Смена способа получения/оплаты мгновенно перестраивает поля и сводку.
- Таймер брони виден и озвучен; по истечении — модалка/плашка «Бронь истекла, обновите заказ».
- Кнопки = результат: «Оплатить», «Оформить заказ» (наличные), «Запросить счёт».
- После успеха → переход на «Спасибо», где предлагается **«Отслеживать в MAX»** (не обязательно).
- Согласия — явные чекбоксы (не предотмеченные втихую — этический принцип).

## 6. Адаптив
Desktop 2 колонки (форма | sticky-сводка); mobile — секции стеком + **sticky bottom-bar**
(итог + CTA), сводка сворачивается. Проверить **320/360/390/768/1440**; поля/радио/кнопки —
тач ≥44px, крупные зоны выбора способа получения/оплаты (карточки-радио).

## 7. Доступность
- Каждое поле — с `<label>`; ошибки — `aria-invalid` + текст, связанный `aria-describedby`;
  фокус переводится на первую ошибку при отправке.
- Радиогруппы «получение»/«оплата» — `fieldset/legend`, выбор стрелками с клавиатуры.
- **Таймер брони** — `aria-live` (озвучивать ключевые точки, не каждую секунду: например,
  на 5/1 мин), чтобы не спамить.
- Согласия — доступные чекбоксы со ссылками на документы.
- Контраст AA, видимый фокус, тач ≥44; модалка «бронь истекла» — focus trap + Escape.

## 8. Моушн (минимальный)
Никаких wow. Плавное появление/скрытие адресных полей, спокойный переход между секциями.
Сумма и таймер — стабильный layout, без дёрганья. Reduced-motion — мгновенно.

## 9. Измеримость
| Событие | Триггер |
|---|---|
| `begin_checkout` | вход в checkout (из корзины/1 клик) |
| `add_shipping_info` | выбран способ получения |
| `add_payment_info` | выбран способ оплаты |
| `order_submitted` | заказ создан (в т.ч. наличные) |
| `payment_succeeded` | онлайн-оплата прошла |
| `b2b_invoice_requested` | «Запросить счёт» |
| `reservation_expired` | истёк резерв |
Guardrail: доля брошенных на checkout; ошибки оплаты; истёкшие брони.

## 10. Acceptance criteria (Checkout)
- [ ] Гостевой checkout без обязательной регистрации/авторизации; MAX — только после заказа.
- [ ] Способы получения (самовывоз главный / доставка Пенза) и оплаты (B2C: ЮKassa+наличные;
      B2B: счёт-PDF) нарисованы; смена перестраивает поля.
- [ ] Бронь 15 мин: таймер + состояние **expired** с пересборкой (цена/остаток).
- [ ] Ошибка оплаты — заказ не теряется, есть повтор/альтернатива.
- [ ] Валидация: ошибки под полями, фокус на первую, `aria-invalid`.
- [ ] Согласия — явные, не предотмеченные.
- [ ] Loading/error/retry + пустой-заказ присутствуют; offline-экрана нет (network error).
- [ ] Mobile: sticky bottom-bar (итог + CTA); тач ≥44; адаптив 320/360.
- [ ] Токены `design.md`; суммы tabular-nums; моушн минимальный, reduced-motion.
- [ ] Доступность: label’ы, fieldset радиогрупп, таймер `aria-live`, focus trap модалки.
