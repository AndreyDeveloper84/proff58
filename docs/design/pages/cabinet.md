# Постраничное ТЗ — Кабинет (B2C + B2B) · Wave 1

Детализация к контракту `../tz-master.md` и `../../design.md` (токены §9). Один документ на оба
кабинета: общий каркас + различия B2C/B2B. **Базовый B2B** (один плательщик, счета-PDF) — Wave 1;
**сложный B2B** (несколько юрлиц/доверенностей) — Wave 3. Избранное/Сравнение — Wave 2.

---

## 1. Назначение и место в флоу
**Цель:** дать зарегистрированному пользователю видеть заказы/статусы, повторять покупки и
управлять данными; B2B — ещё и юрлицо/реквизиты и **счета-PDF**. Вход: авторизация. Ведём к:
повтору заказа (→ корзина), отслеживанию в MAX, скачиванию счёта.

## 2. Раскладка (каркас)
**Desktop (≥1024):** боковая навигация раздела (лево, ~240px) | контент (право). **Mobile:**
навигация — верхнее меню/аккордеон или drawer; контент на всю ширину.
**Разделы навигации:**
- B2C: **Заказы** · Профиль · Адреса · [Избранное — W2] · [Сравнение — W2] · MAX · Выход.
- B2B: то же + **Юрлицо и реквизиты** · **Счета (PDF)**. Ценник единый (юрлицу НДС — в счёте).

## 3. Разделы (контент)

### 3.1 Заказы (главный раздел)
Список заказов: № · дата · сумма · **единый `display_status`** (цвет+иконка+текст) · кнопки
«Открыть»/«Повторить». **Карточка заказа:** снимок состава/цен, способ получения/оплаты,
статус, «Повторить заказ», «Отслеживать в MAX», для B2B — «Скачать счёт (PDF)».

### 3.2 Профиль
Контакты (имя, телефон, e-mail), смена данных, привязка/отвязка MAX. Согласия/уведомления.

### 3.3 Адреса (B2C)
Список адресов доставки, добавить/редактировать/удалить, адрес по умолчанию.

### 3.4 Юрлицо и реквизиты (B2B)
Реквизиты плательщика (наименование, ИНН/КПП, адрес, банк). Wave 1 — **один плательщик**;
несколько юрлиц/доверенности — Wave 3 (место под список зарезервировать).

### 3.5 Счета (B2B)
Список счетов: № · дата · сумма · статус (выставлен/оплачен) · **скачать PDF**. Фильтр по дате.

## 4. Состояния (обязательные фреймы)

| Состояние | Что показываем |
|---|---|
| **Требуется вход** | если не авторизован → экран/редирект логина (не пустой кабинет) |
| **Loading** | скелет списка/карточки |
| **Заказы есть** | список + статусы |
| **Нет заказов (empty)** | «Заказов пока нет» + «Перейти в каталог» |
| **Пустые разделы** | нет адресов/счетов → приглашение добавить/оформить |
| **Повтор заказа** | пере-проверка цен/наличия → часть недоступна → перенести доступное в корзину |
| **B2B без реквизитов** | «Добавьте реквизиты юрлица», блок счетов подсказывает заполнить |
| **Error/retry** | «Не удалось загрузить. Повторить» |

## 5. Интеракции и микрокопи
- «Повторить заказ» → собрать корзину из снимка, пере-проверить цену/остаток, показать
  изменения (цена изменилась/нет в наличии) перед переходом.
- «Скачать счёт (PDF)» (B2B); «Отслеживать в MAX» (deep-link).
- Редактирование профиля/адреса/реквизитов — формы с валидацией и подтверждением сохранения.
- Кнопки = результат: «Повторить заказ», «Скачать счёт», «Сохранить», «Добавить адрес».

## 6. Адаптив
Desktop — sidebar-навигация | контент; tablet/mobile — навигация сворачивается (меню/drawer),
списки заказов/счетов — карточками на mobile (не широкая таблица). Проверить 320/360/390/768/
1440; кнопки/строки — тач ≥44.

## 7. Доступность
- Навигация раздела — `nav` с текущим пунктом (`aria-current`).
- Списки заказов/счетов — доступные таблицы (`<th>`/scope) или списки; статус цвет+иконка+текст.
- Формы (профиль/адрес/реквизиты) — label/`aria-invalid`/описание ошибки; сохранение — `aria-live`.
- Скачивание PDF — понятная ссылка (тип/размер по возможности). Контраст AA, фокус, тач ≥44.

## 8. Моушн (спокойный)
Переходы между разделами без wow; списки — мягкий reveal. Reduced-motion — мгновенно.

## 9. Измеримость
| Событие | Триггер |
|---|---|
| `view_account` (section=…) | открытие раздела |
| `reorder` | «Повторить заказ» |
| `invoice_download` | скачивание счёта (B2B) |
| `max_linked` | привязка MAX |
| `profile_update` / `address_save` / `requisites_save` | сохранение форм |
Guardrail: доля повторов, доля кабинетов без действий.

## 10. Acceptance criteria (Кабинет)
- [ ] Требуется вход обрабатывается (логин/редирект), не пустой кабинет.
- [ ] Заказы: список + карточка (снимок), единый `display_status` цвет+иконка+текст.
- [ ] «Повторить заказ» с пере-проверкой цен/наличия и показом изменений.
- [ ] B2C: профиль + адреса; B2B: + юрлицо/реквизиты (один плательщик) + счета-PDF.
- [ ] Единый ценник (юрлицу НДС — в счёте); счета — скачивание PDF; «Отслеживать в MAX».
- [ ] Empty-состояния (нет заказов/адресов/счетов/реквизитов) ведут к действию.
- [ ] Loading/error/retry; формы — валидация, aria, aria-live на сохранение.
- [ ] Mobile: навигация сворачивается, списки карточками, тач ≥44; адаптив 320/360.
- [ ] Токены `design.md`; суммы tabular-nums; моушн спокойный, reduced-motion.
- [ ] Сложный B2B (мультиюрлица) — место зарезервировано, но не реализуется (Wave 3).

## 11. Открытые вопросы (для этих страниц)
1. Регистрация/вход — способ (телефон+OTP через MAX? e-mail+пароль?) и точки входа.
2. B2B: несколько юрлиц у одного пользователя — точно Wave 3? (влияет на структуру раздела)
3. Детализация статусов заказа в карточке (таймлайн осей или только `display_status`)?
4. Уведомления/подписки в профиле — объём на Wave 1.
5. Избранное/Сравнение (Wave 2) — показывать пункты меню сейчас как «скоро» или скрыть?
