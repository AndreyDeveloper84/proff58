# Постраничное ТЗ — Спасибо / Отслеживание · Wave 1

Детализация экрана к контракту `../tz-master.md` и `../../design.md` (токены §9).
Финальный экран флоу покупки: подтвердить заказ и завести отслеживание.

---

## 1. Назначение и место в флоу
**Цель:** подтвердить, что заказ принят, дать номер и следующий шаг, **предложить
отслеживание в MAX** (опционально, гостю — через подписанный order-link). Откуда: успешный
Checkout (оплата/наличные/запрос счёта). Ведём к: MAX (deep-link), Кабинет, Каталог.
Ключевое: бот **не пишет первым** → ведём пользователя сами кнопкой отсюда.

## 2. Раскладка (зоны)
Центрированная колонка (≤720px): **шапка-подтверждение** (галочка + «Заказ №… принят») →
**сводка заказа** (состав, суммы, способ получения/оплаты, статус) → **блок «Отслеживать в
MAX»** (заметный) → **что дальше** (шаги) → контакты/поддержка → CTA «Продолжить покупки».
На desktop сводка может быть в 2 колонки (детали | статус). Mobile — стек.

## 3. Блоки и компоненты

### 3.1 Подтверждение
Иконка успеха + «Спасибо! Заказ №XXXX принят». Кнопка «Скопировать номер». Дата/время.

### 3.2 Сводка заказа (снимок)
Список позиций (фото/название/кол-во/сумма) · итог · **способ получения** (самовывоз: адрес/
режим; доставка: адрес/срок) · **способ оплаты** · **статус** (единый `display_status`,
`design.md` §9.3). Это снимок — данные не «плывут».

### 3.3 «Отслеживать в MAX» (обязательный блок)
Заметная secondary/brand-кнопка с иконкой MAX + микротекст «Статусы заказа и чек — в MAX».
Deep-link сохраняет `max_chat_id`; **для гостя — через подписанный order-link** (доступ к
заказу без регистрации). Необязательно: пропустить можно.

### 3.4 Что дальше
Короткие шаги под тип заказа: самовывоз («Соберём и сообщим, когда готово»), доставка
(«Согласуем время»), наличные, B2B («Пришлём счёт»). Без ложных сроков (placeholder до
подтверждения данными).

### 3.5 B2B: счёт
Ссылка «Скачать счёт (PDF)» / «Счёт готовится, пришлём» + номер счёта; реквизиты плательщика.

## 4. Состояния (обязательные фреймы)

| Состояние | Что показываем |
|---|---|
| **Loading** | подтверждаем заказ (скелет/спиннер короткий) |
| **B2C оплачен онлайн** | «Оплачено», статус «Оплачен/В сборке», чек/ссылка |
| **B2C наличными / оформлен** | «Заказ оформлен», статус «Новый», оплата при получении |
| **Оплата не подтверждена** | возврат из ЮKassa без успеха → «Оплата не подтверждена» + «Повторить оплату» (не теряем заказ) |
| **B2B счёт запрошен** | «Счёт формируется/готов» + PDF/номер |
| **Гость (без аккаунта)** | акцент на «Отслеживать в MAX» (order-link); без требования регистрации |
| **Error** | не удалось загрузить статус заказа → номер + телефон поддержки + retry |

## 5. Интеракции и микрокопи
- «Отслеживать в MAX» → deep-link; лёгкий pulse **один раз** для привлечения (не назойливо).
- «Скопировать номер заказа» → тост «Номер скопирован».
- «Скачать счёт (PDF)» (B2B).
- «Повторить оплату» при неуспехе.
- Тексты — без ложных обещаний сроков; «Продолжить покупки» ведёт в каталог.

## 6. Адаптив
Центрированная колонка; desktop до 720–840px, mobile — полноширинный стек, кнопка MAX и
«Скопировать номер» — тач ≥44px. Проверить **320/360/390/768/1440**.

## 7. Доступность
- Явная иерархия заголовков (H1 «Заказ принят»); статус — текст+иконка (не только цвет).
- Кнопка MAX и «скопировать» — с понятными подписями; тост — `aria-live`.
- Контраст AA, видимый фокус; ссылки на счёт/документы — доступные.

## 8. Моушн (сдержанный)
Небольшая анимация галочки успеха (не конфетти-перегруз), pulse кнопки MAX один раз.
Reduced-motion — статичная галочка, без pulse.

## 9. Измеримость
| Событие | Триггер |
|---|---|
| `order_confirmation_view` | открытие экрана |
| `max_linked` | переход по deep-link «Отслеживать в MAX» |
| `invoice_download` | скачивание счёта (B2B) |
| `payment_retry` | повтор оплаты (неуспех) |
Guardrail: доля заказов без привязки MAX (для гипотез о микротексте).

## 10. Acceptance criteria (Спасибо/Отслеживание)
- [ ] Номер заказа + сводка-снимок + статус (единый `display_status`).
- [ ] Блок «Отслеживать в MAX» присутствует; для гостя — через подписанный order-link (без
      обязательной регистрации).
- [ ] Варианты: онлайн-оплачен / наличные-оформлен / оплата не подтверждена (повтор) / B2B-счёт.
- [ ] «Что дальше» — без ложных сроков (placeholder до данных).
- [ ] B2B: ссылка на счёт-PDF / номер.
- [ ] Loading/error присутствуют; статус = цвет+иконка+текст.
- [ ] Mobile: кнопки тач ≥44; адаптив 320/360; токены `design.md`.
- [ ] Моушн сдержанный, reduced-motion (без pulse/анимации галочки).
