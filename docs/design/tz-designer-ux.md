# ТЗ дизайнеру №2 — UX + UI (от продукта, без привязки к макетам)

Бриф составлен **с нуля от продукта и дизайн-системы `design.md`**, без опоры на ранее
присланные ИИ-макеты. В отличие от `tz-designer.md` (UI-первый, по экранам), этот документ
**UX-первый**: сначала роли, задачи, сценарии и логика, затем — экраны и визуал.

> `design.md` остаётся источником истины по токенам/типографике/состояниям/моушну.
> Здесь — поведение системы: кто, зачем, каким путём, что при сбое, как меряем успех.

---

## 0. Как пользоваться

Дизайнер сначала проектирует **флоу и состояния** (раздел 2–5), затем рисует экраны
(раздел 8) так, чтобы каждый экран обслуживал конкретный шаг сценария и все его состояния.
UI без понятного UX-сценария не принимается.

## ЧАСТЬ A. UX

## 1. Продукт, роли, задачи (JTBD)

**Продукт.** penzainstrument.ru — магазин профессионального электро/ручного инструмента,
оснастки, садовой техники, оборудования. Пенза и область. Гибрид **B2C + B2B**. 1С — мастер
цены/остатка/кода; сайт — мастер контента. Первый экземпляр переиспользуемого движка
(специфика — в `SiteSettings`).

**Роли и их главные задачи (Jobs To Be Done):**

| Роль | JTBD (когда…, я хочу…, чтобы…) |
|---|---|
| **Гость** | «Когда мне срочно нужен инструмент под задачу, я хочу быстро понять, подходит ли он по характеристикам и есть ли в наличии, чтобы забрать сегодня». |
| **Покупатель B2C** | «…оформить и оплатить заказ с минимумом шагов и видеть статус, чтобы не звонить и не ждать». |
| **Юрлицо B2B** | «…получить счёт на юрлицо с НДС и спецценой, чтобы провести закупку по документам». |
| Менеджер / Кладовщик / Контент / Админ | оперативная панель (вне дизайна витрины, отдельный трек). |

**Контекст использования:** часто с телефона, на объекте, иногда в перчатках, при ярком
свете. Решение принимается по триаде **наличие → цена → характеристики** + доверие к
реальному магазину.

## 2. Информационная архитектура и навигация

**Карта сайта (витрина):**
```
Главная
├─ Каталог (дерево категорий, 3 уровня)
│   └─ Категория / PLP → Карточка товара / PDP
├─ Поиск (артикул/модель/бренд) → выдача
├─ Корзина → Оформление → Спасибо/Отслеживание
├─ Кабинет (B2C | B2B)
├─ Контентные: Акции · Доставка и оплата · Гарантия · Сервис · Компания · Контакты
└─ Системные: 404 · 500 · offline · техработы
```

**Навигация:** глобальная шапка (каталог-мегаменю + поиск + корзина/избранное/сравнение +
город + телефон), хлебные крошки на всех вложенных, футер-карта разделов. Принцип **3 кликов**
до любого товара: Главная → Категория → PDP.

## 3. Сквозные UX-принципы

1. **Не блокируем покупку.** Любая фича (фильтры, консультация, сравнение) — опциональна,
   путь «найти → в корзину → оформить» всегда доступен.
2. **Видимость наличия и цены** на каждом уровне (карточка, PDP, корзина, checkout).
3. **Цена по роли честно:** розница по умолчанию, B2B-цена + НДС после входа как юрлицо.
   Никогда не показываем B2B-цену гостю и наоборот не прячем розницу.
4. **Стабильность критичного:** цена, CTA, поиск, корзина не «прыгают» (ни визуально, ни в
   моушне). Wow — только в hero/баннере консультации.
5. **Доверие как функция:** наличие из 1С, самовывоз сегодня, гарантия, реальные контакты —
   видны рано.
6. **Деградация без тупиков:** любое пустое/ошибочное состояние ведёт дальше.

## 4. Пользовательские сценарии (флоу) — 4 ветки каждый

Для каждого флоу дизайнер рисует: happy-path · альтернатива · ошибка · пограничный случай,
и для каждого шага — экран + состояние.

### 4.1 Гость: подбор по характеристикам → корзина
- **Happy:** Главная/Поиск → Категория → применяет фасеты (мощность, патрон, наличие) →
  PDP → «В корзину» → мини-корзина → «Оформить».
- **Альтернатива:** передумал/сравнивает → «Сравнение» / «Избранное» → возвращается.
- **Ошибка:** фасеты дали 0 → empty с «сбросить»; товар уже не в наличии → «под заказ»/
  «уведомить».
- **Edge:** очень длинное название/нет фото/нет части ТТХ → корректные заглушки.
- **Событие успеха:** `add_to_cart`. Guardrail: глубина просмотра без добавления.

### 4.2 B2C: оформить и оплатить
- **Happy:** Корзина → Оформление (контакты → способ получения → оплата) → оплата ЮKassa →
  Спасибо → «Отслеживать в MAX».
- **Альтернатива:** «Купить в 1 клик» с PDP; самовывоз вместо доставки; оплата при получении.
- **Ошибка:** отказ оплаты → понятный экран + повтор; **резерв 15 мин истёк** → пересборка
  корзины с пере-проверкой цены/остатка.
- **Edge:** частичная доступность корзины → «оформить доступное»; цена изменилась →
  подтверждение было→стало.
- **Успех:** `order_paid`. Guardrail: брошенные корзины, возвраты.

### 4.3 B2B: запрос счёта
- **Happy:** вход как юрлицо → видит B2B-цены с НДС → Корзина → «Запросить счёт» → реквизиты
  юрлица → счёт-PDF.
- **Альтернатива:** несколько юрлиц/доверенностей → выбор плательщика.
- **Ошибка:** неполные реквизиты → валидация; товар под заказ → срок в счёте.
- **Edge:** смешанная корзина (часть нет в наличии) → счёт на доступное / с примечанием.
- **Успех:** `b2b_invoice_requested`. Guardrail: время до счёта.

### 4.4 Повторный заказ и отслеживание
- Кабинет → история → «Повторить заказ» (пере-проверка цен/наличия) → корзина.
- «Отслеживать в MAX» (deep-link, в т.ч. гостю) → статусы приходят в бот. Бот не пишет первым.

## 5. Логика состояний (state-машины — рисовать явно)

- **Наличие (из 1С, read-only):** `в наличии (N) → мало (≤порог) → под заказ (срок) → нет`.
  Влияет на CTA: «В корзину» / «Под заказ» / «Уведомить».
- **Бронь:** при онлайн-оплате остаток резервируется на **15 мин** → `reserved → paid` или
  `reserved → expired` (показать таймер/плашку, пере-проверка).
- **Статус заказа — 3 независимые оси → 1 человекопонятный бейдж:** обработка (1С/менеджер),
  оплата (сайт), выгрузка в 1С. Дизайнер рисует **единый** `display_status` (Новый/Ждёт
  оплаты/Оплачен/В сборке/Готов/В пути/Выполнен/Отменён/Возврат/Бронь истекла), не три бейджа.
- **Цена по роли:** один и тот же товар → розница или B2B(+НДС) в зависимости от
  авторизации; слот B2B в разметке всегда.
- **Корзина:** `актуальна → цена изменилась (подтвердить) → частично доступна → пуста`.

## 6. Контент и UX-writing (часть ТЗ, не «потом»)

- Sentence case, активный залог, без воды. Кнопка = результат («Оформить заказ»,
  «Запросить счёт», «В корзину», «Уведомить о поступлении»), имя сохраняется через весь флоу.
- **Ошибки:** без извинений и размытости, с выходом. Шаблоны для: оплата не прошла, нет сети,
  товар закончился, бронь истекла, реквизиты неполные.
- **Пустые экраны** — приглашение к действию (каталог/сброс фильтров/похожие).
- **Микрокопи-обязательно прописать** для: статусов наличия, B2B-цены («Цена для юр. лиц,
  с НДС»), брони 15 мин, MAX deep-link («Статусы и чек — в MAX»), AI-консультанта (дисклеймер
  «подбор по характеристикам»), согласий (персональные данные/оферта).
- Термины — языком пользователя (патрон, энергия удара, SDS-Plus), не схемой системы.

## 7. Доступность (UX-уровень)

Клавиатурная проходимость всех флоу; видимый фокус; статус ≠ только цвет (иконка+текст);
контраст AA; тач-таргет ≥ 44px; формы с явными ошибками (`aria-invalid`, привязка подписей);
уважение `prefers-reduced-motion`; понятные тексты ссылок/кнопок (не «жми сюда»).

## 8. Измеримость (на каждый флоу)

| Флоу | Событие успеха | Guardrail | Гипотеза A/B |
|---|---|---|---|
| Подбор гостя | `add_to_cart` после фильтра | просмотр без добавления | счётчики у фасетов ↑ переход в PDP |
| Покупка B2C | `order_paid` | брошенные корзины/возвраты | «Купить в 1 клик» ↑ конверсию без роста возвратов |
| Запрос счёта B2B | `b2b_invoice_requested` | время до счёта | предзаполненные реквизиты ↑ долю запросов |
| Привязка MAX | `max_linked` | — | выгода-микротекст ↑ долю привязок |
| Поиск | `search_result_click` | доля пустых выдач | подсказки по артикулу ↓ нулевые выдачи |

## ЧАСТЬ B. UI

## 9. Визуальная система

Полностью по `design.md`: светлая тема «Чистая мастерская», тёмная шапка/подвал, зелёный =
действие (CTA `--green-700`, AA), изумруд — иконки/лого, типографика Oswald/Saira + Inter,
spacing/radius/shadow, signature «инструментальный кант», моушн §17. **Сырой hex запрещён —
только токены.**

## 10. Экраны × обязательные состояния (матрица)

Каждый экран сдаётся со всеми отмеченными состояниями (✓ = обязательно).

| Экран | loading | empty | error | offline | доменные |
|---|---|---|---|---|---|
| Главная | ✓ | — | ✓ | ✓ | — |
| Категория/PLP | ✓ | ✓ (0 по фильтру) | ✓ | ✓ | наличие в карточках |
| Поиск | ✓ | ✓ (0 по запросу) | ✓ | ✓ | подсказки |
| PDP | ✓ | ✓ (нет отзывов) | ✓ | ✓ | под заказ/нет/цена изм./гость↔B2B |
| Корзина | ✓ | ✓ (пустая) | ✓ | ✓ | частичная/цена изм. |
| Checkout | ✓ | — | ✓ (оплата) | ✓ | резерв истёк/реквизиты B2B |
| Спасибо/трекинг | ✓ | — | ✓ | ✓ | статус заказа, MAX-link |
| Кабинет B2C/B2B | ✓ | ✓ (пустые разделы) | ✓ | ✓ | роль-цена, счета-PDF |
| Контентные | ✓ | — | ✓ | ✓ | — |
| 404/500/offline | — | — | ✓ | ✓ | — |

## 11. Ключевые компоненты (варианты + состояния)

Шапка, подвал, мегаменю, **единый шаблон карточки товара** (фото→бренд→название→рейтинг→
наличие→цена→CTA, не смешивать шаблоны в сетке), бейдж наличия, блок цены (B2C/B2B+НДС),
степпер, фасет-чип, инпут/поиск с подсказками, таб/аккордеон, хлебные крошки, тост, статус-
бейдж заказа, AI-консультант (реальная панель), кнопка MAX. Кнопки: primary/secondary/ghost/
danger × default/hover/active/disabled/loading. Все — по `design.md` §9.

## 12. Адаптив и моушн

desktop 1440 + mobile 390 (ключевые — tablet 768). Mobile: hero статичный, фасеты в drawer,
sticky bottom-bar покупки на PDP. Моушн дозирован (hero + баннер консультации), reveal-блоки,
карточки спокойные; обязательный `prefers-reduced-motion` fallback. Параллакс — только
desktop ≥ 1024.

## 13. Что сдать (deliverables)

1. **UX:** sitemap, флоу-диаграммы (4 ветки на сценарий), state-диаграммы (наличие/бронь/

2. **UI:** Figma-variables (токены), компоненты с вариантами/состояниями, экраны desktop+

3. **Ассеты:** иконки (единый набор), требования к фото (1:1, webp/avif), плейсхолдеры.

## 14. Acceptance criteria

- [ ] Каждый экран привязан к шагу сценария и закрывает все свои состояния.
- [ ] Флоу нарисованы в 4 ветках (happy/альт/ошибка/edge).
- [ ] State-машины (наличие, бронь 15 мин, статус 3 оси→1, корзина) визуализированы.
- [ ] Цена по роли + B2B(+НДС) слот везде; наличие = цвет+иконка+текст.
- [ ] Микрокопи прописана для ошибок/статусов/MAX/AI/согласий (реальные RU-тексты).
- [ ] Доступность: клавиатура/фокус/контраст AA/тач ≥44/reduced-motion.
- [ ] Для каждого флоу указаны событие успеха, guardrail, гипотеза A/B.
- [ ] UI строго на токенах `design.md`; тёмная шапка/подвал + «кант» на месте.
- [ ] Моушн ограничен hero/баннером; критичные элементы не двигаются.

## 15. Открытые вопросы (до старта)

1. Пороги наличия: при каком N показывать «мало»? Срок «под заказ» — откуда (1С/ручной)?
2. B2B: один плательщик или несколько юрлиц/доверенностей у пользователя?
3. Гостевой checkout без регистрации — разрешён полностью? OTP только через MAX?
4. Сравнение и избранное — в первом релизе или второй волной?
5. Зоны доставки по Пензе — сколько и как показывать стоимость (калькулятор/таблица)?
