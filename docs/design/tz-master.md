# ТЗ дизайнеру — единое фазовое (MASTER)

**Статус: единственный контракт.** Этот документ объединяет два прежних черновика
(`tz-designer.md` — UI-первый по макетам; `tz-designer-ux.md` — UX-первый) и **заменяет их**.
Источник истины по визуалу (токены, типографика, состояния, моушн) — `design.md`.
Постраничная детализация — `docs/design/pages/*.md`.

Структура контракта: **Часть A (UX) — главная**, продуктовый контракт; **Часть B (UI) —
приложение**: визуальное направление и инвентарь экранов. UX вправе менять композицию
исходных AI-макетов, если этого требует сценарий.

> Принцип: дорогой технический wow на 1-м экране и баннере консультации; дальше — спокойный
> магазин, где сразу видно каталог, цену, наличие и кнопку «купить». Зелёный — сигнал
> действия, не заливка.
>
> **Патч ревью (2026-07-01):** отдельной B2B-цены нет — единый ценник для всех, юрлицу
> выделяется НДС в корзине/счёте; пагинация — гибрид load-more + crawlable; B2B-счёт через
> checkout; «Купить в 1 клик» — контракт qty=1; «Уведомить» — телефон+опция MAX.

# ЧАСТЬ A. UX (главный контракт)

Пенза и область. Гибрид **B2C + B2B**. 1С — мастер цены/остатка/кода; сайт — мастер контента.
Первый экземпляр переиспользуемого движка (специфика — в `SiteSettings`).

| Роль | JTBD |
|---|---|
| **Гость** | быстро понять, подходит ли инструмент по характеристикам и есть ли в наличии, чтобы забрать сегодня. |
| **B2C** | оформить и оплатить с минимумом шагов и видеть статус. |
| **B2B (юрлицо)** | получить счёт на юрлицо (с выделенным НДС) для закупки по документам. |

Контекст: часто телефон, объект, перчатки, яркий свет. Решение по триаде **наличие → цена →
характеристики** + доверие к реальному магазину.

## 3. Информационная архитектура

```
Главная
├─ Каталог (дерево, 3 уровня) → Категория/PLP → PDP
├─ Поиск (артикул/модель/бренд) → выдача
├─ Корзина → Checkout → Спасибо/Отслеживание
├─ Кабинет (B2C | B2B)            [Wave 1]
├─ Контентные: Акции·Доставка·Гарантия·Сервис·Компания·Контакты  [Wave 1]
└─ Системные: 404 · 500 · сетевая ошибка/retry
```
Навигация: шапка (каталог-мегаменю + поиск + корзина/[избранное/сравнение — W2] + город +
телефон), хлебные крошки, футер-карта. **Доступность пути к товару** обеспечивается поиском
и мегаменю (метрика — см. §9), а не жёстким «3 клика».

## 4. Сквозные UX-принципы

1. **Не блокируем покупку.** Фильтры/консультация/сравнение — опциональны. **Гостевой
   checkout без обязательной авторизации и регистрации.** MAX подключается **опционально
   после заказа** (подписанный order-link), не как обязательный OTP-шаг.
2. Видимость наличия и цены на каждом уровне.
3. **Единый ценник** для B2C и B2B (отдельной B2B-цены нет). Для юрлица в **корзине/счёте**
   показываем выделенный НДС, включённый в цену («в т.ч. НДС 20%»). Цена уже содержит НДС.
4. Стабильность критичного: цена, CTA, поиск, корзина не «прыгают».
5. Доверие как функция: наличие из 1С, самовывоз, гарантия, контакты — рано на виду.
6. Деградация без тупиков: пустое/ошибка ведут дальше.

## 5. Сценарии-флоу (по 4 ветки: happy · альтернатива · ошибка · edge)

### 5.1 Гость: подбор → корзина
happy: Главная/Поиск → Категория → фасеты → PDP → «В корзину» → мини-корзина → «Оформить».
альт: сравнение/избранное (W2) → возврат. ошибка: 0 по фильтру → empty+reset; не в наличии →
«под заказ»/«уведомить». edge: длинное название/нет фото/нет части ТТХ → заглушки.
Успех: `add_to_cart`. Guardrail: просмотр без добавления.

### 5.2 B2C: оформить и оплатить
happy: Корзина → Checkout (контакты → получение → оплата) → ЮKassa → Спасибо → опц. «Отслеживать
в MAX». альт: «Купить в 1 клик» (qty=1, не смешивать с корзиной); самовывоз; наличные при
получении. ошибка: отказ оплаты → экран+повтор; **резерв 15 мин истёк** → пересборка с
пере-проверкой цены/остатка. edge: частичная доступность → «оформить доступное»; цена
изменилась → подтверждение было→стало.
Успех: `order_submitted` (создан, в т.ч. наличные) и `payment_succeeded` (онлайн-оплата прошла).
Guardrail: брошенные корзины, возвраты.

### 5.3 B2B: запрос счёта
happy: вход как юрлицо → тот же ценник (в корзине «в т.ч. НДС 20%») → Корзина **«Перейти к
запросу счёта»** → Checkout (реквизиты → получение → комментарий) → «Запросить счёт» → счёт-PDF.
альт: [W3] несколько юрлиц → выбор плательщика. ошибка: неполные реквизиты → валидация; под
заказ → срок в счёте. edge: смешанная корзина → счёт на доступное/с примечанием.
Успех: `b2b_invoice_requested`. Guardrail: время до счёта.

### 5.4 Повторный заказ и отслеживание (4 ветки — обязательно)
happy: Кабинет → история → «Повторить» (пере-проверка цен/наличия) → корзина. альт: часть
позиций недоступна → перенести доступные. ошибка: товар снят/нет цены → пометка+замена. edge:
гость без аккаунта → доступ к заказу по подписанному order-link, отслеживание в MAX без
регистрации. Бот не пишет первым.

## 6. State-машины (рисовать явно)

- **Наличие (1С, read-only):** `в наличии (N) → мало (≤порог) → под заказ (срок) → нет`.
  CTA: «В корзину» / «Под заказ» / «Уведомить».
- **Бронь:** онлайн-оплата → `reserved (15 мин) → paid` | `reserved → expired` (таймер/плашка,
  пере-проверка).
- **Статус заказа:** 3 оси (обработка · оплата · выгрузка в 1С) → **один** `display_status`
  (Новый/Ждёт оплаты/Оплачен/В сборке/Готов/В пути/Выполнен/Отменён/Возврат/Бронь истекла).
- **Цена:** единый ценник для всех; для юрлица в корзине/счёте выделяется включённый НДС
  («в т.ч. НДС 20%»). Отдельной B2B-цены/слота нет.
- **Корзина:** `актуальна → цена изменилась (подтвердить) → товар без цены (CTA заблокирован)
  → частично доступна → пуста`.

## 7. Контент и UX-writing

Sentence case, активный залог, без воды. Кнопка = результат («Оформить заказ», «Перейти к
запросу счёта», «Запросить счёт», «В корзину», «Уведомить о поступлении»), имя через весь флоу.
Ошибки — без извинений, с выходом; шаблоны: оплата не прошла, **нет сети (retry)**, товар
закончился, бронь истекла, реквизиты неполные, товар без цены. Пустые экраны — приглашение.
Микрокопи прописать для: статусов наличия, НДС в корзине/счёте («в т.ч. НДС 20%»), брони 15 мин,
MAX («Статусы и чек — в MAX»), консультации, «Уведомить» (телефон+опция MAX), согласий
(ПДн/оферта). Термины — языком пользователя.

> **Placeholder до подтверждения данными** (не выдавать за факт): «24 эксперта онлайн»,
> 10+/20 000+/50 000+/100+, «доставка завтра», «самовывоз сегодня». Помечать в макете как
> данные, требующие подтверждения (этический принцип — без ложных обещаний).

## 8. Доступность

Клавиатурная проходимость флоу; видимый фокус; статус = цвет + иконка + текст; контраст AA;
тач-таргет ≥ 44px; формы с явными ошибками (`aria-invalid`, привязка подписей); reduced-motion.
Для **мегаменю, drawer, модалок, поиска-поповера** — аннотировать: **focus order, focus trap,
закрытие по Escape, keyboard navigation, `aria-live`** для динамики (счётчики/подсказки/тосты).

## 9. Измеримость

| Флоу | Событие успеха | Guardrail | Гипотеза A/B |
|---|---|---|---|
| Подбор гостя | `add_to_cart` после фильтра | просмотр без добавления | счётчики у фасетов ↑ переход в PDP |
| Покупка B2C | `order_submitted` + `payment_succeeded` | брошенные корзины/возвраты | «Купить в 1 клик» ↑ конверсию без роста возвратов |
| Запрос счёта B2B | `b2b_invoice_requested` | время до счёта | предзаполненные реквизиты ↑ долю запросов |
| Привязка MAX | `max_linked` | — | выгода-микротекст ↑ долю привязок |
| Поиск/доступность товара | `search_result_click` | доля пустых выдач, число переходов до топ-категорий | подсказки по артикулу ↓ нулевые выдачи |

# ЧАСТЬ B. UI (приложение)

## 10. Визуальная система
Полностью по `design.md`: светлая тема «Чистая мастерская», **тёмная шапка/подвал**
(преемственность визитки) + signature «инструментальный кант», зелёный = действие
(CTA `--green-700`, AA; изумруд `--green-500` — иконки/лого/крупное, не мелкий текст),
типографика Oswald/Saira + Inter, spacing/radius/shadow, моушн §17. **Сырой hex запрещён.**

## 11. Глобальные компоненты
Шапка, подвал, мегаменю, **единый шаблон карточки товара** (фото→бренд→название→рейтинг→
наличие→цена→CTA; не смешивать шаблоны в сетке — один шаблон/высота в строке), бейдж наличия,
блок цены (единый ценник; НДС выделяется в корзине/счёте), степпер, фасет-чип, инпут/поиск с
подсказками, таб/аккордеон, хлебные крошки, тост, статус-бейдж заказа, блок «Консультация в
MAX», кнопка MAX. Кнопки: primary/secondary/ghost/danger × default/hover/active/disabled/
loading. Детали — `design.md` §9.

## 12. Экран × состояния (рисуем экономно)
**Состояния — на уровне компонентов + ОДИН representative-экран** на состояние (не полный
фрейм на каждую комбинацию). `offline` как отдельный экран **не рисуем** (нет PWA) — вместо
него **network error + retry**; offline-баннер появится позже при наличии service worker.

| Экран (Wave 1) | loading | empty | error/retry | доменные |
|---|---|---|---|---|
| Главная | ✓ (скелетоны секций) | — | ✓ | — |
| PLP/Категория | ✓ | ✓ (0 по фильтру) | ✓ | наличие в карточках |
| Поиск | ✓ | ✓ (0 по запросу) | ✓ | подсказки |
| PDP | ✓ | ✓ (нет отзывов) | ✓ | под заказ/нет/цена изм./контентная деградация |
| Корзина | ✓ | ✓ (пустая) | ✓ | частичная/цена изм./товар без цены |
| Checkout | ✓ | — | ✓ (оплата) | резерв истёк/реквизиты B2B/оплата выключена флагом |
| Спасибо/трекинг | ✓ | — | ✓ | статус заказа, MAX order-link |

## 13. Инвентарь экранов (композиция, Wave 1)

- **Главная:** hero-параллакс 5 слоёв (слайдер категорий) → категории-витрина → хиты продаж →
  баннер «Консультация в MAX» (эксперт) → преимущества → «О магазине» (статичная карта +
  цифры-placeholder) → подписка → подвал.
- **PLP:** крошки → H1+кол-во → (опц. hero категории) → сортировка + вид → сайдбар фасетов
  EAV со счётчиками (моб — drawer) → сетка карточек (lg 3–4 / xl 4–5 / моб 2) → **«Показать
  ещё» + crawlable якорная пагинация** (гибрид; бесконечный скролл без якорей запрещён).
- **Поиск:** поле с подсказками; выдача = PLP без дерева, «Найдено N по “запрос”»; empty с reset.
- **PDP:** галерея (фото + [видео/360 — если есть ассеты]) | колонка покупки (наличие,
  цена+скидка+экономия (единый ценник; НДС в корзине/счёте), гарантия, степпер, «В корзину»,
  «Купить в 1 клик» (qty=1), [сравнить/избранное — W2], блок «Консультация в MAX») →
  H1/бренд/рейтинг/артикул (в DOM — над галереей) → ключевые ТТХ (сетка) → табы → таблица ТТХ →
  «С этим товаром покупают» → преимущества → баннер консультации. Sticky buy-box desktop ≥1200,
  sticky bottom-bar на mobile.
- **Корзина / Checkout / Спасибо** — по §5.2 с доменными состояниями.

## 14. Адаптив и моушн
Рисовать: **desktop 1440, mobile 390, tablet 768**; карточки проверить также на **320/360**
(2 колонки, длинные цены, CTA ≥44px без переноса). Mobile: hero статичный, фасеты в drawer,
sticky bottom-bar покупки. Моушн дозирован (hero + баннер), reveal-блоки, карточки спокойные,
обязательный `prefers-reduced-motion` fallback; параллакс только desktop ≥1024 (`design.md` §17).
