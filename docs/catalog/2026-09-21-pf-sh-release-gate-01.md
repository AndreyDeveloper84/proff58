## 2. Правила гейта

**Фото.** Достаточно одного корректного изображения, которое витрина реально отдаёт
(JSON-LD `image[0]` → HEAD 200, `image/*`). Число фото сверх одного — quality-метрика.

**RELEASE_REQUIRED** — без этого карточка вводит в заблуждение или бесполезна:

| Тип | Сетевой | Аккумуляторный | Вид питания не определён |
|---|---|---|---|
| перфораторы | `power` + `energy_impact` + `chuck` | `voltage` + `energy_impact` + `chuck` | `power` или `voltage` + `energy_impact` + `chuck` |
| шлифмашины (все подтипы) | `power` | `voltage` | `power` или `voltage` |

Плюс значение не должно быть физически неправдоподобным (такое значение тоже блокирует).

**QUALITY_DESIRABLE** — полезно, но не блокирует: `power_source` (если выводится из мощности/напряжения),
`no_load_speed`, `motor_type`, `weight_kg`, для аккумуляторных — `battery_included`, `battery_capacity`.

Обороты у прямых и полировальных шлифмашин оставлены в desirable: без них карточка не вводит в заблуждение,
и блок был бы искусственным. `CORE_COMPLETE` из PF-SH-CHAR-01 используется как метрика качества,
а не как жёсткий гейт.

**Таксономия.** Станок в типе ручных шлифмашин при существующих `stanki-zatochnye` / `tochila-nazhdaki` —
блок. УШМ и полировальные внутри `shlifmashiny` при существующих `bolgarki-ushm` / `polirovalnye` — known gap:
родово тип верный, проблема только в навигации.

**SEO.** Глобальный запрет индексации даёт статус `SEO_SWITCH_PENDING` и не считается дефектом карточки.

**Primary blocker** выбирается по порядку: COMMERCIAL → CARD → CACHE → IDENTITY → TAXONOMY → MEDIA →
CHARACTERISTICS → OTHER. Остальные проблемы SKU записаны в `secondary_gaps`.

### Риск для поискового робота: SSR → API 429 → 500

Когда карточки запрашивались с паузой 0,3 с, 13 из 85 вернули **500**. В логах фронта в этот момент —
`Error: product 429`: Next.js при серверном рендере карточки упирается в rate-limit DRF.
С паузой 3 с все 85 отвечают 200. Робот, который обходит сайт с похожей частотой, получит 500 на части
карточек, а это может привести к выпадению из индекса.

## Решение владельца (2026-09-21)

Гейт принят. Индексацию **не открывать первым действием**: сценарий «робот → 429 → SSR 500» известен.
`PF-SH-RELEASE-01` делает сначала инфраструктуру публикации — устраняет SSR→DRF 429→500, вводит canonical,
sitemap и политику индексации на уровне товара (индексируются только 74 frozen-кандидата из manifest выше,
11 заблокированных и остальной незавершённый каталог остаются закрыты), убирает двойной суффикс title и
разделяет robots.txt по средам. Production robots открывается только после регресса при закрытом robots.
11 блокеров чинятся отдельной волной `PF-SH-BLOCKERS-01`; следующий тип — `bury`, начиная с media-пилота на 20–30 SKU.
