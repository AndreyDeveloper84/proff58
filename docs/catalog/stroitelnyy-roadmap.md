## 3. Правила проектирования

### Принципы
1. **Сначала leaf, потом keywords** — v2-лист даёт контекст, ключи вторичны.
2. **Сначала reuse, потом new option** — не плодить типы.
3. **Сначала recategorize, потом enrich** — чужое сначала увести, потом типизировать своё.
4. **Широкие подстроки запрещены.**
5. **Сначала dry-run, потом write** (свежий pg_dump перед любым write).

### Запрещённые глобально ключи (гарантированный FP)
`гвозд` · `клей` · `эмаль` · `лак` · `бетон` · `винт` · `нож ` · `лезви` — только leaf-scoped и/или узкие составные подстроки.

### Только leaf-scoped
- **Строительные леса** — исключительно внутри листа «Вышки, леса, лестницы и стремянки».
- **Герметики / фиксаторы резьбы** — внутри листа «Герметики и монтажные пены».

## 6. Архитектурные инварианты миграций (соблюдены во всех write)
- `category_is_manual=True` **сохранялся** при всех переносах (сайт остаётся мастером; исправляем конкретное ошибочное размещение, а не отменяем ручное управление).
- recategorize выполнялся **только по явно утверждённым `product_id`** (не по широким правилам).
- каждый бакет имел **rollback-map** (`product_id: old_category → new_category`, для 3D.2b.1 — двойной: category + удаление PAV).
- **product slug / publish-status не менялись** ни в одном переносе.
- `tool_type` / `attrs_cache` менялись **только там, где это часть утверждённого плана** (Round 1/2 enrich, 3D.2b.1).
- **глобальные write-команды не использовались** — всё scoped и идемпотентно проверено (repeat-preview=0 после каждого write).
- перед каждым write — **свежий pg_dump**; запись — в одной `transaction.atomic`.
