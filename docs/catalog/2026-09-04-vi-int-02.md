## Находки

- **I-1 (требует решения перед staging pilot):** у 3 товаров с уже
  существующим главным фото (2092→615, 6794→641, 7057→643) pipeline
  добавил **второй** `is_main=True` (659, 721, 724): `process_batch`
  передаёт `is_main=(i==0)`, демоции старого главного и выставления
  `sort_order` (default 0) в коде нет. Это штатное поведение существующего
  pipeline (код не менялся); гейт «существующие изображения не тронуты»
  выполнен дословно. Риск: ordering `[-is_main, sort_order]` при двух
  `is_main=True, sort_order=0` недетерминирован — какое фото главное на
  витрине, не определено. Варианты: принять / доработать pipeline
  отдельным треком / исключать товары с непустой галереей из image-импорта.
- **R-1 (документационное):** фактический контракт `apply_rollback`
  **удаляет файлы media** (`image_reversibility.py:310`), а не оставляет
  orphans — docstring `catalog_images_ops` утверждает обратное. На
  fidelity отката влияет положительно; docstring стоит поправить.
- **M-1:** см. раздел «Миграция» — коллизия номера 0038 устранена
  переносом на 0039 (локальные изменения, необходимые для VI-INT-02;
  без коммита).
