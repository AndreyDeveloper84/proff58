# Нормализация названий товаров

Правило, по которому витринное название приводится в порядок: что меняем, чего
не трогаем и почему. Реализация — `apps/catalog/name_normalization.py`, прогон —
`manage.py normalize_product_names`.

Основание: замер каталога от 2026-09-08 (DRF-1600, 47 225 товаров на стенде) и
решения владельца по DRF-1601.

## Три поля, три роли

| поле | что в нём | кто пишет |
| -- | -- | -- |
| `original_name` | строка ровно как прислала 1С | только обмен; **нормализация не касается никогда** — это точка отката |
| `name` | витринное название: страница товара, заголовок вкладки, поиск | сайт (нормализация + ручные правки); обмен не перезаписывает (ADR-0007) |
| `card_name` | короткая форма для плитки каталога | сайт; та же косметика, но без раскрытия сокращений |

## Что делает нормализация

1. **Пробелы.** Двойные схлопываются, пробел перед `,` и `;` убирается, края
   подрезаются.
2. **Слипшаяся точка.** `Головка шлиф.алмаз.D95` → `Головка шлиф. алмаз. D95`.
3. **Точка у единиц измерения.** `140мм.` → `140 мм`; список закрытый
   (`мм`, `см`, `кг`, `мл`). `гр.` намеренно не входит: в каталоге это и граммы
   (`453гр.`), и градусы (`Адаптер 90гр.`) — регуляркой не различить.
4. **Единый алфавит.**
   * разделитель размера: латинская `x` между цифрами → кириллическая `х`
     (9 663 названия против 462 — меньшинство иначе не находится поиском);
   * кириллические буквы-двойники внутри латинской маркировки: `RВ18DLL` →
     `RB18DLL`, `CrМоV` → `CrMoV`. Правило одностороннее — чиним только слово,
     где латиницы больше, поэтому `АвтоDело` и `ЗУБР` не трогаются.
   * буква `х` из этой починки **выведена**: в каталоге она прежде всего
     разделитель размера (`PH3х 50 мм`, `19хLED`), и перевод в латиницу спорил бы
     с предыдущим пунктом.
5. **Раскрытие сокращений с согласованием рода.** В начале названия ищем тип
   товара (`GENDER`, 166 слов), он задаёт род — мужской, женский, средний или
   множественное число, — и разворачиваем идущие следом сокращения:
   `Круг алмаз. отрез.` → `Круг алмазный отрезной`, `Клещи обжим.` →
   `Клещи обжимные`. Цепочка обрывается на первом незнакомом слове: в
   `Дрель удар. Makita с алмаз. коронкой` второе сокращение относится уже к
   коронке, род которой в этой позиции неизвестен, — оставляем как есть.
   Недоделать здесь дешевле, чем получить «с алмазный коронкой».
6. **Сокращённый тип товара.** `Перф.` → `Перфоратор`, `Шлифмаш` →
   `Шлифмашина`, `Шуруп.` → `Шуруповёрт`, `Свар. аппарат` → `Сварочный аппарат`.
7. **Предлог «для».** `д/лобзика` → `для лобзика`. Слово после слэша почти
   всегда уже в родительном падеже; обрубленные 1С окончания досклоняем по
   закрытому списку (`д/триммер` → `для триммера`, `д/пист` → `для пистолета`,
   `д/мет` → `для металла`).
8. **Артикул, продублированный в хвосте.** `Кожух защитный для диска УШМ 338845`
   при `article=338845` → без хвоста. Правило узкое, и таким его сделал опыт
   первого прогона:
   * только точное совпадение с полем `article`;
   * артикул **с пробелом не трогаем** — в каталоге это типоразмер
     (`Фитинг цанга прямой 6512 4-1/8`, `Компрессорное масло DICREA 46 (20л)`),
     и без него позиции сливаются в одну;
   * хвост остаётся, если без него в названии меньше четырёх слов: у запчастей
     артикул единственное, что их различает. Сняв его, мы получили на стенде
     32 одинаковых «Зубчатое колесо редуктора» и 28 «Уплотнительное кольцо».

## Чего нормализация не делает — и почему

* **Не додумывает обрезанные названия.** 6 164 позиции обрезаны по 50 символов
  (`…для трубной цилиндр резьбы, стал`). Хвост потерян в данных; вернуть его
  может только перезаливка — DRF-1604. Такие названия нормализуются как обычные
  (пробелы, сокращения), но ничего не дописывается.
* **Не трогает маркировку со слэшем.** `ц/х` (цилиндрический хвостовик, 830
  позиций), `м/р`, `а/ч`, `к/х`, `об/мин`, `л/мин`, `г/п`, `х/б`, `уд/мин` —
  это обозначения, а не «для». Раскрывается единственная ветка `д/`, и только
  когда слева граница слова: иначе `ход/мин` превратилось бы в `хо для мин`
  (32 таких названия).
* **Не раскрывает точку там, где это не сокращение.** `шт.`, `мм.`, `кг.`,
  `гр.`, `мл.` — единицы; `арт.` — метка артикула; `Профессионал.` — серия ЗУБРа.
* **Различает `Шуруп.` и `Шуруп`.** С точкой — шуруповёрт (368 позиций), без
  точки — метиз. Правило чувствительно к точке.
* **Не переставляет слова.** Схема «Тип · уточнения · Бренд · Модель · размеры»
  как целевая форма не применяется: перестановка меняет смысл и не проверяется
  автоматически. Решение владельца по DRF-1601.
* **Не убирает бренд из названия.** `brand` заполнен лишь у 4 205 товаров из
  47 225 — у остальных бренд в названии единственное место, где он есть.
* **Не чинит опечатки источника** (`маетал`, `оргганайзер`, `ЦИКУЛЯНОЙ`):
  словарь опечаток пришлось бы вести вручную, и цена ошибки выше выигрыша.

## Порядок выката

```bash
normalize_product_names --dry-run --in-stock --report /tmp/wave1.csv  # волна 1: глазами
normalize_product_names --in-stock                                    # волна 1: записать
normalize_product_names --dry-run                                     # волна 2: объём
normalize_product_names                                               # волна 2: записать
```

Сначала стенд, на прод — после проверки витрины. Команда идемпотентна: повторный
прогон ничего не меняет.

**Откат.** `original_name` не трогается никогда, поэтому вернуть исходные названия
можно всегда. Штатный способ — пересчитать витринное имя от исходника:

```bash
normalize_product_names --restore-truncated --dry-run  # чинит только своё
normalize_product_names --from-original --dry-run      # пересчитать всё от исходника
```

`--restore-truncated` трогает лишь те имена, которые сам прогон и укоротил
(текущее `name` — начало `original_name`). `--from-original` пересчитывает всё и
**затирает ручные правки**: на стенде у 274 позиций в витринном имени стоит
дописанное руками «(арт. 19001)», которым различали одинаковые товары, — в
исходнике 1С этой добавки нет.

## Новые позиции из 1С

Товар, созданный обменом, получает уже нормализованное `name` и заполненное
`card_name` (`apps/sync_1c/product_writer.py`). Обновление существующего товара
витринное имя по-прежнему не трогает — только `original_name`. Без этого каталог
набирал бы телеграфные названия заново после каждой новой номенклатуры.

## Эффект (замер по стенду, 47 225 товаров)

| | до расширения правил | после |
| -- | --: | --: |
| изменится `name` | 12 557 | 15 690 |
| раскрыто сокращений | 2 673 | 3 383 |
| раскрыто на остатках | 601 | 729 |

Первая волна (позиции на остатках) — 2 471 изменение из 6 203 позиций.
