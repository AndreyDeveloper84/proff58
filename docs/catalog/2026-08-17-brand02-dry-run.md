## 2. Ошибка правила, найденная аудитом dry-run

Первый прогон дал `COMPAT_ONLY` **227**, и разбор показал, что 170 из них ложные:

```
Адаптер  для бит KRAFTOOL BULLDOG 150мм        ← товар KRAFTOOL
Адаптер для биметал.коронок ЗУБР SDS+          ← товар ЗУБР
Адаптер 1/4"F-3/8"M увеличивающий для головок KRAFTOOL
```

«для бит», «для коронок», «для головок» — назначение изделия, а не совместимость с
брендом. Исходное правило считало маркер действующим в окне 20 символов слева.
Окно здесь не работает в принципе: разрыв между маркером и брендом одинаков и в
ложном, и в верном случае —

```
Щетки угольные АНАЛОГ 5х10х14мм 18-120 MAKITA   → MAKITA совместимость
Круг отрезной для металла 125х1,6х22,2 ЗУБР     → ЗУБР производитель
```

Разделяет не расстояние, а то, является ли бренд **прямым объектом предлога**.

### Итоговое правило — два класса маркеров

| класс | маркеры | действие |
|---|---|---|
| `strong` | аналог, совместим, подходит, замена, взамен | на всё название: любой бренд правее — совместимость |
| `adjacent` | для, под, тип | только вплотную: между маркером и брендом лишь пробел, знак или «с»/«к» |

После правки: `COMPAT_ONLY` 227 → 51, `CREATE` +170.

**Проверка обратного направления.** 433 товара к записи содержат маркер где-то левее
бренда, но не вплотную. Выборочный разбор — все собственная продукция бренда
(«Адаптер для алмазных коронок KRAFTOOL SDS-max»). Мягкое правило потеряло бы их.

## 4. Контракт команды

```
python manage.py catalog_fill_brand                     # dry-run по умолчанию
python manage.py catalog_fill_brand --apply --rollback-artifact <path>
```

Флаги: `--in-stock-only`, `--active-only`, `--json-report`, `--rollback-artifact`,
`--vocabulary`, `--limit`.

* писать имеет право **единственный статус `CREATE`**;
* **`changed` не существует как исход.** Обмен с 1С пишет бренд только в пустое поле
  (`sync_1c/product_writer.py:103`), то есть первый записавший владеет полем. Команда
  ведёт себя так же и после первого apply: занятое поле с другим извлечением — это
  `CONFLICT` на разбор, а не тихий update;
* `--apply` без `--rollback-artifact` падает с ошибкой: без прежнего значения откат
  неотличим от «бренда никогда не было»;
* артефакт хранит `{product_id, old_brand, new_brand}` по каждой записи;
* повторная сверка поля идёт **внутри транзакции** под `select_for_update` — план
  строится вне неё, и чужая запись между планом и применением даёт `CONFLICT`.

## 5. Остаточный риск

Строгая смежность может пропустить совместимость вида «для <код модели> <БРЕНД>»
(«Аккумулятор для ДА-24-2ЛК Зубр»): маркер не вплотную, бренд получит статус
производителя. Направление ошибки выбрано сознательно — лучше не записать спорное,
чем записать чужого производителя; но в текущем правиле такой случай уйдёт в
`CREATE`. Кандидат на уточнение после первого сбора с внешнего источника, где
`source_brand` даст независимую проверку.
