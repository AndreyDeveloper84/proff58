# Оси под бензопилы и триммеры (DRF-1439)

Read-only разбор выгрузки huter.su, карта сопоставления и dry-run. **Записей в
каталог в этой задаче нет** — ни атрибутов, ни значений; заливка идёт отдельным
шагом гейт-циклом с `pg_dump` (`docs/catalog/operations/README.md`).

## 1. Замер

Выгрузка huter.su — 654 карточки. План совпадений (`/tmp/huter_applied2.json`,
тот же, по которому лились фотографии PR #675/#676) даёт 64 наших товара; они

| -- | -- |

## 2. Разбор подозрительных значений

### `Шаг цепи, дюйм = 1.4` — это дробь 1/4, а не 0.404

Постановка предполагала опечатку `0.404`. Данные говорят другое: значение стоит
на цепи C10, и **и наше имя из 1С**, и **имя карточки источника** содержат шаг
явно.

| | |
| -- | -- |
| наш товар | `Цепь 45 звена C10 1/4  8" HUTER для ELS-20/8` |
| карточка huter | `Цепь С10 Huter (8"-1/4-45 для ELS-20/8 Li)` |
| поле карточки | `Шаг цепи, дюйм = 1.4` |

Подтверждение с двух других сторон: соседняя цепь C9 того же шага подписана
корректно (`Шаг цепи, дюйм = 0.25`), а совместимая с ней пила ELS-20-Li-2К в
поле `Шаг цепи` даёт `1/4`. Итог: у источника **потерялась косая черта дроби**.
В карте `1.4 → pitch-1-4` с `confidence: low`, чтобы значение оставалось видно в
отчёте импорта.

### `Длина шины, мм = 152.4` — не другая единица, а точный перевод из дюймов

152.4 = 6.0 × 25.4 ровно. Значение стоит на цепи C9 для ELS-20Li, а ту же пилу
источник в поле `Длина шины, мм/дюйм` подписывает `150/6`. То есть это **та же
6-дюймовая шина**, только один раз переведённая точно, а другой — округлённая до
номинала. Остальной ряд (350, 400, 450, 500, 505) целыми дюймами не делится и
пришёл номиналами.

Решение — нормализатор `bar_length_mm`: точный перевод из дюймов приводится к
номинальному ряду, который взят **из самого источника** (поле «мм/дюйм» даёт
пары 150/6, 250/10, 300/12, 400/16, 450/18, 505/20). Номиналы не трогаются.

### Дефекты источника, которые картой не чинятся (вынесены владельцу)

* **500 vs 505 на 20 дюймах.** Huter подписывает 20-дюймовую шину и `500`, и
  `505`; обе — его собственные номиналы, ни одна не является точным переводом,
  поэтому нормализатор их не трогает. В фасете `bar_length` 20-дюймовые
  разойдутся на два значения.
* **Цепь C2:** источник даёт `Количество звеньев = 62`, наше имя из 1С — «Цепь
  **63** звена C2». Проверить перед заливкой.

## 3. Новые оси — 7, с доказательством отсутствия дубля

Проверка велась **по смыслу** против всех 77 существующих `Attribute` (поиск по
`name` + `slug` по корням, плюс группировка по единицам измерения и замер
фактического использования). Известные дубли словаря (`weight`↔`weight_kg`,
`load_capacity`↔`capacity`) третьего не получают.

| Новый | Тип, ед. | Значений / разных | Почему не дубль |
| -- | -- | -- | -- |
| `bar_length` «Длина шины» | decimal, мм | 27 / 6+ | Ближайший кандидат — `length` («Длина», мм). Он **не подходит и не занят**: 2113 значений в каталоге и **ноль** в пяти типах скоупа; фактически стоит на бурах (820), пассатижах, уровнях, ножовках — это длина самого изделия. На цепи и на шине «длина шины» — ось совместимости, а не размер изделия; складывать их в одну ось нельзя. |
| `chain_pitch` «Шаг цепи» | select | 22 / 3 | Единственное совпадение по корню — `thread_pitch` («Шаг резьбы», мм): другая физическая величина и другая единица. Опции: `pitch-1-4`, `pitch-0-325`, `pitch-3-8`, `pitch-0-404` (закрытая мировая номенклатура). |
| `chain_links` «Количество звеньев» | decimal, шт. | 26 / 9 | Совпадения по корню — `package_quantity` («Количество в упаковке») и `piece_count` («Предметов в наборе»): это счёт вложений, а не конструктив изделия. Тип `decimal` — конвенция каталога для счётных осей (обе перечисленные тоже decimal). |
| `chain_gauge` «Толщина звена» | decimal, мм | 21 / 2 | Совпадений по смыслу нет вообще: оси «толщина» в словаре не существует. |
| `engine_displacement` «Объём двигателя» | decimal, см³ | 12 / 5+ | Оси объёма в словаре нет ни одной (проверено по единицам: см³ и л отсутствуют). `capacity`/`load_capacity` — грузоподъёмность в тоннах, `battery_capacity` — А·ч. |
| `chain_auto_oiling` «Автоматическая смазка цепи» | boolean | 12 / 2 | Совпадений нет. |
| `split_shaft` «Разъёмная штанга» | boolean | 14 / 2 | Совпадений нет; семейство триммерных осей (`head_design`, `line_feed`, `quick_load`) эту величину не покрывает. |

### Оси, которые НЕ заводятся — потому что уже есть

* **`Напряжение аккумулятора, В` → существующий `voltage`.** Прямой ответ на
  проверку §2 постановки: новый атрибут не нужен. Значения 12 и 20 В проходят
  порог battery (< 60 В) и пишутся; сетевые `220-230В, ~50 Гц` импортёр сам
  отбрасывает в `skipped_voltage` (в dry-run — 5 штук).
* **`Тип катушки` → существующий `quick_load`** («Быстрая заправка лески»,
  boolean, заведён в P1 вместе с `head_design`/`line_feed`). «Easy Load» —
  фирменное имя Huter ровно для этого. Заводить `spool_type` значило бы
  повторить историю `weight`/`weight_kg`.
* `Емкость аккумулятора` → `battery_capacity`; `Частота вращения, об/мин` →
  `no_load_speed`; `Тип двигателя` → `motor_type` (только значения про щётки).

### Оси, отклонённые правилом DRF-1428 (< 2 разных значений)

| Подпись | В скоупе | Комментарий |
| -- | -- | -- |
| `Антивибрационная система` | 11 значений, все «Есть» | вариант «Нет» источник не пишет вовсе |
| `Тормоз цепи` | 6, все «Есть» | |
| `Уровень звукового давления, дБ` | 6, все 96 | второе значение (80) в постановке пришло с воздуходувки — она вне скоупа; ось откроется вместе с `bp-vozdukhoduvki`/`bp-generatory` |
| `Ширина скоса диском, мм` | 6, все 255 | |
| `Ширина скоса леской, мм` | 6, все 460 | |
| `Число оборотов, об/мин` | 6, все 9500±500 | плюс это макс. обороты, а не х.х. — в `no_load_speed` класть нельзя |
| `Зажигание` | «электронное (CDI)» и «Электронный» — одно значение | |

Замечание к постановке: `noise_level` в её таблице предложен на основании счёта
по всем 64 товарам. По скоупу бензопил и триммеров он правило не проходит.

### Отложено сознательно (в `unmapped` с причиной)

* `fuel_tank_capacity` / `oil_tank_capacity` — ось живая, но у Huter та же
  величина идёт в двух единицах: «мл» у пил и «л» у генераторов/мотопомп.
  Единицу оси выбирать разом по всей бензотехнике, а не по пяти пилам.
* `noise_power_level` — `Уровень шума, Дб` не различает LpA и LwA (разница ~11
  дБ); смешивать в один фасет нельзя, это та же ловушка, что брутто/нетто веса.
* `line_diameter` — в существующий `diameter` не кладём: там диаметр изделия
  (свёрла, буры, диски), а тут расходник в комплекте.
* `engine_stroke` (2-тактный / 4-тактный) — значений хватает, но извлекается из
  прозы («Одноцилиндровый, двухтактный, бензиновый двигатель…»), а не словарём.
* **`power` и `weight`/`weight_kg` из карты исключены целиком** — это трек
  DRF-1440, чтобы два трека не столкнулись на одних осях.

## 4. Карта

`data/catalog_processing_rules/scraped_attr_map.benzopily-trimmery.json` —
**одна карта на семейство** из пяти `tool_type` (`scope_tool_types`), потому что
оси шины и цепи общие: длина шины стоит и на пиле, и на цепи, и на шине. Пять
копий одного файла разошлись бы.

Нормализаторы под требования постановки:

| | |
| -- | -- |
| десятичная запятая (`25,4`, `51,7`, `1,3`) | штатный `decimal`, отдельного правила не потребовалось |
| кавычки в select (`Easy Load` / `«Easy Load»` / `« Easy Load »`) | `option_key`: снимает кавычки любого начертания и схлопывает пробелы — одна опция, не три |
| `152.4` → `150` | `bar_length_mm` |
| `«400/16"»`, `«250/10”»` | `bar_length_mm` берёт первое число (миллиметры) |
| «Есть»/«Нет» | `boolean_map` — словарь в карте, молчаливой эвристики нет |

Два изменения движка (`apps/catalog/scraped_import.py`):

1. **boolean-оси** — раньше движок знал только select и число; без этого
   `chain_auto_oiling`, `split_shaft` и `quick_load` были бы недоступны, хотя
   постановка их прямо называет.
2. **одно поле → две оси** — `Толщина звена и шаг цепи, мм/дюймы` = `1,3 / 3/8`.
   На месте правила стоит список правил с `extract`-регулярками. Без этого пять
   флагманских бензопил остались бы вовсе без характеристик цепи: другого
   источника шага и толщины у них нет.
