## 1. Обязательный формат

### canonical key
`package_quantity` — существующий атрибут id=85. Новую ось не создаём (DECISION 2).

### display name
«Количество в упаковке» (как в БД и в блоке `str-skoby`). В `discover_missing_rules`
ось названа «Фасовка» — это только текст probe, БД не трогает.

### canonical unit
`шт.` (строка с точкой, как у атрибута в БД и в блоке `str-skoby`). `load_attributes`
сравнивает `unit` как safe-field: во всех фрагментах proposal `unit = "шт."`, поэтому
действие по атрибуту — `keep`, а не `update`.

### source units
Только «шт» и его формы: `шт`, `шт.`, `штук`, `штуки`, `ШТ` (регистр снимает `normalize`),
приклеенные `штдля`, `штЗУБР`. **Не источники**: «пар/пары» (перчатки «25 пар (50шт)» —
единица пары, а не штуки), «кг/пачка N кг» (электроды, дюбель-гвозди «упак 25кг»), «л»,
«м», «рул/уп», «листов». Слова «уп.», «упак», «/уп», «коробка», «ведро», «за N шт.»,
«в упак» — только контекст, число берётся из «N шт».

### conversion rules
Нет конверсий: число пишется как есть (Decimal без масштаба). Правила формы:
- значение **≥ 2** — `([1-9]\d{1,4}|[2-9])`; «1 шт», «(1шт.)» не пишутся (11 названий
  у пилок/полотен и по одному у стяжек/бит — молчание, единица упаковки не фасовка);
- максимум 99 999 (5 разрядов), «10 000шт» с пробелом-разрядом **не читается** (4 гвоздя
  KRAFTOOL 23GA — молчание; писать 10 или 0 — ложь);
- lookbehind `(?<![\d+\-хx])`: число не продолжает другое число, не идёт после «+»
  («50+50шт»), «-» («1кг -500 шт»), «х»/«x» («8х10 шт» — размерная пара). Запятая/точка
  перед числом **разрешены** («STAYER,100 шт», «уп.50шт», «(G/11/57),5000 шт»);
- правая граница `шт(?![a-z]|(?!для|зубр|ук)[а-я])`: после «шт» нельзя букву — режет
  бренд ШТОК, «штока», «штуцер», «штепсельных», «штампованный», — но пропускает
  приклеенные «3штдля мини УШМ», «100штЗУБР» и словоформы «штук/штуки»;
- форма «×N»: «Круги шлиф.перфор. х10 шт.» — отдельный шаблон `(?<!\S)[хx](\d{1,3})\s*шт`
  только у `krugi-shlif`.

### allowed source fields
Только `Product.original_name` (движок `AttributeRules.extract`, `source=regex`, priority 40).
Карты скрапера (`scraped_attr_map.*.json`) ось не несут — единственное упоминание в
`benzopily-trimmery` это комментарий про тип `decimal`. Скрапер как источник фасовки
не предлагаю: это отдельный трек.

Формы записи (все из реальных названий, см. `cases.json`): `10шт`, `5 шт`, `(10 шт.)`,
`(5шт)`, `за 10 шт.`, `уп 1000шт`, `упак 125шт`, `(уп.50 шт)`, `100 шт/уп`, `6000шт/упак`,
`в упак 5шт`, `5шт. упак.`, `коробка 150 шт`, `100 шт ведро`, `S24 10шт`, `(5 шт; 8 мм)`,
`4 ШТ`, `24 штук`, `3штдля`, `100штЗУБР`, `х10 шт.`.

### existing Attribute collision
Прямой коллизии нет: `package_quantity` уже существует и используется. Похожие по смыслу
оси: `piece_count` («Предметов в наборе», unit «шт» без точки) — другая семантика,
владельцы не пересекаются; `chain_links` («Количество звеньев», «шт.»), `socket_count`,
`teeth_count`, `ram_count` — счёт конструктива, не упаковки. Единица «шт.» vs «шт» — два
разных строковых unit у двух атрибутов; в БД так уже месяц, proposal это не меняет.

### existing PAV collision
- `package_quantity`: 62 PAV, все `str-skoby` — proposal блок скоб не трогает, движок
  даёт те же 62 значения (`keep`).
- `piece_count`: 496 PAV в 5 типах, **ни одного у 15 типов proposal** → один товар не
  получит обе оси. Гарантия на будущее: `skip_if набор/комплект` у всех фрагментов + ни
  один блок не объявляет обе оси одновременно (предлагаемый инвариант, см. ниже).
- Другие оси кандидатов (`width` у лезвий/СВП, `diameter` у тросов, `grit`/`width`/`length`
  у абразивов, `length`/`diameter` у крепежа) — независимые slug, конфликтов нет;
  проверено, что `width=18` у «Лезвие 18х100х0,5мм … 10шт» сохраняется рядом с
  `package_quantity=10`, а `width` у «Клинья для кафеля … 100 шт» по-прежнему молчит
  (skip_regex «клин» — у width, не у фасовки).

**Предлагаемая формулировка инварианта** (взамен `owners == [SKOBY]`):

```python
# Явный реестр владельцев оси фасовки. Каждое добавление — решение владельца каталога
# (ХАР-20 → str-skoby; DECISION 2 2026-09 → лезвия, тросы, СВП [+ tier 2]).
PACKAGE_QUANTITY_OWNERS = frozenset({"str-skoby", "hoz-lezviya", "hoz-trosy", "krep-svp", ...})

def test_package_quantity_owners_are_an_explicit_registry():
    raw = _ruleset()
    owners = {t["tool_type"] for t in raw["tool_types"]
              if any(a["slug"] == "package_quantity" for a in t["attributes"])}
    assert owners == PACKAGE_QUANTITY_OWNERS          # ни больше, ни меньше
    # Фасовка и «предметов в наборе» никогда не живут в одном блоке (кроме
    # transitional corrective-ruleset, который в боевом файле не хранится).
    for t in raw["tool_types"]:
        slugs = {a["slug"] for a in t["attributes"]}
        assert not ({"package_quantity", "piece_count"} <= slugs), t["tool_type"]
    # Наборы — территория piece_count.
    assert not any(tt.startswith("nabory-") for tt in owners)
    # Каждый владелец глушит наборы: «N шт» у набора не становится фасовкой.
    for t in raw["tool_types"]:
        for a in t["attributes"]:
            if a["slug"] == "package_quantity" and t["tool_type"] != "str-skoby":
                assert {"набор", "комплект"} <= set(a.get("skip_if", []))
```

(`str-skoby` исторически без `skip_if`; можно добавить — на 68 названиях скоб слов
«набор/комплект» нет, поведение не изменится.)

## 2. Что ещё проверено

- **piece_count ↔ package_quantity на одном товаре**: 0 пересечений сейчас; у всех
  фрагментов `skip_if набор/комплект/к-т`, поэтому «Набор отверток и бит 114 шт» и любой
  «набор …» остаются на `piece_count`.
- **Ловушка ШТОК**: правая граница не пропускает букву после «шт» — проверено на
  «№3 ШТОК» (в блоке nabory-instrumenta ось не объявлена; даже generic-шаблон даёт None).
- **«2шт» у клиньев для топора**: `topory` не владелец, `weight_kg` не задет.
- **«х10 шт» vs «8х10 шт»**: первое читается только у кругов отдельным шаблоном, второе
  молчит везде.
- **Стенд ≠ документ**: снимок стенда показал 62 PAV, а не 22 из docs — остаток скоб
  дописан позже; ХАР-20-документ описывает только corrective-окно.
