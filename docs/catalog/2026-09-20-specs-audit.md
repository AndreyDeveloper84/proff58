# DATA-01: аудит характеристик товаров на витрине

Дата: 20.09.2026. Источник — публичный API боевого стенда `proff58.ru`, только чтение.
Выборка: до трёх конечных разделов в каждом из 15 корневых, первые 24 товара раздела —
всего 947 товаров. Это срез, а не полная проверка 47 тысяч позиций.

## Как было и как стало

Карточка списка показывала значения без названий, в алфавитном порядке названий:

```text
Перфоратор DH24PG:  730 Вт · Сеть · SDS-plus · 2,7 Дж
Бензопила HUTER:    Да · 505 мм · 76 шт.
```

Теперь это пары «Название: значение» в порядке важности для типа товара:

```text
Перфоратор DH24PG:  Энергия удара: 2,7 Дж / Мощность: 730 Вт / Тип патрона: SDS-plus
```

Ответ API для того же перфоратора, `GET /api/catalog/products/?category=elektroinstrument&tool_type=perforatory`:

```json
// было: по алфавиту названий
["Мощность", "Питание", "Тип патрона", "Энергия удара", "Тип инструмента"]
// стало: по типу товара, служебный тип — последним
["Энергия удара", "Мощность", "Тип патрона", "Питание", "Тип инструмента"]
```

Detail-эндпоинт отдаёт тот же порядок и флаг `is_key`. Карточка списка, быстрый просмотр
и блок «Главное в работе» берут первые характеристики из одного списка и не расходятся.

Порядок хранится в `data/card_attribute_order.json`: общий рейтинг осей и переопределения
для 21 типа товара. Файл курируемый. Новый тип без переопределения получает общий рейтинг.

## Проблемы данных и правила исправления

Представление этими проблемами не занимается: пустое значение оно просто не рисует,
выдуманных значений не подставляет. Исправлять нужно данные.

### 1. Пустое значение у «Высоты подъёма»

Десять талей и лебёдок имеют характеристику `lift_height` со значением `null`:
`00031235`, `00008090`, `00001870`, `00001918`, `00030365`, `00009474`, `00009793`,
`00012199`, `00014094`, `00007750`.

Пример: «Таль рычажная г/п 6,0тн, высота подъёма 3м GEARSEN». В названии высота указана
в метрах, а ось заведена в миллиметрах. Извлечение создало запись, но значение не записало.

Правило: в блоке правил талей принять метры и перевести в миллиметры либо завести для
талей отдельную ось в метрах. Пустые записи удалить штатной уборкой характеристик.

### 2. Поле «бренд» не заполнено

У 42 % товаров выборки бренд пуст, у каждого шестого из них бренд написан в названии.
Примеры: «Домкрат 10 т … MATRIX», «Домкрат 12т … ЗУБР», «Лебедка 1,1 т … ЗУБР»,
«Перфоратор DH24PG».

Следствие для витрины — страницы брендов бедны:

| Бренд | Точная выдача | Поиск по слову |
|---|---|---|
| Makita | 2 | 134 |
| Bosch | 27 | 222 |
| DeWALT | 0 | 6 |
| Metabo | 2 | 57 |
| AEG | 0 | 1 |
| Milwaukee | 0 | 0 |
| Hilti | 0 | 0 |
| Stanley | 0 | 2 |
| Ресанта | 114 | 185 |

Правило: заполнение уже реализовано командой `catalog_fill_brand` (BRAND-02). Она по
умолчанию работает без записи и умеет отчёт `--json-report` и файл отката
`--rollback-artifact`. Запуск с записью на стенде — решение владельца каталога.
Товары вида «аналог Metabo» и «для Makita» команда отсекает: это совместимость, не бренд.

Milwaukee и Hilti в каталоге отсутствуют совсем. Их плитки на главной ведут на страницу
«товаров сейчас нет». Решить, оставлять ли эти бренды в блоке.

### 3. Почти половина товаров без характеристик

У 45 % товаров выборки есть только служебный «Тип инструмента». Карточка у них остаётся
без блока характеристик, страница товара — без технического паспорта. Значения не
выдумываются.

Правило: очередь правил извлечения ведёт команда `discover_missing_rules`. Она показывает,
какую ось писать следующей и сколько товаров это закроет.

### 4. Неверный тип или раздел

- `00027507` «Державка 22-152 мм для коронок» — тип «Отрезные и шлифовальные круги».
- `00037323` «Ванночка для краски» — тип «Валики и ролики».
- `010295EY87` «Аккумулятор HUTER 12 В для генераторов» лежит в разделе «Генераторы».

Правило: перенос через штатный контур типов (`enrich_tool_type`, сначала без записи).

### 5. Ось названа не тем, что измеряет

`375125` «Маска сварщика „Хамелеон“ 100х50мм»: «Длина: 50 мм», «Ширина: 100 мм». Это
размер смотрового окна, а не маски. Покупатель прочтёт это как габариты изделия.

Правило: для масок завести ось «Смотровое окно» вместо общих «Длина» и «Ширина».

### 6. Одинаковая подпись у разных осей

«Тип» — это и `domkrat_type`, и `level_type`. Внутри одного товара они не встречаются,
поэтому на карточке путаницы нет. В сравнении товаров разных типов подписи совпадут.

Правило: задать отображаемые названия «Тип домкрата» и «Тип уровня».

## Состояние задачи

Представление готово: пары «Название: значение», порядок по типу товара, единый для
карточки, быстрого просмотра и страницы товара; пустые значения не рисуются, `0` и «Нет»
сохраняются. Наполнение данных — отдельная работа по спискам выше.
