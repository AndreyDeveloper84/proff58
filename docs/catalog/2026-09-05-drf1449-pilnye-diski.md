# ДРФ-1449 — тип `pilnye-diski`: манифест 360 → 361

Дата: 2026-09-05. GO владельца получен. Изменение манифеста таксономии,
меняется canonical-хэш контура.

## Что было не так

327 товаров в листе **87 «Пильные диски»** имели `tool_type = krugi-shlif`
(«Отрезные и шлифовальные круги»). Пильный диск и отрезной круг — разные
товары с разными осями: у круга это диаметр, толщина, посадка и материал
обработки, у диска — диаметр, посадка и **число зубьев**, которого у круга
нет вовсе. Пока они в одном типе, общего осмысленного набора характеристик
у них быть не может: любая ось заполнена у половины пула и пуста у другой.

Видно это и по фасетам листа 87: `disc_diameter` 124 значения, `bore` 60,
а `disc_type` привязан и **мёртв — 0 значений**, потому что ни одно значение
словаря отрезных кругов к пильным дискам не применимо. Панель типа при этом
заявляет покупателю «отрезной круг».

## Аудит категории 87 (предусловие ТТ-19 снято)

По ТТ-19 создание типа было обусловлено аудитом категории 87. Аудит выполнен,
read-only, записей в БД не делалось:

| проверка | результат |
|---|---|
| товаров в листе 87 | **327** |
| из них с типом `krugi-shlif` | **327** — все |
| в листе без `tool_type` | 0 |
| названий вида «диск пильный» в листе | **327 из 327** |
| пильных дисков **вне** листа среди прочих 990 `krugi-shlif` | **0** |
| источник значения типа у всех 327 | `manual` |

Множества совпадают точно. **Дерево уже верное — переносить нечего**, сломан
только словарь типов. Остальные 990 `krugi-shlif` лежат в 82 `krugi` (487),
85 `shlifovalnye-zachistnye` (292), 83 `lepestkovye` (167), 77 `diski` (26),
109 `na-moderaciyu` (9), 102 `abrazivy` (8), 181 `trimmery-i-motokosy` (1) —
и ни один из них по названию не пильный диск.

## Изменение манифеста

Добавлена одна опция, `sort_order` 18 — рядом с `krugi-shlif`:

```json
{"slug": "pilnye-diski", "value": "Пильные диски", "sort_order": 18,
 "origin_kind": "manual_backport",
 "origin_ref": "DRF-1449 + owner decision 2026-09-05",
 "review_status": "approved", "review_ref": "drf-1449"}
```

Хэши пересчитаны штатными рецептами (`taxonomy_manifest.py`); перед
пересчётом рецепты проконтролированы на неизменённом файле — оба сошлись
с записанными значениями.

| | было | стало |
|---|---|---|
| options | 360 | **361** |
| `taxonomy_identity_hash` | `ddf4b949…` | **`9313a959…`** |
| `manifest_semantic_hash` | `afe2b1ab…` | **`afd18768…`** |

## Перевыпуск замороженных артефактов

`taxonomy_hash` входит в gate-sample, а `labels.sample_hash` — это
`canonical_hash(sample)`, поэтому оба файла перевыпущены на новый canonical
binding. **Строки не тронуты: 103 как были.** Рецепт `sample_hash` так же
проконтролирован на неизменённых файлах перед правкой.

Release manifest перегенерирован командой `catalog_rules_release_manifest`
(`--force`), повторный `--check` — `ok`, exit 0. Новый

## Что ещё НЕ сделано (следующий шаг, отдельным гейт-циклом)

Изменение манифеста само по себе **не трогает БД**. После выката нужно:

1. `load_tool_types` — засев опции из манифеста (fail-closed, no-delete).
   ⚠️ У команды есть побочный эффект: `update_or_create` с
   `defaults` `is_filter`/`is_seo_facet=True` молча перезаписывает
   существующие привязки категорий — снимок `CategoryAttribute` до и после
   обязателен в post-audit.
2. Перетипизация 327 товаров листа 87 с `krugi-shlif` на `pilnye-diski`:
   `pg_dump` → снимок отката → запись → post-audit → повторный dry-run
   как no-op.
3. Отдельно решить судьбу мёртвой привязки `disc_type` к листу 87 и
   осмысленных осей для нового типа (число зубьев).

## Границы

Записей в БД в рамках этой правки нет. Дерево не менялось: категория 87
остаётся на месте со всеми 327 товарами. Прочие 990 `krugi-shlif` не
затронуты. Таксономия только расширена — удалений и переименований нет.
