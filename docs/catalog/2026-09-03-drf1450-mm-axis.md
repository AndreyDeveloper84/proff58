# DRF-1450 — ось размера в миллиметрах из собственных названий 1С

Замер и dry-run: 2026-09-03, стенд `proff58_staging-web-1`. **В БД не записано
ничего**: read-only замеры, правила, два dry-run, план привязок. Заливка — отдельным
окном по гейт-циклу (`docs/catalog/operations/README.md`).

## 1. Перемеренное покрытие

Постановка считала только товары **без единой оси** и давала по листьям 26–49 %.
Правильный счёт — `(уже заполненные + новые) / всего товаров листа` — по выбранным
листьям выглядит иначе.

Пул: `is_active=True AND available_quantity > 0` — 6 150 товаров, из них 2 763 имеют
`tool_type` и ни одной другой оси; 979 из этих 2 763 несут «N мм» в названии
(в постановке 1 149 — расхождение от более широкого regex замера, где под «мм»
попадали и вторые члены пар).

| Лист | Ось | Всего | Было | Станет | Различных значений |
| -- | -- | --: | --: | --: | --: |
| `shpateli-kelmy-i-terki` (196) | `width` | 62 | 3 (4 %) | **56 (90 %)** | 21 |
| `chashki` (76) | `disc_diameter` | 28 | 0 | **28 (100 %)** | 4 |
| `elektrika-elektromontazh` (389) | `tape_width` | 24 | 0 | **19 (79 %)** | 5 |
| `almaznaya-osnastka` (75) | `disc_diameter` | 11 | 0 | 5 (45 %) | 1 |

Три первых листа проходят порог 50 % и дают настоящий фасет. Четвёртый —
побочный: пять чашек лежат в «Алмазной оснастке», где `disc_diameter` уже привязан;
одно различное значение фасет там не оживит, отдельной задачей это не считаем.

## 2. Ось выбирается по типу инструмента, а не по единице

«N мм» означает разную величину, поэтому одного правила «мм → `diameter`» не
существует. Живую ось `diameter` (3 412 значений) ни одно из трёх правил не трогает
— это заперто тестом `test_millimeters_never_land_in_diameter`.

| `tool_type` | Ось | Почему именно она |
| -- | -- | -- |
| `str-shpateli` | `width` (Ширина) | «Шпатель 150 мм» — ширина полотна. Второй размер зубчатого («зуб 6х6мм») — уже существующая ось `notch_size`, 16 значений в этом же листе. |
| `chashki-shlif` | `disc_diameter` (Диаметр диска) | У чашки «N мм» — диаметр. Берём ту же ось, что у кругов, чтобы в «Алмазной оснастке» фасет был один, а не два синонима. |
| `hoz-izolenta` | `tape_width` (Ширина ленты) | «Изолента 19мм х 20м» — ширина ленты; длина рулона всегда в метрах, под «мм» не попадает. Ось живая, 120 значений. |

Новых `Attribute` не требуется — все три оси уже существуют.

## 3. Пары размеров

175 товаров пула несут «AxB». Пара как одно число не разбирается:

* `Шпатель 150мм зуб 6х6мм` → `width=150`; число после «х» заблокировано lookbehind,
  плюс ширина берётся первым совпадением;
* `Чашка алмазная для заточки 125х32` → `disc_diameter=125`; «х» у диаметров
  конструктивна и не блокируется (решение владельца), поэтому первое число пары
  читается явным паттерном, а посадка 32 в ось диаметра не попадает;
* `Чашка алмазная 175 мм посад. диам. 22 мм` → 175, а не 22;
* тройки (`125*22,2*20`, `100/22,23-15`, `125х5х22 мм`) и `Шпатель резиновый 150х50 мм`
  — правило молчит целиком. Разделители значимы, «нормализовать для надёжности» здесь
  нельзя.

Ось `bore` у чашек **не заводится**: посадка у всей выборки одна (32) — меньше двух
различных значений, правило DRF-1428.

## 4. Dry-run

Ruleset прогона = файл стенда + три новых блока (см. §6 — расхождение стенда с `dev`).

```
--active-only --in-stock-only :  108 товаров → 105 значений
                                 width 53 | disc_diameter 33 | tape_width 19
                                 create 105, update 0, prune 0, skipped_priority 0
без фильтров (весь пул)      :  301 товар  → 285 значений
                                 width 194 | disc_diameter 72 | tape_width 19
                                 create 285, update 0, prune 0, skipped_priority 0
```

**Ни одной перезаписи**: `current_value` пуст у всех 285 строк. Ни одно существующее
значение — ни `diameter`, ни `notch_size`, ни `width` у кельм — не затрагивается.

Не извлечено 16 из 301 (в наличии — 3 из 108): наборы («Набор шпателей 3
предмета:40,60,80мм»), тройки размеров, пары «150х50 мм» и товары вообще без размера
в названии. Все 16 проверены глазами — молчание правильное.

`load_attributes --dry-run --strict-live-categories`: привязок создать **2**, изменить 0.

```
chashki-shlif | Чашки (76)                     | disc_diameter | create | bound:tree
hoz-izolenta  | Электромонтаж (389)            | tape_width    | create | bound:tree:live
str-shpateli  | Шпатели, кельмы и тёрки (196)  | width         | keep   | bound:tree
```

Все три садятся на **живой лист**, а не в корень раздела (известная ловушка 28 блоков
из 48). У шпателей привязка `width` уже существует и остаётся `keep` — флаги
`is_filter`/`is_seo_facet` молча не переписываются.

## 5. Команды заливки (для отдельного окна)

```bash
# 1. pg_dump до записи
docker exec proff58_staging-db-1 pg_dump -U proff proff58 | gzip > pre-drf1450-<дата>.sql.gz

# 2. привязки (создаст 2 CategoryAttribute)
docker exec proff58_staging-web-1 python manage.py load_attributes --strict-live-categories

# 3. значения — только пул «в наличии», как решил владелец
docker exec proff58_staging-web-1 python manage.py enrich_attributes \
    --tool-type str-shpateli --tool-type chashki-shlif --tool-type hoz-izolenta \
    --active-only --in-stock-only

# 4. post-audit: фасеты листьев 196 / 76 / 389
```

Откат: `enrich_attributes` пишет `source=regex`; созданные PAV удаляются по списку из
JSON-отчёта dry-run. Снимок из шага 1 — страховка.

## 6. Найденное попутно: стенд разошёлся с `dev`

`/app/data/attribute_rules.json` на стенде **не равен** файлу в `origin/dev`:

* на стенде есть 5 блоков, которых нет в `dev`: `bp-benzopily`, `bp-generatory`,
  `bp-motobloki`, `bp-motopompy`, `bp-trimmery`;
* на стенде есть ось `weight_kg` в блоках `domkraty`, `dreli-shurupoverty`,
  `perforatory`, `shlifmashiny`, которой в `dev` нет;
* блок `molotki` отличается.

Ближайший деплой `dev` на стенд перезапишет файл и эти правила со стенда исчезнут.
Влить их в `dev` — задача того окна, которое их применяло; здесь только фиксируем факт.
Dry-run этого трека сделан на файле стенда + три новых блока, поэтому его числа не
искажены расхождением.

## 7. Что не взято и почему

Замерены, но отложены — «мм» там означает не одну величину:

| Тип | Товаров | Почему отложен |
| -- | --: | -- |
| `krep-styazhki` | 66 | В одном листе три семантики: у переходников 6 мм — диаметр шланга, у обжимных хомутов «8-13 мм» — диапазон (единого значения нет), у стяжек «100х2,5» — длина × ширина. |
| `str-markery` | 50 | Половина названий — диапазон толщины стержня («1,5-3 мм»), у карандашей «180 мм» — длина. Плюс потребовался бы новый `Attribute`. |
| `napilniki` | 25 | У круглого напильника «4,8 мм» — диаметр, у плоского «200 мм» — длина. Один тип, две оси. |
| `nozhnitsy-ruchnye` | 33 | Ось `length` чистая (≈ 25 из 33), но пять «Насадок на дрель» несут толщину металла, а «d=10мм» — диаметр кабеля. Следующий кандидат после отсечения насадок. |
| `topory` | 15 | «380 мм» — длина рукояти, а у ледоруба-топора «140 мм» — лезвие. |
| `prochaya-osnastka` | 153 | Свалка, разбирать по составу. |
