## 1. Таблица размеров перчаток (`siz-perchatki`) — APPROVED 2026-08-03

Источник: `scratchpad/cat14/gloves-size-normalization.md`, утверждена
владельцем **как есть** (решение 1). Правила по ней заводит окно CAT-14C
(часть B) — они требуют флаг `word_boundary` из CODE-02.

### Буквенные размеры → select `size`

| Вариант в названии | Каноническое значение | slug |
|---|---|---|
| `XS`, `р-р XS` | XS | `xs` |
| `S`, `р-р S`, ` S` на конце | S | `s` |
| `M`, `р-р M` | M | `m` |
| `L`, `р.L`, `р-р L` | L | `l` |
| `XL`, `р-р XL`, `размер XL` | XL | `xl` |
| `XXL`, `р-р XXL` | XXL | `xxl` |
| `XXXL` / `3XL` | XXXL | `xxxl` |

Диапазоны — самостоятельные значения (не разложение):

| Вариант | Каноническое значение | slug |
|---|---|---|
| `S-M`, `р-р S-M` | S–M | `s-m` |
| `L-XL` | L–XL | `l-xl` |

### Числовые размеры → number `size_num`

| Вариант в названии | Каноническое значение |
|---|---|
| `р-р 6` … `р-р 13` | 6 … 13 (число) |

Якорь обязателен: число берётся **только** после `р-р` / `размер` / `р.` —
голые числа в названии не размер.

### НЕ размер (явно исключается)

| Фрагмент | Что это | Пример |
|---|---|---|
| `10 кл`, `10 кл.` | класс вязки | «10 кл.5-ти нитка» |
| `5-нит`, `5-ти нитка`, `10/5-нит` | число нитей | «с ПВХ 10/5-нит» |
| `(10/400)`, `(10/300)` | упаковка пар/короб | «БЕЛЫЕ (10/400)» |
| `КЩС-2`, `87-950`, `87-900` | модель/артикул | «Перчатки КЩС-2» |
| `11279-XL` | размер в **артикуле** — источником не является (только название) | арт. `11279-XL` |

## 3. Решения владельца (accepted / rejected), 2026-08-03

1. **Таблица размеров перчаток — ACCEPTED как есть.** Буквенные S–XXXL,
   диапазоны S–M / L–XL самостоятельными значениями, числовые 6–13 только
   при якоре `р-р` / `размер` / `р.`, явный список «НЕ размер».
2. **Буквенные размеры — ACCEPTED вариант 2: правка движка, opt-in флаг
   `word_boundary: true` на правиле.** Поведение существующих select-правил
   по умолчанию не меняется; используется обкатанная механика границ слова
   из `tool_type.py` (`_keyword_starts_at_word_boundary`, TT-17 / PR #631).
   Периметр — окно CODE-02.
3. **`kind: text` — ACCEPTED, добавить в движок.** Regex возвращает строку,
   значение пишется в `ProductAttributeValue.value_text` (поле и
   `AttributeType.TEXT` уже есть — миграции БД не нужны), остальные
   value-поля обнуляются; normalization/trim; select-options для открытых
   кодов НЕ создавать. Первый потребитель — `zap-shchetki-ugolnye.analog_code`.
   Периметр — окно CODE-02.
4. **`skip_if_regex` — REJECTED (не реализуется).** Вместо кода — замер на
   CAT-14C (часть A3): искать названия с диапазоном резьбы через дефис,
   несколькими парами `Мd×P` и без слов `набор`/`держатель`/`вороток`.
   0 случаев → вопрос закрыт без кода; есть случаи → отдельное решение с
   примерами.
5. **Болты и винты «4х55» — ACCEPTED внутри `krep-bolty`.** Требования к
   regex: `[хx]`, первое число → диаметр, второе → длина, допустимые
   диапазоны метизных размеров, без срабатывания на тройки размеров, только
   в типах крепежа, приоритет точного формата `Мd×L` сохраняется.
   Реализация — CAT-14C (часть A1).

Порядок исполнения (владелец): `CAT-14D → параллельно CODE-02 и CAT-14C →
sandbox → staging apply`. Staging-apply правил, зависящих от
`word_boundary` или `text`, — только после merge и deploy CODE-02.

## 4. Ограничения движка на момент фиксации

- **select матчит голой подстрокой** (`apps/catalog/attribute_extract.py:201`:
  `normalize(kw) in norm`) — без границ слова; keyword «s»/«l» ловит
  латиницу брендов (`STELS`, `ANSELL`). Отсюда — порядок опций (комбо и
  более длинные ключи раньше) и потребность в `word_boundary` (CODE-02).
- **`normalize` сводит только регистр и `ё`→`е`**
  (`apps/catalog/tool_type.py:27-29`). Кириллическая «х» и латинская «x»
  НЕ сводятся — в правилах обязателен класс `[хx]` (конвенция уже соблюдена
  в 13 местах `attribute_rules.json`). Аналогично `[мm]` для буквы «М».
- **kinds на момент фиксации: `select` / `number` / `boolean`.**
  `text` появится в CODE-02. `number` — regex с группой → Decimal
  (значения вида «13-102» невыразимы).
- **`skip_if`** — список подстрок (стемов), матчится той же подстрокой после
  `normalize`; срабатывание = правило не применяется целиком.
- **Приоритет паттернов**: движок берёт первый сработавший regex / первую
  совпавшую опцию — точные паттерны и комбо-опции ставятся первыми.

## 5. Критерии приёмки CAT-14C

Окно CAT-14C обязано предъявить (по промпту
`scratchpad/phase8/prompts/cat-14c-rules-coverage-prompt.md`):

1. **Coverage до/после** для каждого затронутого типа — на выборке и на
   популяции, сопоставлено с CAT-14A (`scratchpad/cat14/cat-14a-coverage.json`).
2. **Замер по вопросу 4** (отклонённый `skip_if_regex`): число реальных
   совпадений формата «диапазон резьбы через дефис + несколько пар `Мd×P`
   + без `набор`/`держатель`/`вороток`», по каждому — `product_id`,
   название, какой атрибут и значение были бы ошибочно извлечены. Явная
   фиксация «0 совпадений, вопрос закрыт без кода» при нуле.
3. **Dry-run без записи в БД**: staging — только чтение (SELECT через
   `manage.py shell`), скрипты без write-вызовов; `load_attributes` /
   `enrich_attributes` в боевом режиме не запускаются (глобальный guard:
   перед записью обязательны dry-run + sandbox-репетиция).
4. Правила части B (`size` перчаток с `word_boundary`, `analog_code` с
   `kind: text`) — отдельным коммитом, валидация после rebase на CODE-02;
   **непроходящие тесты в ветку не коммитить**.
5. `pytest apps/catalog/test_attribute_extract.py` зелёный; полный
   `pytest apps/catalog` на своей БД, база сравнения — прогон CAT-14D
   (1304 passed, 1 skipped); JSON валиден; `ruff` / `black -l 100` чисто.
