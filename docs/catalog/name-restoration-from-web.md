# Восстановление обрезанных названий по внешним источникам

6 164 позиции приехали из 1С с наименованием, обрезанным ровно по 50 символов
(489 из них на остатках). Хвост потерян **в самой учётной системе** — разбор в
DRF-1604: доля обрезанных падает с 25,9 % у кодов 0–5 000 до 2,3 % у кодов
30 000+, то есть реквизит «Наименование» когда-то был ограничен полусотней
символов. Ни наш импорт (режет по 512), ни API обмена (проверено живым запросом)
к потере отношения не имеют.

Значит восстановить имя можно только снаружи: по артикулу найти карточку
производителя, дистрибьютора или магазина и дописать потерянный хвост.

## Что именно делаем

**Дописываем хвост, а не заменяем название.** «Стяжка груза 6м, 2т STAYER
"PROFESSIONAL" для креп» → «…для крепления груза», а не «Ремень STAYER
PROFESSIONAL для крепления груза 35мм 2000кг 6м» из чужого магазина. Структура
названия в каталоге своя, и менять её целиком под чужую выдачу незачем.

## Порядок

1. **Найти источник по артикулу.** Приоритет: сайт производителя → официальный
   дистрибьютор → специализированный магазин. Маркетплейсы годятся только для
   подтверждения, их карточки часто переписаны продавцами.
2. **Убедиться, что это та самая позиция.** Совпасть должен артикул, а не
   похожее название: у одного бренда «GLI 14,4 V-LI» и «GLI 18 V-LI» отличаются
   одной цифрой и живут под общим кодом.
3. **Записать в файл** — CSV с колонками `product_id,name,evidence_url,confidence`.
   Ссылка обязательна: без неё предложение проверить нечем, и команда его
   отклонит.
4. **Применить:**

```bash
catalog_restore_names --file var/names.csv            # dry-run по умолчанию
catalog_restore_names --file var/names.csv --commit
```

## Что делает команда

Пишет через `provenance.apply_sourced_value` с `source="web"`, то есть:

* сверяет baseline — если имя успели поправить руками после подготовки файла,
  вернётся `conflict`, а не молчаливая перезапись;
* уважает приоритет источников: ручное имя (`manual`, приоритет 100) веб-находка
  (25) не затирает;
* проставляет `content_field_sources['name'] = 'web'`, `content_source`,
  `content_confidence` — по ним потом видно, откуда взялось название;
* отклоняет предложения с `confidence < 0.7`: восстановленное имя видит
  покупатель, и «примерно похоже» здесь не годится.

`original_name` не трогается никогда — там остаётся то, что прислала 1С.

Повторная правка того же имени блокируется приоритетом (равный источник не
перезаписывает равный). Если нашли лучшее название — `--allow-equal`.

## Чего делать нельзя

* **Додумывать хвост без источника.** «Домкрат 2 т гидравлический подкатной
  T30, 135-330» может кончаться и «мм», и «мм, кейс» — угадывание тут создаёт
  правдоподобную ложь в карточке товара.
* **Брать характеристики из чужой карточки.** Мы восстанавливаем название, а не
  наполняем описание: для характеристик есть отдельный контур
  (`enrich_attributes`, `apps/ai/sourcing`).
* **Возвращать обрезанную строку 1С поверх найденной.**
  `normalize_product_names --restore-truncated` такие позиции пропускает —
  проверяет `content_field_sources['name'] == 'web'`.
