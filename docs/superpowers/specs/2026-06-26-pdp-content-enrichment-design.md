# Дизайн: наполнение карточки товара контентом (демо)

**Дата:** 2026-06-26
**Ветка:** claude/pdp-enrich-content
**Статус:** дизайн на ревью

## Контекст

Карточка товара (PDP) доведена (кусок A, влит в `dev`), но в дампе у большинства
товаров пусто: нет описания, фото, мало характеристик. Задача — наполнить **одну**
карточку реальным контентом из интернета, чтобы карточку можно было показать «как
живую»: несколько фото, характеристики, описание, видео.

Товар: **Домкрат KRAFTOOL 2т, slug `00015935`** (id=32, категория «Домкраты»). Сейчас:
описание пустое, 0 фото, 3 характеристики.

По правилам проекта **сайт — мастер контента** (названия, характеристики, фото,
описания), поэтому наполнение через БД/команду — корректный канал (не через 1С).

## Цель

На карточке `00015935` на dev-витрине отображаются: галерея из нескольких фото,
расширенный список характеристик, текстовое описание, блок видео (YouTube).

## Объём

**Входит:**
1. Поле `Product.video_url` + миграция + вывод видео на PDP (переиспользуемая фича).
2. Идемпотентная management-команда `catalog_enrich_product` (наполнение товара из JSON).
3. Контент для `00015935` (JSON): описание, характеристики, ссылки на фото, видео —
   собранный из открытых источников.

**Не входит / ограничения:**
- Фото с чужих сайтов — **только для локального демо** (авторские права); в прод
  такие медиа складывать нельзя. Команда и поле `video_url` — переиспользуемые;
  конкретный демо-контент (фото/описание домкрата) — локальные данные, в `dev`/прод
  без отдельного решения **не мержим** (мержим только `video_url` + фронт-вывод).
- Фасеты (`CategoryAttribute`) под новые атрибуты **не создаём** — характеристики
  карточки берутся из всех `ProductAttributeValue`, фасеты нужны лишь для фильтров;
  не трогаем фасетный кэш категории.
- Наполняем **один** товар.

## Решения по развилкам

- **Видео** — добавляем поле `video_url` (а не текст в описании): «видео» будет
  по-настоящему, с встраиваемым плеером.
- **Характеристики** — `get_or_create` `Attribute` по мере (если под спарсенную
  характеристику нет атрибута — создаём), затем `ProductAttributeValue`.

## Архитектура

### 1. Видео: модель + фронт (переиспользуемое)

- **`apps/catalog/models.py`**: в `Product` добавить
  `video_url = models.URLField(_("Видео (URL)"), blank=True)`. Миграция `000X_product_video_url`.
- **API**: `ProductDetailSerializer` добавляет поле `video_url` в выдачу detail-эндпоинта.
- **Фронт**:
  - `lib/types.ts` — `ProductDetail.videoUrl?: string`.
  - `lib/adapters.ts` — маппинг `video_url` → `videoUrl` в `fetchProductFromApi`.
  - Новый клиентский компонент `components/product/ProductVideo.tsx` — принимает URL
    YouTube, рендерит адаптивный `<iframe>` (embed). Невалидный/пустой URL → ничего
    не рендерит.
  - `app/product/[slug]/page.tsx` — секция «Видео» с `ProductVideo`, если `videoUrl` задан.

### 2. Команда наполнения `catalog_enrich_product`

`apps/catalog/management/commands/catalog_enrich_product.py`:
- Аргументы: `slug` (обязательный), `--json <path>` (файл контента), `--images-dir <path>`
  (каталог с заранее скачанными фото, чтобы не зависеть от сети контейнера).
- JSON-формат:
  ```json
  {
    "description": "…", "short_description": "…", "video_url": "https://www.youtube.com/watch?v=…",
    "images": ["img1.jpg", "img2.jpg"],
    "attributes": [
      {"name": "Грузоподъёмность", "unit": "т", "type": "decimal", "value": "2"},
      {"name": "Высота подхвата", "unit": "мм", "type": "integer", "value": "158"},
      {"name": "Тип", "type": "text", "value": "бутылочный гидравлический"}
    ]
  }
  ```
- Логика (в транзакции, идемпотентно):
  - Найти `Product` по slug (нет → ошибка `CommandError`).
  - Установить `description`/`short_description`/`video_url` (перезапись — команда
    отвечает за контент товара).
  - **Фото:** для каждого файла из `images` создать `ProductImage`, если такого ещё
    нет (дедуп по имени файла/порядку — повторный запуск не плодит дубли). Файл
    читается из `--images-dir` и сохраняется в `ImageField` (`media/products/`).
  - **Характеристики:** для каждого `attributes[]`:
    - `Attribute` — `get_or_create` по `slug` (из `name`), задать `name`/`unit`/
      `attribute_type`.
    - `ProductAttributeValue` — `update_or_create` по (product, attribute); значение
      в нужное типизированное поле (`value_text`/`value_integer`/`value_decimal`).
  - Лог: сколько фото/атрибутов добавлено/обновлено.

### 3. Сбор контента (исполнителем, web-инструменты)

Через web-поиск/фетч найти по KRAFTOOL 2т (сверить с названием товара) на открытых
источниках: описание, ТТХ, 3–5 URL фото, 1 обзорное видео (YouTube). Фото скачать
в `--images-dir` (curl), остальное — в JSON. Это входные данные для команды.

## Поток данных

Ресёрч (web) → `content.json` + скачанные фото в каталоге → `catalog_enrich_product
00015935 --json content.json --images-dir <dir>` → БД (`Product`, `ProductImage`,
`Attribute`, `ProductAttributeValue`) → detail-API отдаёт description/images/specs/
video_url → PDP-витрина рендерит галерею/характеристики/описание/видео.

## Обработка ошибок

- Нет товара по slug → `CommandError`.
- Отсутствует файл фото из списка → предупреждение, пропуск этого фото (не падать).
- Невалидный тип атрибута → `CommandError` (явная ошибка данных).
- Пустой/битый `video_url` на фронте → `ProductVideo` ничего не рендерит.
- Команда идемпотентна: повторный запуск не создаёт дублей фото/значений.

## Тестирование

- **Бэкенд (pytest-django):**
  - миграция `video_url` применяется; `ProductDetailSerializer` отдаёт `video_url`.
  - команда: создаёт описание/видео/атрибуты/фото для тест-товара; повторный запуск
    идемпотентен (кол-во фото/значений не растёт); `get_or_create` атрибута не плодит
    дубли; несуществующий slug → `CommandError`.
- **Фронт:** `tsc --noEmit` 0, `eslint` 0; `ProductVideo` рендерит iframe при валидном
  URL и ничего при пустом (проверка типами/линтом — тест-раннера во фронте нет).
- **Ручная проверка:** карточка `00015935` на dev-витрине — фото-галерея + лайтбокс,
  характеристики, описание, видео-секция.

## Этапы (для плана)

1. Поле `video_url` (модель + миграция + сериализатор) + тесты.
2. Фронт-видео (`ProductVideo` + типы/адаптер + интеграция в page.tsx).
3. Команда `catalog_enrich_product` (+ тесты, идемпотентность).
4. Сбор контента KRAFTOOL 2т (web) → JSON + фото.
5. Прогон команды на `00015935` + ручная проверка карточки.
