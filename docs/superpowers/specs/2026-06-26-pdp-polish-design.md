# Дизайн: доводка карточки товара (PDP) — кусок A

**Дата:** 2026-06-26
**Ветка:** claude/amazing-ptolemy-itpz0j
**Статус:** дизайн на ревью

## Контекст

Карточка товара (`frontend/app/product/[slug]/page.tsx`, коммит #242) структурно
готова: галерея, цена, наличие, бейджи, CTA, характеристики, описание, блок
совместимости. Задача — навести порядок и наладить недостающий функционал.

Объём разбит на два независимых куска:
- **A (этот спек)** — фронтовая доводка PDP + минимальный бэкенд приёма заявок.
- **B (отдельный эпик, позже)** — отзывы и рейтинг (фуллстек, за флагом
  `reviews_enabled`). В данный спек **не входит**.

Данные staging залиты локально (47 225 товаров, 254 категории) — доводка ведётся
на реальных данных.

## Входит в A

1. **Блок покупки:** выбор количества, sticky-панель при скролле, обработка
   состояния `order` («Под заказ»), реальные заявки «Запросить цену» /
   «Уточнить поступление» (фуллстек).
2. **Галерея:** зум/лайтбокс, клавиатура + свайп, ленивая загрузка/размеры.
3. **Контент/SEO/a11y:** Product JSON-LD + BreadcrumbList, адаптив и доступность,
   сворачивание длинных характеристик/описания, шеринг.

## Не входит (out of scope)

- Отзывы и рейтинг (кусок B).
- Избранное (вынесено в отдельную задачу; в A только шеринг).
- Синхронизация чего-либо с аккаунтом пользователя.

## Решения по развилкам

- **Модель заявок** размещается в **новом приложении `apps/leads`** (чистая
  граница, растёт под будущий CRM).
- **Шеринг** — Web Share API с фолбэком на копирование ссылки (фронт-онли).

## Архитектура

Изолированные юниты, каждый со своей зоной ответственности и интерфейсом.

### Фронтенд (Next.js, `frontend/`)

> Внимание: в этом репозитории Next.js с breaking changes — перед правкой читать
> релевантный гайд в `node_modules/next/dist/docs/` (см. `frontend/AGENTS.md`).

**Блок покупки** (клиентские острова):
- `QuantityStepper` — счётчик −/+ и числовой ввод, кламп `1..stockQty`
  (если `stockQty` неизвестен — верхней границы нет). Контролируемый компонент.
  Вход: `value`, `max?`, `onChange`. Не знает про корзину.
- `OrderCta` (расширение существующего) — прокидывает выбранное количество в
  `add(productId, qty)`; добавляет ветку `stock === "order"` → «Под заказ»
  (реальное добавление в корзину как для `in`, текст отличается). Сохраняет
  существующие фазы idle/loading/added/error и `data-event`-атрибуты.
- `InquiryDialog` — модалка заявки для сценариев без прямой покупки
  (`price_request` при отсутствии цены, `restock_notify` при `stock==="out"`).
  Поля: телефон (обязателен, валидация формата RU), имя (опц.), сообщение (опц.).
  Сабмит → BFF `/api/inquiry`. Состояния: idle/submitting/success/error.
  Фокус-трап, закрытие по Esc/overlay, `aria-modal`.
- `StickyBuyBar` — липкая панель (цена + основная кнопка), появляется, когда
  основной блок покупки ушёл из вьюпорта (IntersectionObserver по якорю).
  На мобиле — фиксирована снизу; на десктопе — сверху/сбоку. Переиспользует
  `OrderCta`/`QuantityStepper`, без дублирования логики.

**Галерея** (`ProductGallery` апгрейд + новый `Lightbox`):
- Миниатюры: roving tabindex, навигация стрелками ←/→, `aria-current`.
- Главное фото: свайп влево/вправо на тач-устройствах (переключение `active`).
- `Lightbox` — клик по главному фото → фуллскрин-оверлей с перелистыванием
  (стрелки/свайп), закрытие по Esc/клику вне, фокус-трап, блок скролла body.
- `next/image`: первому фото `priority`, остальным — lazy; корректные `sizes`
  под две колонки/мобайл; фиксированный aspect-ratio → нет CLS.

**Контент/SEO/a11y:**
- `ProductJsonLd` — серверный компонент, рендерит `<script type="application/ld+json">`
  с `Product` (name, brand, image[], description, sku/mpn при наличии),
  `Offers` (price `final`, priceCurrency RUB, availability по `stock`) и
  отдельный `BreadcrumbList` из тех же крошек, что в UI. Без цены — `Offers`
  опускается или `availability`-only.
- `Collapsible` — обёртка «Показать всё»/«Свернуть» для характеристик (> N строк,
  N задаётся, дефолт 8) и описания (> M символов). Доступная кнопка-тоггл
  (`aria-expanded`, `aria-controls`).
- `ShareButton` — Web Share API (`navigator.share`), фолбэк — копирование URL в
  буфер с тостом «Ссылка скопирована».
- a11y-проход всей страницы (порядок заголовков h1→h2, фокус-менеджмент модалки
  и лайтбокса, контраст, лейблы) — финальный аудит агентом `accessibility-auditor`.

**Данные/типы:** существующий `ProductDetail` (`lib/types.ts`) уже содержит всё
нужное для A (images, price, stock, stockQty, specs, description, breadcrumb,
brand). Поля `rating?`/`reviews?` в A **не используются** (это кусок B).

### Бэкенд (Django, новое приложение `apps/leads`)

- **Модель `ProductInquiry`** (наследует `core.TimeStampedModel`):
  - `kind` — choices `price_request` | `restock_notify`.
  - `product` — FK на `catalog.Product` (`on_delete=PROTECT`, `related_name="inquiries"`).
  - `phone` — строка (нормализуется), `name` — опц., `message` — опц. (TextField).
  - `status` — choices `new` | `processed` (дефолт `new`), для модерации.
  - `created`/`modified` — из TimeStampedModel.
- **API** (DRF, под `/api/leads/`): один create-only вьюсет/вью
  `POST /api/leads/inquiries/`. Без auth, **throttled** (anti-spam, scoped rate).
  Сериализатор валидирует `phone` и `kind`; `product` по id. Ответ `201` с
  минимумом полей (id, kind, status). Ошибки валидации `400`.
- **Уведомление:** при создании издаётся доменное событие (`apps/core/events.py`,
  через `transaction.on_commit`) → подписчик шлёт уведомление (email/Telegram —
  по доступным каналам; если каналов нет, событие просто логируется). Канал
  уведомления — за `external_integrations`/eventbus-флагом, не блокирует создание.
- **Админка:** `ProductInquiry` в списке с фильтром по `kind`/`status`, поиск по
  телефону, действие «отметить обработанной».
- **Регистрация:** `apps/leads` в `INSTALLED_APPS`, urls подключены в
  `config/urls.py` под `api/`. Миграция `0001_initial`.

### BFF (Next.js, `frontend/app/api/`)

- `POST /api/inquiry` — тонкий прокси на Django `/api/leads/inquiries/`
  (паттерн как у `app/api/orders/route.ts`): принимает тело формы, валидирует
  минимум, форвардит на `INTERNAL_API_BASE_URL`, возвращает статус/ошибки клиенту.

## Поток данных

1. **Покупка в наличии:** `QuantityStepper` → `OrderCta` → `useCart().add(id, qty)`
   → существующий BFF `/api/cart/items` → Django. (Изменение: проброс `qty`.)
2. **Заявка (нет цены / нет в наличии):** кнопка → `InquiryDialog` → `POST /api/inquiry`
   (BFF) → Django `POST /api/leads/inquiries/` → `ProductInquiry` + событие →
   уведомление. Клиент показывает success/error.
3. **Sticky:** IntersectionObserver следит за якорем основного блока; вне вьюпорта
   → показать `StickyBuyBar`.

## Обработка ошибок

- Корзина: существующая модель фаз (loading/added/error) сохраняется.
- Заявка: ошибки сети/валидации → состояние `error` в модалке с возможностью
  повтора; не закрывать модалку при ошибке.
- Бэкенд: невалидный `phone`/`kind`/`product` → `400` с понятным сообщением;
  несуществующий товар → `400`/`404`. Throttle-превышение → `429`.
- Сбой канала уведомления **не** валит создание заявки (заявка уже сохранена).

## Тестирование

- **Бэкенд (pytest-django, TDD):** модель/валидация сериализатора (телефон, kind),
  создание `201`, throttle `429`, эмиссия события `on_commit`, админ-действие.
- **Фронтенд:** юнит на `QuantityStepper` (кламп, −/+), логика `OrderCta` с qty.
  По возможности — компонентный тест `InquiryDialog` (валидация/сабмит,
  замоканный fetch).
- **a11y:** прогон `accessibility-auditor` по итоговой странице (фокус, роли,
  контраст).
- **Регрессия:** существующие тесты PDP/корзины зелёные.

## Доступность (a11y)

- Модалка и лайтбокс: фокус-трап, возврат фокуса, Esc, `aria-modal`/роль.
- Галерея: клавиатура по миниатюрам, `aria-current`.
- Крошки: уже `aria-label`; добавить семантику текущего узла.
- Контраст и порядок заголовков — финальный аудит.

## Этапы реализации (для плана)

1. Бэкенд `apps/leads` (модель + API + админ + событие + тесты).
2. BFF-роут `/api/inquiry`.
3. Блок покупки (QuantityStepper, OrderCta qty/order, InquiryDialog, StickyBuyBar).
4. Галерея (клавиатура/свайп/lightbox/lazy).
5. Контент/SEO (JsonLd, Collapsible, Share).
6. a11y-аудит + регрессия + полировка.
