## 1. Цель

Заменить демо-страницу `frontend/app/page.tsx` (сейчас — витрина состояний
`ProductCard`) на полноценную главную страницу из макета: 7 блоков с анимациями
(параллакс, reveal-on-scroll, hover). Перебрать общую шапку под макет. Подключить
форму консультации к доменной системе заявок (leads), расширив её на общий тип
«консультация» без привязки к товару.

Объём согласован: **полная вёрстка + анимации сразу**, данные категорий/товаров —
из реального API каталога, тексты/статистика/ассеты — конфиг.

## 3. Архитектура (frontend)

`app/page.tsx` — Server Component: тянет данные на сервере и компонует блоки.
Анимации навешиваются client-островками (минимум клиентского кода; основная
разметка — SSR).

```
app/page.tsx                       // SSR-композиция блоков + загрузка данных
components/home/Hero.tsx            // client — параллакс 5 слоёв
components/home/CategoryGrid.tsx    // server-обёртка + client-плитки (hover)
components/home/TrustBadges.tsx     // reveal-on-scroll
components/home/Bestsellers.tsx     // client — карусель + reveal
components/home/ConsultBlock.tsx    // параллакс-фон + кнопка модалки
components/home/AboutStats.tsx      // параллакс + count-up
components/home/InquiryModal.tsx    // client — форма консультации → /api/inquiry
components/motion/Reveal.tsx        // обёртка whileInView (fade-up, once)

lib/home-content.ts                // конфиг: тексты, статистика, маппинг slug→ассет, ссылки (MAX, телефон, промо)
```

часть продукта; карточка покрыта компонентом и используется в каталоге).

## 5. Анимации (framer-motion)

Добавляем зависимость `motion` (текущий неймспейс framer-motion). Анимированные
блоки — client-компоненты. **Обязательно** уважаем `prefers-reduced-motion`: при
нём параллакс/count-up/stagger отключаются, остаётся статичный фолбэк.

- **Hero — параллакс 5 слоёв.** `useScroll` + `useTransform`: слои (фон → дальний →
  средний → объект → текст/CTA) сдвигаются по Y с разной скоростью. Ассеты слоёв —
  в `public/home/hero/` (пока плейсхолдеры/заглушки; финальную графику добавит
  дизайнер). Текст/CTA — самый «быстрый» слой, всегда читаемы (тёмный градиент-оверлей
  под текстом для контраста).
- **Категории — hover.** Подсветка рамки `--accent`, лёгкий зум фото/иконки,
  всплытие подписи (CSS/Tailwind + `whileHover`). Появление сетки — stagger reveal.
- **Доверие / Хиты / О магазине — reveal-on-scroll.** Общая обёртка `<Reveal>`
  (`whileInView`, `viewport={{ once: true, margin }}`): fade-up. Хиты — stagger.
- **О магазине — count-up.** Счётчики анимируются от 0 до значения при появлении.
- **Консультация + О магазине — параллакс-фон.** Фон двигается медленнее контента.
- **Карусель «Хиты»** — CSS scroll-snap + кнопки-стрелки (`scrollBy`) + точки-индикаторы.
  Без тяжёлого слайдер-пакета.

Производительность: анимируем только `transform`/`opacity` (GPU), `will-change`
точечно, `viewport once`; framer-motion грузится только для анимированных блоков;
изображения — через `next/image` (lazy, размеры).

## 6. Форма консультации + расширение leads (backend)

CTA «Получить консультацию» (hero) и «Подобрать инструмент» (блок консультации)
открывают `InquiryModal` — единую модалку.

### Frontend

- **Поля:** имя, телефон (обяз.), опц. сообщение/задача. Клиентская валидация
  (телефон — формат, имя — непустое); переиспользуем `lib/validation.ts` при совпадении.
- **Отправка:** `POST /api/inquiry` (существующий BFF-прокси → Django
  `/api/leads/inquiries/`).
- **Состояния:** idle → submitting (disabled + спиннер, блок повторной отправки) →
  success (благодарность, автозакрытие) / error (текст + повтор).
- **A11y:** focus-trap, закрытие по Esc/оверлею, `role="dialog"` + `aria-modal`,
  возврат фокуса на кнопку-инициатор. Нативная модалка (не браузерный `alert/confirm`).
- **MAX:** «Консультация в MAX» — внешняя ссылка (`target="_blank" rel="noopener"`)
  на URL из `home-content.ts`, без формы.

### Backend (расширение `apps/leads`)

Текущая модель `ProductInquiry` требует **обязательный** `product` (FK, `PROTECT`)
и поддерживает только `kind ∈ {price_request, restock_notify}`. Общую консультацию
без товара она не принимает. Расширяем единую систему заявок:

- `InquiryKind.CONSULTATION = "consultation"` (новый вид).
- `ProductInquiry.product` → `null=True, blank=True` (+ миграция). Для существующих
  видов (`price_request`, `restock_notify`) товар по-прежнему обязателен — проверка
  переносится в сериализатор/use-case (валидация на уровне `kind`).
- `ProductInquirySerializer`: `product` опционален; правило «product обязателен, если
  kind ≠ consultation; запрещён/необязателен для consultation».
- `create_inquiry(...)` и подписчик-уведомление о новой заявке корректно работают
  при `product=None` (в уведомлении — без названия товара).
- Админка заявок отображает консультации (product может быть пустым).

## 7. Адаптив, доступность, ошибки

- **Адаптив (mobile-first, sm/md/lg).** Hero: на мобиле слои упрощаются. Категории:
  6 плиток → 2–3 колонки. Хиты: горизонтальная карусель. Топ-бар/меню → бургер.
- **Доступность.** `prefers-reduced-motion` отключает движение. Контраст текста на
  тёмном фоне и поверх фото (градиент-оверлей). Один `<h1>` (hero), секции `<section>`
  с заголовками. Клавиатура: модалка, стрелки карусели, все CTA фокусируемы; видимый
  `:focus-visible` уже в `globals.css`.
- **Деградация данных.** Категории/хиты тянутся на сервере. При недоступности API
  блок деградирует мягко (скрыт/скелетон) и **не роняет всю страницу** (в отличие от
  PLP, где ошибка → `error.tsx`). Кириллица в текстах/ошибках — корректная.
