# Stock-aware semantic audit каталога (v2, по остаткам)

- Статус: **черновик-исследование** (read-only, данные не меняются)
- Источник: `data/catalog_fixed.json` (поля `name`, `stock`, `is_active`, `sku`,
  `source_group`). Группы 1С (`source_group`) — **не используются как структура**,
  только как слабый сигнал. Классификация — по **смыслу названия**.
- Метод: частотный анализ названий (Метод 2) → первый словарь-классификатор
  доменов (Метод 1). LLM (Метод 3) — отложен на хвост и атрибуты.

## 5. Спорные/ambiguous (medium confidence — на ручную проверку)

- `набор` — набор чего (бит/ключей/инструмента)? решать по второму слову.
- `насадка`, `патрон`, `адаптер`, `переходник` — оснастка vs ручной vs питание.
- `компрессор` — автомобильный / поршневой (пневмо) / строительный.
- `шланг`, `лента`, `пистолет`, `мешок` — мульти-домен.
- `съёмник` — ручной vs авто.

Low confidence (`цилиндр`, `комплект`, `опора`, `элемент`) — без авто-переноса.

## 6. Следующие шаги

1. **Продуктивизировать** в команду `catalog_semantic_classify` (read-only,
   `--only-in-stock --dry-run`) + словарь `data/product_type_rules.json`:
   на каждый товар — `domain / product_type / confidence / reason`, отчёты
   summary + per-item CSV + review-needed.
2. Добить словарь по хвосту (§4) до ≥90% и разметить ambiguous (§5).
3. От доменов (§3) спроектировать **подтипы** (product_type) и целевое дерево v2.
4. Пилот по ядру: **Оснастка + Ручной инструмент + Электроинструмент** (по
   коммерческой ценности остатков), не по старой 1С-категории.
5. Нулевые остатки — отдельный backlog-контур (классифицировать позже, не лочить,
   не строить по ним меню/SEO).

> Принципы (из обсуждения, к фиксации в `catalog-taxonomy-v2.md`): группы 1С —
> не авторитет; бренд/питание/диаметр — не категории; глубина ≤2; аксессуары —
> свои разделы; перенос только dry-run→review→commit; `category_is_manual` —
> только после уверенной классификации.
