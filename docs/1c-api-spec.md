# Интеграция 1С 7.7 → API сайта «Профессионал». Задание для разработчика 1С

Документ описывает, **как 1С должна отправлять данные на сайт**: формат JSON,
авторизацию, контракты эндпоинтов, форматы значений, интервалы и обработку ошибок.

> Направление обмена: **1С сама вызывает HTTP API сайта** (push). Сайт ничего не
> забирает из 1С напрямую.

---

## 1. Общие правила

| Параметр | Значение |
|---|---|
| Базовый URL (прод) | `https://proff58.ru/api/1c/` |
| Базовый URL (тест) | `https://dev.proff58.ru/api/1c/` |
| Метод | `POST` (кроме `GET`: `orders/new`, `sync/<batch_uid>`) |
| Content-Type | `application/json` |
| Кодировка | строго **UTF-8** |
| Тело запроса | конверт `{ "items": [ ... ] }`, массив **не пустой** |
| Числа | строкой или числом; разделитель дробной части — точка `.` **или** запятая `,` (сайт нормализует); разряды можно без пробелов |
| Булево | `true/false`, либо `1/0`, либо `"да"/"нет"` |

Все эндпоинты принимают **пакет строк** (`items`), а не по одной — слать данные
батчами (рекомендация по размеру — в разделе 6).

---

## 2. Авторизация (токен)

Каждый запрос обязан содержать HTTP-заголовок:

```
X-Api-Key: <ТОКЕН>
```

- Токен — общий секрет, выдаётся отдельно (свой для прода и для теста).
- Сверяется на стороне сайта за константное время.
- Нет заголовка / неверный токен → **HTTP 403** (тело: `{"detail": "..."}`), запрос
  не обрабатывается.

Токен передаётся вне этого документа (через защищённый канал). В коде/логах 1С
его хранить как защищённую константу, не светить в открытом виде.

---

## 3. Идентификация товара (ключи связи)

Сайт связывает строку 1С со своим товаром по идентификаторам. В каждой строке
**обязателен минимум один** из:

| Поле в JSON | Что это | Роль |
|---|---|---|
| `external_id` | внутренний код/GUID номенклатуры 1С | **главный** ключ (уникальный) |
| `code_1c` | синоним `external_id` | то же |
| `sku` | артикул товара | запасной ключ |
| `article` | синоним `sku` | то же |

Правила:
- Сопоставление идёт **сначала по `external_id`/`code_1c`**, затем по `sku`/`article`.
- **`external_id` должен быть стабильным и уникальным** на товар (не меняться между
  выгрузками). Это критично — по нему сайт находит товар при каждом обновлении.
- Артикул **не обязан быть уникальным**. Если по артикулу (без кода) подходит
  несколько товаров — строка считается **конфликтом**, ничего не обновляется,
  она уходит в ручной разбор (см. поле `errors` в ответе).
- Рекомендация: **всегда присылать `external_id`** — он снимает неоднозначность.

---

## 4. Что чем управляет (важно!)

Сайт — продающая система, 1С — учётная. Поэтому сайт **берёт из 1С только**:

- цену, остаток;
- базовые поля: исходное название, бренд (если на сайте пусто), штрихкод,
  единицу измерения, активность, исходную группу.

Сайт **никогда не перезаписывает из 1С**: категорию каталога, витринное название,
описание, SEO, фото, опубликованность. Это ведут на сайте вручную.

Практический вывод для 1С: можно смело слать обновления цен/остатков сколько
угодно часто — контент сайта от этого не пострадает.

## 5. Контракты эндпоинтов

### 5.1 `POST /products/import` — загрузка/обновление номенклатуры

Создаёт новые товары и обновляет существующие. Используется для первичной
выгрузки и периодической полной/частичной синхронизации номенклатуры.

**Поля строки** (обязателен только идентификатор):

| Поле | Тип | Прим. |
|---|---|---|
| `external_id` / `code_1c` | строка | главный ключ |
| `sku` / `article` | строка | артикул |
| `name` | строка | наименование из 1С |
| `brand` | строка | бренд |
| `barcode` | строка | штрихкод |
| `unit` | строка | ед. изм. |
| `source_group` | строка | группа товара в 1С (справочно) |
| `is_active` | булево | активность в 1С |
| `price` | число (2 знака) | цена |
| `old_price` | число (2 знака) | старая цена (для скидки) |
| `currency` | строка | напр. `RUB` |
| `price_type` | строка | тип цены, по умолчанию `retail` |
| `stock` | число (3 знака) | остаток |

**Пример запроса:**

```json
POST /api/1c/products/import
X-Api-Key: <ТОКЕН>
Content-Type: application/json

{
  "items": [
    {
      "external_id": "1c-000123",
      "sku": "BOSCH-GSB13RE",
      "barcode": "4600000000017",
      "name": "Дрель ударная BOSCH GSB 13 RE",
      "brand": "Bosch",
      "unit": "шт",
      "source_group": "Электроинструмент/Дрели",
      "is_active": true,
      "price": "5900.00",
      "old_price": "6500.00",
      "currency": "RUB",
      "price_type": "retail",
      "stock": "7"
    }
  ]
}
```

> **Импорт асинхронный.** Запрос ставится в фоновую обработку, поэтому ответ —
> **`202 Accepted`** + `batch_uid` (см. 5.3). Реального результата (создано/обновлено)
> в этом ответе нет — его нужно **опросить** по `batch_uid`.

### 5.2 `POST /products/update` — обновление существующих

То же тело, что и `products/import`, **но новые товары НЕ создаются**. Если товара
по идентификатору нет — строка попадает в `skipped` (пропущена). Использовать,
когда нужно только обновить уже заведённые товары, не плодя новые.
Тоже **асинхронный**: ответ `202` + `batch_uid`, результат — опросом.

### 5.3 Асинхронный импорт: `202` и опрос статуса `GET /sync/<batch_uid>`

`products/import` и `products/update` обрабатываются в фоне (могут быть большими
и долгими). Поток:

```
1С → POST products/import → 202 { "batch_uid": "...", "status": "accepted", "accepted": N }
1С → GET  /api/1c/sync/<batch_uid>  (опрашивать каждые 5–15 с, пока finished=false)
        → { "status": "ok|partial|error", "finished": true, "created":.., "errors":.., ... }
```

`GET /api/1c/sync/<batch_uid>` (заголовок `X-Api-Key`) — ответ:

```json
{
  "batch_uid": "0f3c1e54-...",
  "status": "running | ok | partial | error",
  "finished": true,
  "rows_total": 100, "rows_ok": 98, "rows_error": 2,
  "created": 30, "updated": 68, "skipped": 0, "uncategorized": 5, "errors": 2,
  "finished_at": "2026-06-16T08:55:00Z",
  "error_details": "1c-000777: Неоднозначный артикул ..."
}
```

- `status=running`, `finished=false` — ещё обрабатывается, опросить позже.
- `finished=true` — готово; `status` = `ok` (без ошибок) / `partial` (часть строк
  не принята) / `error` (прогон упал целиком).
- неизвестный `batch_uid` → `404`.

> `batch_uid` — это ID **прогона на сайте**, который выдаёт сайт. Не путать с
> внутренним кодом товара 1С (`external_id`/`code_1c`) и с возможным кодом
> выгрузки/пакета 1С (его сейчас не принимаем).

### 5.4 `POST /prices/update` — только цены

**Поля строки:**

| Поле | Тип | Прим. |
|---|---|---|
| идентификатор | строка | `external_id`/`code_1c`/`sku`/`article` |
| `price` | число (2 знака) | **обязательно** |
| `old_price` | число (2 знака) | опционально |
| `currency` | строка | по умолч. `RUB` |
| `price_type` | строка | по умолч. `retail`; разные типы (`retail`/`wholesale`/…) живут независимо |

```json
POST /api/1c/prices/update
{
  "items": [
    { "external_id": "1c-000123", "price": "5900.00", "old_price": "6500.00", "currency": "RUB", "price_type": "retail" },
    { "external_id": "1c-000123", "price": "5400.00", "price_type": "wholesale" }
  ]
}
```

### 5.5 `POST /stocks/update` — только остатки

**Поля строки:**

| Поле | Тип | Прим. |
|---|---|---|
| идентификатор | строка | обязателен |
| `stock` | число (3 знака) | физический остаток |
| `reserved` | число (3 знака) | резерв |
| `available_stock` | число (3 знака) | доступно к продаже; если не прислать — считается как `stock − reserved` |
| `warehouse` | строка | код/название склада, по умолч. `main` |

```json
POST /api/1c/stocks/update
{
  "items": [
    { "external_id": "1c-000123", "stock": "7", "reserved": "2", "available_stock": "5", "warehouse": "main" }
  ]
}
```

### 5.6 Заказы (этап M4 — пока заглушки)

| Эндпоинт | Метод | Назначение |
|---|---|---|
| `/orders/new` | `GET` | 1С забирает новые заказы с сайта |
| `/orders/confirm` | `POST` | 1С подтверждает приём заказа/резерв/ошибку |

Сейчас оба возвращают **HTTP 501** — контракт зафиксирован, реализация позже.
Их форматы выдадим отдельным дополнением к этому ТЗ перед этапом заказов.

## 6. Ответы и обработка ошибок

Два режима ответа:

- **Асинхронные** `products/import` и `products/update` → **`202 Accepted`**
  `{ "batch_uid": ..., "status": "accepted", "accepted": N }`. Итог — опросом
  `GET /sync/<batch_uid>` (см. 5.3).
- **Синхронные** `prices/update` и `stocks/update` → **`200 OK`** со сводкой прогона
  сразу (та же структура счётчиков):

```json
{
  "created": 0,
  "updated": 3,
  "skipped": 0,
  "uncategorized": 0,
  "errors": 0,
  "batch_uid": "0f3c1e54-9b2a-4f0e-8a1c-7c2d9b1f3a44"
}
```

| Поле | Значение |
|---|---|
| `created` | создано новых товаров (для `products/import`) |
| `updated` | обновлено существующих / применено цен-остатков |
| `skipped` | пропущено (нет товара при update-only; нет цены/остатка в строке) |
| `uncategorized` | создано без категории (ушли в «Неразобранные» на сайте) |
| `errors` | строк с ошибкой/конфликтом — разобрать по `batch_uid` в админке сайта |
| `batch_uid` | идентификатор прогона; назвать его при разборе проблем |

Те же счётчики для импорта приходят в ответе `GET /sync/<batch_uid>` после `finished=true`.

**Важно:** HTTP 200 с `errors > 0` означает, что часть строк не принята (битый
формат, конфликт артикула и т.п.). Остальные строки при этом обработаны. Причины
каждой ошибки сайт сохраняет у себя (журнал по `batch_uid`).

### Коды ошибок

| Код | Когда | Действие 1С |
|---|---|---|
| `400` | неверный формат тела (нет `items`, пустой массив, нет идентификатора, кривой тип) | исправить payload, не повторять «как есть» |
| `403` | нет/неверный `X-Api-Key` | проверить токен |
| `501` | `orders/*` (пока не реализовано) | не использовать до выхода M4 |
| `5xx` / таймаут / сеть | временная проблема сайта | **повторить с экспоненциальной задержкой** (см. ниже) |

### Ретраи

- На `5xx`/таймаут/сетевую ошибку — повтор: 2с, 4с, 8с, 16с (до 4–5 попыток).
- Повторная отправка одних и тех же строк **безопасна**: обмен идемпотентен —
  товар матчится по `external_id` и обновляется, дубли не создаются.
- На `400`/`403` ретраить бессмысленно — это ошибка данных/доступа.

## 7. Форматы значений

- **Числа:** `"5900.00"`, `"5900,00"`, `5900` — все валидны. Дробные у цены — 2
  знака, у остатка — 3 знака.
- **Булево:** `true`/`false`, `1`/`0`, `"да"`/`"нет"`.
- **Пустые поля:** можно не присылать вовсе (а не пустой строкой) — так понятнее.
- **Кодировка:** только UTF-8. Если выгрузка формируется в CSV/Windows-1251 на
  стороне 1С — перекодировать в UTF-8 перед отправкой по API (API принимает JSON
  в UTF-8).

## 8. Размеры пакетов и интервалы запросов

### Размер пакета
- Рекомендуемый размер `items` в одном запросе — **до 500–1000 строк**.
- **Жёсткий лимит** — `ONEC_MAX_ITEMS` (по умолчанию 1000): больше строк → ответ
  `400` (запрос не принимается). Большую номенклатуру слать **частями**.

### Рекомендуемые интервалы (push из 1С по расписанию)

| Операция | Частота | Комментарий |
|---|---|---|
| `prices/update` | каждые **5–15 мин** или по факту изменения | цены — самое «живое» |
| `stocks/update` | каждые **5–15 мин** или по факту изменения | остатки меняются часто |
| `products/update` | **1–4 раза в сутки** | базовые поля меняются редко |
| `products/import` | **раз в сутки (ночью)** + по запросу | полная/большая выгрузка номенклатуры |
| `sync/<batch_uid>` | каждые **5–15 с** после import/update | опрос статуса, пока `finished=false` |
| `orders/new` (M4) | каждые **1–5 мин** | когда заказы будут включены |

Не слать всё одновременно в один момент — разнести по времени, чтобы не создавать
пиковую нагрузку.

## 9. Тестовый контур

- Сначала всё отлаживается на **тесте**: `https://dev.proff58.ru/api/1c/` с
  **тестовым токеном** и тестовыми данными.
- После приёмки на тесте — переключение на прод `https://proff58.ru/api/1c/` с
  боевым токеном.
- Для проверки достаточно отправить 1–2 товара в `products/import`, затем
  `prices/update` и `stocks/update` по тем же `external_id`, и сверить ответы
  (`created`/`updated`) и наличие товара в админке сайта.

## 10. Чек-лист для разработчика 1С

- [ ] Заголовок `X-Api-Key` во всех запросах.
- [ ] Тело — `{"items": [...]}`, UTF-8, непустой массив.
- [ ] У каждой строки стабильный уникальный `external_id`.
- [ ] Числа — с точкой/запятой, цена 2 знака, остаток 3 знака.
- [ ] Батчи ≤ 500–1000 строк, большие выгрузки — частями.
- [ ] Расписание: цены/остатки часто, номенклатура — реже.
- [ ] Ретраи на `5xx`/таймаут с экспоненциальной задержкой; на `400`/`403` — нет.
- [ ] Разбор `errors`/`batch_uid` при ненулевых ошибках.
- [ ] Сначала тест-контур, потом прод.
