# Оплата: АТОЛ Pay Ecom

Действующая касса витрины. ЮKassa-код остаётся в репозитории рабочим, но по
умолчанию не используется (`PAYMENT_PROVIDER=atolpay`).

Реквизиты мерчанта: ИП Шатров Алексей Григорьевич, ИНН 582902253600 (КПП у ИП нет
и в запросы не передаётся). СНО — УСН «доходы минус расходы», ставка — **без НДС**
(так настроил бухгалтер на вкладке «Чеки» боевого ЛК; код передаёт ставку в каждой
позиции явно и перекрывает ЛК — значения в `.env` обязаны совпадать с ЛК). Оплата
одностадийная (`oneStep`), B2B оплачивает по счёту и онлайн-кассу не использует.

Банки: в песочнице — Альфа-Банк, в боевом ЛК — Т-Банк (карта, T-Pay) и Сбербанк
(СБП). Банк берётся из настроек ЛК, в запросах не передаётся.

## 1. Как это работает

```
checkout / кнопка «Оплатить»
   └─ POST /api/payments/orders/{номер}/        (гость — с ?t=<access_token>)
        └─ POST {ATOLPAY_BASE_URL}/payments     amount в копейках + чек 54-ФЗ
             ← paymentUrl → покупатель уходит на форму кассы
касса
   └─ POST /api/payments/webhook/atolpay/?t=<ATOLPAY_CALLBACK_TOKEN>
        └─ GET {ATOLPAY_BASE_URL}/payments/{orderId}/status   ← состояние берём отсюда
             └─ payment_succeeded + order_paid → резерв подтверждён, 1С получает заказ
```

Два места, где легко ошибиться:

- **Подписи у callback нет.** Тело уведомления — только сигнал «сходи посмотри».
  Заказ помечается оплаченным исключительно по ответу `/status`, а сам вход закрыт
  секретом в query. Пустой `ATOLPAY_CALLBACK_TOKEN` = вход закрыт полностью (403),
  а не «пускаем всех».
- **Чек обязан сойтись с суммой платежа до копейки**, иначе касса отвечает
  `INVALID_RECEIPT_AMOUNT` и платёж не регистрируется. Сборка — в
  `apps/payments/atolpay/receipt.py`: промо-скидки разносятся по позициям,
  неделимая цена разбивается на две строки, доставка идёт отдельной позицией
  (признак «услуга»).

Номер заказа у нас начинается с кириллической «П» — касса такой `orderId` не
принимает, поэтому у платежа свой ASCII-идентификатор (`P-20260907-ABC123`), а
повторная попытка оплаты получает суффикс (`…-2`): тот же `orderId` касса второй
раз не примет (`PAYMENT_EXISTS`).

## 2. Переменные окружения

| Переменная | Значение |
|---|---|
| `PAYMENTS_ENABLED` | `True` только когда касса настроена (в проде по умолчанию `False`) |
| `PAYMENT_PROVIDER` | `atolpay` |
| `SITE_URL` | публичный https-адрес витрины — из него строятся `returnUrl` и `notificationUrl` |
| `ATOLPAY_BASE_URL` | прод `https://new-api-mobile.atolpay.ru/v1/ecom`, песочница `https://croc-sandbox-api-mobile.atolpay.ru/v1/ecom` |
| `ATOLPAY_TOKEN` | токен из ЛК (Настройки → API Токены); уходит как `Authorization: Bearer <token>` — документация АТОЛ пишет «без схемы», но касса на это отвечает 403 |
| `ATOLPAY_CALLBACK_TOKEN` | наш секрет для callback (любая случайная строка) |
| `ATOLPAY_SNO` | система налогообложения: `2` УСН доход-расход (наше), `0` общая, `1` УСН доход, `4` ЕСХН, `5` патент |
| `ATOLPAY_VAT_CODE` | код ставки НДС по справочнику кассы: `5` — без НДС (наше), `10` — 22%, `0` — 20% |
| `ATOLPAY_RECEIPT_ENABLED` | `True`; `False` отключает чек (только для отладки) |

## 3. Настройка личного кабинета

1. **Песочница**: ЛК АТОЛ Pay → «Перейти в sandbox» (https://croc-sandbox-lk.atolpay.ru/),
   вход через АТОЛ ID.
2. **Токен**: Настройки → API Токены → сгенерировать. Показывается один раз —
   сразу в `.env` сервера, не в git.
3. **Настройки заказов → Оплата**: банк для карты — Т-Банк, СБП — Сбер (после
   подключения), название магазина, обратный url — адрес витрины.
4. **Настройки заказов → Коллбеки**: можно оставить пустыми — адрес уведомлений
   мы передаём в каждом платеже (`additionalProps.notificationUrl`), и он имеет
   приоритет над настройками ЛК.
5. **Провайдер чеков**: ЛК АТОЛ Онлайн → Мои компании → Настройки интегратора →
   скачать файл → загрузить во вкладке «Провайдер чеков» (ФФД 1.05). Затем вкладка
   «Чеки» — параметры по умолчанию.
6. **СБП**: оплатить счёт АТОЛ + заявление в СберБизнес (Эквайринг → СБП QR-code,
   1 устройство, время 00:00–00:00, сумму указывает клиент) → полученный **ID
   устройства** передать в АТОЛ.

Адрес для callback (его же указывать в поддержку при разборе проблем):

```
https://<домен>/api/payments/webhook/atolpay/?t=<ATOLPAY_CALLBACK_TOKEN>
```

## 4. Проверка настройки

```bash
# Справочники кассы: коды предметов расчёта, ставок НДС, единиц измерения.
# Числовых кодов в документации нет — они берутся отсюда. Снимок от 11.09.2026:
# НДС 22% = 10, 20% = 0, 10% = 1, 0% = 4, без НДС = 5; СНО: 0 общая, 1/2 УСН, 5 патент.
docker compose exec web python manage.py atolpay_check --dictionaries

# Как выглядит чек конкретного заказа (локально, в кассу ничего не уходит).
docker compose exec web python manage.py atolpay_check --receipt П-20260907-ABC123

# Что касса думает о платеже.
docker compose exec web python manage.py atolpay_check --status P-20260907-ABC123
```

Регистрация платежа с чеком в песочнице проверена 11.09.2026 (заказ с неделимой
ценой 333.34×3 + доставка: касса приняла позиции 333.33×2 + 333.35 + 350.00 и
выдала `paymentUrl`).

Полный цикл в песочнице пройден 11.09.2026 на стенде dev.proff58.ru: оплата с
чеком, отказ банка и повтор тем же заказом, автоотмена неоплаченного, возврат из
ЛК кассы — всё дошло до заказа через callback.

Прогон в песочнице: оформить заказ с онлайн-оплатой → оплатить тестовой картой
(карты Альфы: https://alfabank.ru/sme/payservice/internet-acquiring/docs/connection-options/api/test-cards)
→ убедиться, что заказ перешёл в «Оплачен», а в платеже заполнились `receipt_id` и
`receipt_status = success` (админка → Платежи).

## 5. Что делать, когда что-то пошло не так

| Симптом | Причина и действие |
|---|---|
| Ручка оплаты отвечает 503 `payments_disabled` | `PAYMENTS_ENABLED=False` |
| 503 `provider_unavailable` | нет токена, касса недоступна или чек не сошёлся — смотреть `logs/payments.log` |
| `PAYMENT_SETTINGS_NOT_FOUND` | в ЛК не выбраны методы оплаты (Настройки → Настройки заказов → Оплата) |
| `INVALID_RECEIPT_AMOUNT` | расхождение позиций и суммы заказа — воспроизводится локально через `atolpay_check --receipt` |
| Callback приходит, заказ не оплачен | секрет в `notificationUrl` не совпадает с `ATOLPAY_CALLBACK_TOKEN` (в логе «callback с неверным секретом») |
| `receipt_status = fail` | деньги приняты, чек не пробит — фискализировать вручную, транзакция остаётся действительной |

Неоплаченные заказы гасит janitor `apps/payments/expiry.py`: перед отменой он
спрашивает кассу напрямую, и если та говорит «оплачено», отмена не выполняется.
