# ADR-0007a: 15-й top-level раздел витрины — «Насосы и водоснабжение»

- Статус: Proposed / Draft. Не применяется без отдельного approval, PR/мержа и отдельного
  gate на изменения БД.
- Дата: 2026-07-02
- Тип: addendum к [ADR-0007](ADR-0007-catalog-hierarchy-ownership.md) (дерево категорий
  мастерится на сайте). Не изменяет ADR-0007, а фиксирует одно конкретное решение по
  форме дерева в рамках его правил.
- Связано: ADR-0001 (`tool_type` — атрибут, а не узел дерева),
  `docs/plans/catalog-taxonomy-redesign.md`, backlog каталога (память проекта,
  пункт «Электроинструмент / Насосы»).

## Контекст

В ходе characterization-round раздела «Электроинструмент» (корень id=3) разобран
хвост из 645 товаров без `tool_type`. Крупнейший однородный блок — **насосы и
оборудование водоснабжения**, которые ошибочно лежат в «Электроинструменте» и не
имеют дома в текущей v2-таксономии.

Read-only разведка на стенде (SELECT-пробы, без изменения БД) дала согласованную рабочую
карту насосного хвоста (данные 1С могут дрейфовать, поэтому цифры — рабочий срез):

- **water universe в id=3 (untyped): 202 товара / 46 published.**
- После отсева непрофиля будущий раздел ≈ **189 товаров / ≈44 published**.
- **FP (не водоснабжение): 10** — исключаются из раздела.
- **HOLD (ручное решение): 3** — не включаются автоматически.
- **EAV пуст (`ATTR_UNIQUE=0`)** на всех 202 — структурированных характеристик нет.

Насос — инженерное оборудование водоснабжения (свой покупательский сценарий, свои
фильтры и высокочастотные коммерческие запросы: «купить насос», «дренажный насос»,
«насосная станция», «циркуляционный насос для отопления»). Ни один существующий
v2-раздел его семантически не вмещает.

## Решение

1. **После принятия этого addendum добавить 15-й top-level раздел витрины** в v2-дерево:
   - **Название:** «Насосы и водоснабжение».
   - **Slug:** `nasosy-vodosnabzhenie`.
   - **Место:** отдельный раздел верхнего уровня (не подраздел «Силовой»).

2. **Внутренняя структура — 9 подтипов** (ось `tool_type`, ADR-0001; узлами дерева
   подтипы не делаем):

   | Подтип | total / published (карта 2026-07-02) |
   |---|---|
   | Насосы дренажные и фекальные | ~59 / ~20 |
   | Насосы циркуляционные | ~33 / ~1 |
   | Насосы поверхностные | ~30 / ~5 |
   | Насосы скважинные | ~28 / ~8 |
   | Насосы вибрационные | 23 / 6 |
   | Насосные станции | 9 / 4 |
   | Автоматика для насосов | 6 / 0 |
   | Комплектующие для насосов | ~1 / 0 |
   | Мотопомпы | 0 / 0 (в текущем хвосте пусто; подтип заводим на будущее) |

3. **Что входит:** мотопомпы (не в «Силовую»), автоматика/управление насосами
   (реле давления, станции управления/защиты, преобразователи частоты, пульты),
   комплектующие/ЗИП, циркуляционные, насосные станции — всё в этот раздел.

4. **Что НЕ входит (FP 10 шт — не маршрутизировать в насосный раздел автоматически):**
   - ножные насосы (5) → авто/накачка;
   - НШ-гидронасосы (2) → гидравлика/спецтехника;
   - молочный насос + ремкомплект (2) → сельхоз/пищевое;
   - насос ДС-134 (1) → дорожное/битумное.

   Будущие адреса выше — **ориентировочные**, не обязательный route в рамках этого ADR
   (конкретная маршрутизация FP — отдельные решения/round-ы).

5. **HOLD — ручное решение (3, не маршрутизировать автоматически):** насос для
   опрессовки; плунжерный насос для АВД (мойки высокого давления); всасывающий
   насос DP72-ST-DC/AC с блоком питания.

## Долг: EAV / фасеты

У насосного хвоста **нет ни одной характеристики в EAV** — фасеты придётся
проектировать и наполнять отдельным enrich-объёмом. Плановый набор фасетов
(фильтры + SEO-лендинги):

- тип насоса (подтип), назначение (чистая/грязная вода, отопление, скважина, полив);
- производительность (л/мин · м³/ч), напор (м), глубина погружения/всасывания (м);
- мощность (Вт), Ø скважины (дюйм/мм), забор воды (верхний/нижний — для вибрационных);
- бренд (⚠️ поле `brand` на хвосте пустое — проставить в round-е).

## Миграционный порядок (по правилам ADR-0007, без «зеркала 1С»)

1. ✅ Read-only детализация — завершена (эта карта).
2. Этот addendum ADR-0007a (документ).
3. Создание раздела `nasosy-vodosnabzhenie` в дереве `Category` — **отдельный data-change
   шаг после approval**. Сам этот ADR раздел НЕ создаёт и данные НЕ меняет.
4. Словари типизации `product_type_rules` для 9 подтипов; типизация через
   `catalog_semantic_classify` — **сначала типизация, потом маршрутизация**, НЕ regex
   по именам.
5. Round маршрутизации ~189 товаров (по образцу hoztovary): dry-run → показ владельцу →
   `pg_dump` → отдельный ОК на `--commit` → post-audit.
6. Отдельным заходом — проектирование и наполнение фасетов (EAV-долг).

Каждый шаг 3–6 — только по отдельному ОК владельца; БД/словари в рамках этого ADR не
меняются.

## Последствия

- v2-таксономия расширяется с 14 до 15 top-level разделов; бизнес-логика и URL
  привязываются к `slug` (`nasosy-vodosnabzhenie`), не к русскому label (ADR-0007 §66).
- Насосы уходят из «Электроинструмента», что уменьшает его untyped-хвост и убирает
  семантический шум из PLP/фасетов инструмента.
- Появляется отдельный SEO-кластер под насосные запросы (лендинги по подтипам).
- Раздел заводится «пустым по характеристикам» — до наполнения фасетов фильтрация
  ограничена; это осознанный поэтапный подход.

## Альтернативы (отклонены)

- **Насосы → «Силовая».** Отклонено: семантический промах (насос — водоснабжение, а
  не источник энергии), несовместимые фасеты, потеря SEO-кластера под насосные запросы.
- **Насосы остаются в «Электроинструменте».** Отклонено: чужой блок засоряет фасеты и
  навигацию инструмента, нет профильных фильтров, слабый SEO.
- **Первоклассный подраздел вместо раздела.** Рассмотрено как компромисс без правки
  ADR; отклонено в пользу полноценного раздела из-за объёма (~189) и коммерческой
  ценности (насосы — самостоятельная товарная категория с отдельным покупательским
  интентом, фасетами и SEO-семантикой).
