# ADR-0007: Дерево категорий мастерится на сайте; 1С — отдельный слой маппинга

- Статус: принято
- Дата: 2026-06-24
- Связано: ADR-0001 (tool_type — атрибут, не категория), ADR-0002 (`on_site`/скрытый
  корень), `docs/ARCHITECTURE.md`, `docs/plans/catalog-taxonomy-redesign.md`,
  `docs/1c-api-spec.md` §4

## Контекст

Публичная иерархия каталога — критический путь (catalog-first) и фундамент SEO,
PLP-фильтров, навигации и хлебных крошек. Структура 1С (группы справочника
номенклатуры) грязная, неполная и неудобная для витрины: смешанные группы
(«Буры, коронки, биты, пилки и полотна»), служебные ветки («яяПриход»,
«Прочее»), деление по питанию, узлы-бренды («Запчасти Hitachi»).

Существовал риск трактовки: «иерархия сайта = выгрузка групп из 1С». Это связало
бы витрину с чужой грязной структурой, сделало бы SEO/URL нестабильными и
заблокировало бы ручное управление каталогом. Нужно зафиксировать обратное правило.

## Решение

1. **Дерево категорий — мастер на стороне сайта.** Источник истины структуры —
   модель `Category` (django-treebeard, БД), редактируемая в админке
   (`CategoryAdmin(TreeAdmin)`: создать / переименовать / переместить / скрыть /
   править slug и SEO / привязать фасеты). 1С структуру **не диктует**.

2. **1С влияет только на наполнение, через отдельный настраиваемый слой маппинга.**
   Связь — односторонняя: 1С кладёт товары в *уже существующие* категории. Маршрут
   «признак 1С → категория» задаётся:
   - `Category.external_id_1c` — справочный код группы (для разового бутстрапа);
   - `CategoryMappingRule` — правила авторазбора (по артикулу / слову в названии /
     бренду / группе 1С → целевая категория), управляемые в админке.
   `data/group_mapping.json` — **разовый seed** стартового дерева
   (`build_categories`), а не runtime-зависимость.

3. **Импорт 1С никогда не перетирает структуру и ручные категории.**
   `product_writer` обновляет только данные 1С (цена/остаток/бренд-если-пусто/…) и
   не трогает `category`, витринное название, описание, SEO, фото, slug. Ручное
   назначение категории фиксируется флагом `Product.category_is_manual=True` —
   после этого авторазбор/переимпорт товар не перевешивает.

4. **Грязь и служебные группы 1С** не попадают в публичное дерево: помечаются
   `on_site=false` и живут под скрытым корнем (ADR-0002).

5. **Типы инструмента (Перфораторы, УШМ, …) — ось `tool_type`** (ADR-0001), а не
   узлы дерева. Дерево остаётся стройным; типы — вторая ось навигации/SEO.

## Гарантии для пользователя/менеджера

- Иерархию можно править в админке в любой момент, без участия 1С и без релиза.
- Переразбор/повторная выгрузка 1С не меняет дерево и не сбрасывает ручные
  категории (защита — `category_is_manual`; подсказки об этом — в админке
  категорий, товаров и правил маппинга).
- Массовая перепривязка товаров — действие «Перепривязать выбранные товары в
  категорию» в списке товаров (фиксирует `category_is_manual`).

## Последствия

- `group_mapping.json` после go-live используется как воспроизводимый seed/конфиг
  для staging→prod, а не как «живая» структура; маршрутизация новых групп — через
  `CategoryMappingRule` в админке.
- Редизайн таксономии (`docs/plans/catalog-taxonomy-redesign.md`) — это изменение
  *данных/формы* (перемещение узлов, фасеты, slug+redirect), а не моделей: схема
  уже поддерживает произвольное админ-редактируемое дерево.
- Бизнес-логика привязывается к `slug`/`code`/`id` категории, не к русскому label.

## Альтернативы (отклонены)

- **Иерархия = зеркало групп 1С.** Отклонено: грязь/нестабильность/SEO-дубли,
  потеря ручного контроля, блок переиспользования движка под другой магазин.
- **Жёсткий маппинг только в JSON-файле.** Отклонено как единственный путь: правки
  требовали бы релиза; для маршрутизации оставлен админ-управляемый
  `CategoryMappingRule`, JSON — лишь seed.
