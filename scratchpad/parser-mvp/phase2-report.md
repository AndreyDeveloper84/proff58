## 4. Обоснование расположения `parser/` и ключевых решений

- **`parser/` — автономный пакет вне Django** (роадмап §4): донор характеристик
  не имеет права трогать БД и код `apps/`; запись в каталог — отдельная
  management-команда Phase 4 (`catalog_import_scraped`, с `--dry-run`).
  Поэтому схемы (`schemas.py`), HTTP-клиент (`client.py`), сбор URL
  (`category.py`), извлечение (`product.py`) и CLI (`main.py`) живут в
  корневом `parser/` со своими тестами на fixtures (без сети).
- **Дефолтные маски категорий**: у sitemap-источников (resanta, vihr,
  interskol) `--category-url` — маска-подстрока для фильтрации `<loc>`
  sitemap'а; у zubr — URL страницы листинга. У Интерскола дефолт сужен до
  `product/perforator`: широкая маска `perforator` захватывала новости
  (`/news/…`) и категорийные страницы (`/catalog/…`). У resanta/vihr та же
  проблема вылечена при приёмке сужением маски до `perforator-` — см. §8.
- **`category.source_url` = sitemap** у sitemap-источников: маска — не URL,
  поэтому в `Export.category.source_url` пишется URL sitemap'а (валидный
  абсолютный URL по схеме); у zubr — сам URL листинга.
- **`--source all`**: один прогон по всем четырём источникам с общим клиентом
  (общий троттлинг/кэш/журнал) — приёмочный сценарий Phase 2; файлы пишутся
  по каждому источнику отдельно, при `AccessDeniedError` обход останавливается,
  частичные результаты сохраняются.

### Фикс-волна ревью режима B (8 тестов)

- `run_limit` считает **только карточки** через `start_card_phase()`:
  запросы фазы сбора (sitemap/листинг) лимит не едят —
  `test_browser_client.py::test_collect_phase_requests_do_not_eat_card_limit`
  (регрессия Critical 1), `test_main.py::test_browser_run_limit_counts_only_cards`;
  заодно переработан `test_run_limit_stops_run` (явный `start_card_phase()`);
- **плановый лимит → exit 0**: `BrowserRunLimitError` не наследует
  `AccessDeniedError`, штатная остановка по лимиту не докладывается как
  «доступ запрещён» — `test_run_limit_error_is_not_access_denied`,
  `test_main.py::test_browser_run_limit_is_planned_stop_exit_0`;
- **в кэш пишется только 200** (как в режиме A) —
  `test_error_status_not_cached[404]`, `test_error_status_not_cached[500]`
  (Important 2);
- **robots — после проверки лимита**: при исчерпанном лимите лишний запрос
  за robots.txt не уходит — `test_robots_not_fetched_after_limit_exhausted`
  (Important 3).
