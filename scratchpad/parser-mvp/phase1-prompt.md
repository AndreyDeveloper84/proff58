## РЕЖИМ ДОСТУПА — обязателен

Мы гость на чужом сайте:
- соблюдать `robots.txt` каждого источника (у всех четырёх полного запрета нет);
- **не чаще 1 запроса в 2–3 секунды на домен**, никаких параллельных потоков на хост;
- честный `User-Agent` с контактом, не маскировка под браузер ради обхода;
- скачанное кэшировать в fixtures и повторно не запрашивать;
- всего за разведку — десятки запросов, не сотни. Если источник начнёт отвечать
  429/403 — **остановиться и доложить**, не подбирать обходы.

## ГРАНИЦЫ

- **Read-only.** Ничего не писать в БД, каталог не трогать. К товарам — только SELECT.
- **Парсер не писать** — это Phase 2. Здесь только разведка и фиксация структуры.
- Ничего не создавать в `apps/`; скрипты разведки — в `scratchpad/parser-mvp/`.
- Фотографии не скачивать и не разбирать — решение владельца.
- Глобальные команды (`enrich_attributes` без `--path`, `rebuild_attrs_cache`) запрещены;
  отдельный незакрытый блокер — `PLAN_CREATE=40`.
- Staging не трогать. Push и PR — только по явной просьбе владельца.
- Рабочая копия общая: чужие незнакомые изменения не откатывать, `git add` — только
  точечными путями, никогда `git add -A`.
- **Перед любой работой с GitHub** (мерж, пуш, PR) сначала `git fetch gitlab --prune`
  и сверка `origin/dev` с `gitlab/dev` — правило владельца; там работает
  фронтенд-команда, а деплой делает на сервере `git reset --hard`.
