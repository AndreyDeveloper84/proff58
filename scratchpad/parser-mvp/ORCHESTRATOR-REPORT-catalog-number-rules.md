## 2. Что было не так

Все дефекты — один класс: **regex брал число, которое не является характеристикой**.

| Дефект | Пример | Записывалось |
|---|---|---|
| Диапазон | «Набор головок 1/2, 10-32 мм» | `size=32` |
| Диапазон с пробелами | «Ключ трубный 10 - 36 мм» | `size=36` |
| Ступенчатое сверло | «Сверло ступен. 4-12мм» | `diameter=12` |
| Перечисление | «Коронка карбид. 33-53-67-73-83 мм» | `diameter=83` |
| Число зубьев | «Диск пильный 255х30мм **z-100**» | `disc_diameter=100` |
| Зернистость | «Мини-насадки ЗУБР, **Р-180**» | `disc_diameter=180` |
| Длина вместо размера | «Насадка 3/8" HEX 4 **L-50мм**» | `size=50` |
| Класс инструмента как двигатель | «**Щёточный шлифователь** METABO» | `motor_type=Щёточный` |
| Модельная маркировка | «Перфоратор ЗУБР **ЗП-24 Д**» | `energy_impact=24 Дж` |

Практический вред одинаков: это фильтры витрины. Разводной ключ 55–65 мм находился по
«65» и не находился по «55»; пильный диск 255 мм лежал в фильтре «100 мм».

## 3. Что сделано

### 3.1. Правки правил (данные)

- `size` (`golovki`, `klyuchi-gaechnye`): `(?<![\d.,/-])(?<!-\s)(?<!-\s\s)` — диапазон,
  в том числе с пробелами.
- `diameter` (`koronki`, `sverla`): `-` в lookbehind + `(?!\s+ступен)` у свёрл.
- `disc_diameter` (`bolgarki-ushm`, `krugi-almaznye`, `krugi-shlif`): `(?<![\dzр]-)`.
- `motor_type` (`shlifmashiny`): голое «щеточн» → «щеточный двигател» / «щеточный двиг».
- `energy_impact` (`perforatory`): усечённый паттерн требует дробное число.

### 3.2. Изменение движка

`apps/catalog/attribute_extract.py` — у любого правила появилось поле **`skip_if`**:
список стоп-слов, при попадании правило не применяется целиком.

Нужно там, где характеристики в единственном числе не существует: «Набор ключей
6 - 19 мм, 8 шт.» не имеет одного «размера под ключ». В regex не выражается — Python не
поддерживает lookbehind переменной длины. Стоит на 4 правилах:
`["набор", "комплект", "предмет", " шт"]`.

### 3.3. Тесты

**+72 теста** в `apps/catalog/test_attribute_extract.py` (122 → 194 в файле).

Каждая защита проверена **мутацией** — тест обязан падать, если дефект вернуть:

| Мутация | Падений |
|---|---|
| вернуть широкий `energy_impact` | 3 |
| переставить опции `chuck` | 3 |
| вернуть старый lookbehind `size` | 7 |
| добавить «х» в `size` (выровнять по `passatizhi`) | 4 |
| вернуть голое «щеточн» | 4 |
| убрать `skip_if` из словаря | 3 |
| отключить `skip_if` в движке | 4 |
| убрать `(?<!-\s)` | 3 |
| убрать `(?!\s+ступен)` | 1 |
| убрать `(?<![\dzр]-)` | 4 |
| заблокировать любой дефис в `disc_diameter` | 1 |

## 4. Три решения, которые НЕ были очевидны

Их стоит знать до следующей правки — «дочинить по аналогии» здесь ломает данные.

### 4.1. Пары «10х11» у ключей — сохраняем (решение владельца)

Полная починка `size` по конвенции `passatizhi` удалила бы **463** значения
(198 опубликованных) вместо 248. Из них **211** — двусторонние ключи «10х11», где
размер 11 реально существует, и **4** — «14х14», где значение полностью корректно.

Диапазон — это **ложь** (размера нет вообще), пара — **неполнота** (размер есть, просто
не единственный). Удаление лжи делает витрину честнее; удаление неполноты лишает
215 ключей фильтруемости, не давая ничего взамен.

Расхождение с конвенцией осознанное, закрыто тестом `test_size_pair_is_kept_deliberately`.
Полное решение (мультизначение `size=[10,11]` либо `size_min`/`size_max`) — **отдельная
задача, решения нет**.

### 4.2. У `diameter` коронок и свёрл «х» КОНСТРУКТИВНЫЙ

Паттерн `(\d{1,3})\s*[х*x]\s*\d` написан специально, чтобы взять диаметр из
«Коронка 42х10хМ16». Добавление «х» в lookbehind сломало бы правило начисто.

### 4.3. У `voltage` дефис — модельная маркировка, а не диапазон

Все **5** названий с дефисом перед напряжением содержат реальные вольты:
«ЗУБР **ДА-18 В**», «ДИОЛД **ДЭА-12В-04**», «ЗУБР **AB-125- 20В**».
Правка дала бы 1+ ложную потерю и 0 исправлений. **Не трогали**, закрыто якорным тестом.

Аналогично `piki-dolota.length`: группа правила — **второе** число пары «18х400», а
lookbehind стоит перед первым. Блокировка не защищает от диапазона в длине, зато
сломала бы «ЗД-18х400». Кандидатов в каталоге 0. **Не трогали.**

## 5. Методические выводы (важнее самих правок)

### 5.1. Замерять через движок целиком, а не по одному regex

Дважды подряд поверхностная оценка расходилась с реальностью на порядок:

- по 40 «новым» значениям казалось, что правка `size` затронет 40 → реально в БД было
  записано **1594**, полная починка удалила бы 463;
- у `sverla.diameter` я сравнил первый regex из пяти и получил «потеряет 1086 из 1606» →
  реально **55**.

**Правило:** сравнивать `AttributeRules.extract` со старым и новым словарём, потери
раскладывать по причине (диапазон / пара / одиночное) и показывать владельцу **до** записи.

### 5.2. Проверять, что тест падает именно от снятия защиты

Первая версия теста на «6 - 19 мм» проходила и **без** защиты: кейс содержал слово
«набор» и его отсекал `skip_if`. Защита lookbehind оставалась непокрытой. Поймано
мутацией, кейсы переписаны без «набора».

### 5.3. Артефакты гейт-цикла в `/tmp` контейнера не переживают деплой

Между dry-run и write раунда 2 прошёл деплой PR #598, контейнер поднялся заново,
`/tmp` очистился, write упал с `FileNotFoundError`. Обошлось: запись не состоялась
вовсе, состояние согласованное (проверено по последнему `ImportRun` и покрытию).

**Правило:** перед write проверять `docker ps` (нет свежего `Up N seconds`) и наличие
`--path`-каталога; после любого сбоя сначала устанавливать факт, потом повторять; дамп
снимать заново.

### 5.4. Общая тестовая БД даёт дедлоки, читаемые как регрессия

`--reuse-db` + фиксированное имя `test_proff58`: при параллельных прогонах два pytest
дерутся за строки и падают с `deadlock detected`, причём **каждый раз разные тесты**.
Три прогона подряд дали `2 failed` → `2 failed + 2 errors` → `7 failed + 2 errors`.

**Правило:** для полного прогона поднимать свою БД (`DATABASE_URL` с другим именем +
`--create-db`), после — удалять. Признак именно этой проблемы: набор падающих тестов
меняется от прогона к прогону, в изоляции всё зелёное.

### 5.5. Ложная находка P1 из отчёта H4 (закрыта)

«pytest пишет в `data/attribute_rules.json`» — **не воспроизводится**. Полный прогон на
чистом дереве: md5 файла не изменился, `git status` пуст. В репозитории нет кода,
пишущего в этот файл. Наблюдавшийся симптом был собственной незакоммиченной работой
Phase 0.5 (дословно содержимое коммита `10f7453`). Владелец подтвердил и снял пункт.
