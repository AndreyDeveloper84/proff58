## Схема лестницы матчинга

```
┌─────────────────────────────────────────────────────────────┐
│ 1. SKU / артикул                                            │
│    exact match по артикулу карточки → однозначный матч      │
├─────────────────────────────────────────────────────────────┤
│ 2. exact_model                                              │
│    точное совпадение model_key                              │
├─────────────────────────────────────────────────────────────┤
│ 3. normalized_model                                         │
│    совпадение нормализованного model_key                    │
├─────────────────────────────────────────────────────────────┤
│ 4. alias                                                    │
│    совпадение по алиасу модели (суффиксные написания)       │
├─────────────────────────────────────────────────────────────┤
│ 5. ambiguous                                                │
│    несколько равнозначных кандидатов или «многие к одному»  │
└─────────────────────────────────────────────────────────────┘
```

### Точки принятия решения

- **Победа точного SKU над алиасом.** Если карточка разрешается по SKU,
  она не смешивается с карточками, разрешаемыми по alias, и не порождает
  ложную `ambiguous` для точного товара.
- **Разрешение «многие к одному».** Если несколько карточек разной
  степени точности указывают на один товар, сохраняется наиболее точный
  матч (`sku` точнее `exact_model`, тот точнее `normalized_model`,
  тот точнее `alias`). Менее точный матч отбрасывается и, если у него
  не осталось других кандидатов, может перейти в `ambiguous`.
- **Fuzzy без артикула запрещён.** Рекомендации из `fuzzy_suggestions`
  остаются только для ручного разбора; автоматически они не применяются.
- **Конфликт значений.** При расхождении значения атрибута с каталогом
  действие становится `conflict`, независимо от `source_priority`.

## Политика конфликтов

### Правило

Автоматический `overwrite` запрещён. Если scraped-значение атрибута
отличается от значения в каталоге, запись **не производится**.
Карточка попадает в категорию `conflict` отчёта импорта.

### Что видно в отчёте

Каждая запись конфликта содержит:

- `product_id` и наименование товара;
- код атрибута и исходное поле;
- значение в каталоге (`catalog_value`) и его источник (`catalog_source`);
- артикул/SKU стороны каталога (`catalog_article`);
- scraped-значение (`scraped_value`);
- артикул/SKU стороны источника (`scraped_sku`);
- источник данных (`scraped_source`).

### Фактические конфликты в регрессии

#### `perforatory`

```json
{
  "product_id": 44523,
  "product": "Перф.ЗУБР ЗП-26-800 SDS+,800Вт, 3,2Дж, ...",
  "attribute": "energy_impact",
  "field": "Максимальная энергия удара, Дж",
  "catalog_value": "3.2000",
  "catalog_source": "regex",
  "catalog_article": "ЗП-26-800-К",
  "scraped_value": "3.0",
  "scraped_sku": "ЗП-26-800 К",
  "scraped_source": "zubr",
  "raw": "3"
}
```

### Почему `ambiguous` не уменьшилась у дрелей

Хотя лестница разрешила 3 alias-коллизии, одновременно 3 суффиксных
написания из `not_found` стали `ambiguous`, потому что для них нет
SKU-совпадения, но они конфликтуют с точными SKU-матчами других карточек
на тот же товар. Это ожидаемое поведение: угадывание запрещено.
