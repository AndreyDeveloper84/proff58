### 1. Парсер Интерскола

**Причина пустых `attributes` у `Д-10/300ЭР`, `Д-10/350Т`, `Д-10/350ЭР`:**
у этих старых сетевых дрелей Интерскол не inlined характеристики в Next.js RSC-payload,
а опубликовал их в HTML-описании (блок `div.unfolding-list-right`) в формате
`Параметр: значение`.

**Изменения:**
- `parser/product.py` — добавлен fallback `_parse_interskol_description_specs`,
  который, если RSC-свойства не найдены, парсит строки описания, отсекает типовые единицы
  измерения (`об/мин`, `Вт`, `мм` и т.п.) и складывает пары в `attributes`.
- `data/catalog_processing_rules/scraped_attr_map.dreli-shurupoverty.json` — добавлены
  поля для fallback-описания (`Частота вращения на холостом ходу`,
  `Номинальная потребляемая мощность`) и `ignore`-записи для остальных параметров
  из HTML-описания, чтобы сохранить `dropped: 0`.

**Важное ограничение:** для resanta/vihr/zubr в выборке уже есть карточка без суффикса,
которая точно матчится на тот же товар. Если добавить простой алиас для суффиксной версии,
обе карточки свалятся в `многие к одному`, и команда `catalog_import_scraped` уберёт их из
`matched` (текущая логика: несколько карточек → один товар = ambiguous, не в базу).
Поэтому точечные алиасы без доработки правила коллизий **не поднимут** `matched`.

### 6. Вердикт по применению карты

- Новый охват: **26 видимых товаров из 565 (4,6 %)**.
- Карта даст **85 create + 2 confirm + 1 overwrite** = 88 операций с данными.
- `dropped` остаётся **0** — карта предсказуема.
- Всё ещё недостижимо: 30 карточек (50 % выборки) остаются `not_found`, из них
  10 — корзина A, но простые алиасы блокируются правилом «многие к одному»;
  18 — товаров в каталоге нет; 2 — `MODEL_RE` не знает `ЗДМ`.

**Вывод:** применять карту **сейчас не стоит**. Окно apply (гейт-цикл, бэкап,
post-audit) не окупается охватом 4,6 % и 85 значениями. Прежде чем идти в apply,
нужно либо решить матчинг корзины A с учётом коллизий (предпочтение точному
совпадению / дизамбигуация по артикулу), либо расширить выборку источников.

   Остаётся единственным `overwrite`; решение по-прежнему требуется.

3. Нужна ли дизамбигуация `ambiguous` по артикулу/SKU? Это безопаснее fuzzy,
   но затронет общий матчер и потребует повторной проверки регрессии.
