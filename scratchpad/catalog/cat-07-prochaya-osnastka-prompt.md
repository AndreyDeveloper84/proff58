**Главное наблюдение — проверь его первым делом.** Для сотен товаров **категория уже
правильная, а тип — нет**: 137 съёмников лежат в категории «Съёмники», 41 тележка —
в «Тележки и тачки», 65 талей — в «Лебёдки и тали». Дерево знает, что это, а
`tool_type` говорит «прочая оснастка». Если это подтвердится, у разбора появляется
дешёвый и надёжный критерий: **категория как источник истины для типа**, а не разбор
названий регулярками.

## ЗАДАЧА 1 — карта содержимого

Разложить 2039 на **связные кластеры**, по каждому:

- сколько всего и сколько **опубликовано** (опубликованные важнее — их видит покупатель);
- в каких категориях лежат;
- есть ли **уже готовый подходящий тип** в манифесте
  `data/catalog_processing_rules/tool_type_taxonomy.v1.json` (334 опции) — искать
  честно, по значению и синонимам, а не только по slug;
- если типа нет — предложить, но **не заводить**.

Кластеры смотреть глазами по выборке названий, не только по первому слову: «набор»,
«насадка», «головка» — слова-обманки, за ними разное.

## ЗАДАЧА 2 — три класса разбора

Разнести кластеры по стоимости и риску:

1. **Категория уже права** — тип берётся из категории, критерий воспроизводим одним
   запросом, риск минимальный. Это первая очередь.
2. **Нужен разбор названий** — критерий по названию, требует проверки на ложные
   срабатывания.
3. **Действительно прочее** — то, что честно остаётся в `prochaya-osnastka`. Назвать
   объём: сколько из 2039 разбору не поддаётся и почему.

Третий класс так же важен, как первые два: он показывает, где предел.

## ЗАДАЧА 3 — ловушки

Найти и назвать поимённо то, что при разборе легко испортить:

- **`леска` 102 + `яялеска` 88** — это один кластер или разные? Для `bp-leska` (тип
  заведён в TT-07) нужен единый критерий;
- **19 бензокос в `bp-trimmery`** со словом «леска» в характеристиках — их не трогать,
  проверено в TT-08;
- `набор`, `аксессуары`, `комплект` — что переносить, а что нет: набор головок ≠ головка;
- запчасти (`втулка`, `оправка`, `кожух`) — их место в `zapchasti`, а не в оснастке,
  но это уже перенос по дереву, не смена типа.

## ЗАДАЧА 4 — отдельная находка, проверить и доложить

Оркестратор нашёл при замере: **4550 товаров в каталоге имеют название,
начинающееся на `яя`** — служебный сортировочный префикс из 1С. **2547 из них
опубликованы**, то есть покупатель видит на витрине:

```
яяLivi Tag брелок
яяЛеска 3,0ммх240м Nylium Starline Oregon
яяO-RING 322834
```

Нужно (read-only):

- подтвердить цифры своим запросом;
- проверить, попадает ли префикс в **поиск и сортировку** витрины: товар на `яя`
  улетает в конец алфавитного списка и не находится по запросу «леска»;
- выяснить, **перезапишет ли 1С** очищенное название при следующем обмене. По ADR-0007
  обмен не трогает контент сайта — но это надо **подтвердить кодом** `sync_1c`, а не
  принять на веру;
- оценить объём: у скольких товаров после снятия `яя` название станет дублем
  существующего.

**Ничего не чистить в этом окне.** Это вход для отдельной задачи, и массовая правка
2547 видимых названий требует авторизации владельца.

- Контур `tool_type` (манифест, gate, ruleset) не трогать.
- Push и PR — только по явной просьбе владельца.
- **Перед любой работой с GitHub** — сначала `git fetch gitlab --prune` и сверка
  `origin/dev` с `gitlab/dev`.
- Рабочая копия общая: чужие изменения не откатывать.
- Параллельно идут TT-08 (переклассификация гайковёртов и лески) и PARS. TT-08
  забирает лески — **не планировать их дважды**, свериться с его протоколом
  `scratchpad/catalog/tt-08-report.md`.

## ПРИЁМКА

- карта 2039 разложена по кластерам с числом опубликованных;
- по каждому кластеру сказано, есть ли готовый тип в манифесте;
- три класса разбора названы с объёмами, включая честный остаток «прочего»;
- ловушки перечислены поимённо, с критериями отсечения;
- гипотеза «категория уже права» проверена запросом и подтверждена или опровергнута
  цифрами;
- по `яя`: цифры подтверждены, влияние на поиск и сортировку проверено, поведение
  обмена подтверждено **чтением кода** `sync_1c`, объём дублей оценён;
- предложена **первая очередь** разбора — один кластер, который даст покупателю
  больше всего при наименьшем риске, с готовым воспроизводимым критерием;
- протокол `scratchpad/catalog/cat-07-report.md`.
