# CAT-03 · Каталог · переопределение подписи атрибута для категории

## КОНТЕКСТ

CAT-02 довёл характеристики измерительного до витрины: заведено 7 `CategoryAttribute`,
панели фильтров отдаются, счётчики сходятся с БД.

Вскрылась проблема подписи. Атрибут `size` — **глобальный** и делится между ручным
инструментом и измерительным. Его имя — **«Размер «под ключ»»**. Для ключей и головок
это правильно, а на странице **Угольников и линеек** покупатель видит:

```
Размер «под ключ», мм
```

Для угольника это бессмыслица: там `size` — длина стороны. Пер-категорийного
переопределения подписи в модели сейчас нет.

## ЗАДАЧА

Дать возможность переопределять отображаемое имя характеристики **в рамках категории**,
не трогая сам `Attribute` и не плодя дубликаты.

**Предпочтительное решение — поле переопределения в `CategoryAttribute`** (например,
`display_name`, пустое по умолчанию → берётся имя атрибута). Причины: не создаёт новых
атрибутов, не требует миграции данных, не ломает `taxonomy`-контур и правила извлечения.

**Альтернатива — развести `size` на два атрибута** (`size` для ключей, отдельный для
измерительного). Она дороже: миграция значений, правка `attribute_rules.json`, повторный
прогон правил, риск для 1594 существующих значений. **Выбирать её только если
переопределение подписи окажется технически неприемлемым** — и тогда обосновать.

Решение по варианту принять самостоятельно **на основании кода**, но если всплывёт
продуктовый вопрос (например, нужны разные единицы измерения, а не только подпись) —
остановиться и вынести владельцу.

## ОБЪЁМ

1. **Модель**: поле переопределения в `CategoryAttribute` + миграция. Пустое значение —
   поведение как сейчас.
2. **Админка**: поле доступно куратору, с понятной подсказкой, что пусто = имя атрибута.
3. **API фасетов**: отдаёт переопределённую подпись там, где она задана. Проверить, что
   ключ фильтра (`slug`) при этом **не меняется** — иначе поедут сохранённые ссылки.
4. **Фронт**: использует подпись из API; убедиться, что нигде не захардкожено имя.
5. **Применить к угольникам**: `size` → «Размер» (или иная формулировка на твоё
   предложение, вынести в отчёт). Проверить живым запросом, что на странице
   `izmeritelnyy-ugolniki-i-lineyki` подпись изменилась, а на странице ключей осталась
   прежней.
6. **Тесты**: переопределение отдаётся; пустое поле — fallback на имя атрибута; slug
   фильтра не изменился.

## ГРАНИЦЫ

- Значения характеристик и `Attribute` не трогать; новые `Attribute`/`AttributeOption`
  не создавать.
- `attribute_rules.json` не править — подпись к извлечению отношения не имеет.
- Контур `tool_type` (manifest, gate, ruleset) не трогать.
- Глобальные команды (`enrich_attributes` без `--path`, `rebuild_attrs_cache`) запрещены.
- Миграция должна быть обратимой и неразрушающей.
- **Перед любой работой с GitHub** — сначала `git fetch gitlab --prune` и сверка
  `origin/dev` с `gitlab/dev`: фронт живёт там, а правка витрины может пересечься.
- Рабочая копия общая: чужие изменения не откатывать, `git add` точечными путями.
- Push и PR — только по явной просьбе владельца.

## КООРДИНАЦИЯ

Фронтовая часть пересекается с зоной фронтенд-команды (`frontend/`). Перед правкой
свериться с `gitlab/dev`; если там идут изменения тех же компонентов — доложить,
а не разрешать конфликт молча.

## ПРИЁМКА

- подпись переопределяется на уровне категории, пустое значение даёт прежнее поведение;
- **ключ фильтра не изменился** — сохранённые ссылки живы, проверено;
- на угольниках подпись корректная, на ключах прежняя — доказано живыми запросами
  к `dev.proff58.ru`;
- миграция обратима, применена локально и на staging;
- тесты покрывают переопределение и fallback;
- regression без третьего падения, арифметика показана;
- протокол `scratchpad/catalog/cat-03-report.md`.
