## 2. Post-audit: фоновый писатель идентифицирован, моё изменение изолировано

Агрегатные хэши `fp_pav`/`fp_attrs_cache` между «до» и «после» разошлись — вне моего
scope. Расследование (построчные хэши 61059 PAV + 47225 attrs_cache против
восстановленного pre-write дампа):

- изменилось ровно **305 PAV** и **305 attrs_cache**, добавлено/удалено 0;
- все 305 PAV — атрибут **`tool_type`**, источники manual (304) / web (1);
- множество из 305 товаров **1:1 совпадает с rollback-map TT-08**
  (`scratchpad/phase8/artifacts-tt08/rollback-map.json`: 107 gaikoverty +
  6 gaikoverty-ruchnye + 192 bp-leska).

**Вывод:** между моими замерами на staging отработало окно **TT-08**
(переклассификация, санкционированная отдельно). Моё изменение изолировано:
ядро товаров с маской `is_active` стабильно во всех замерах (`91bc884a…`),
PAV/cache вне TT-08-множества — ноль расхождений, мой UPDATE писал только
`is_active`. Пересечений задач по строкам нет (TT-08 не трогает `is_active`,
я не трогаю `tool_type`). Координационный урок: перед write-пунктом сверять не
только ImportRun, но и движение построчных хэшей — TT-08 регистрирует дампы,
не ImportRun.

## 5. Остатки (вне scope)

- 4550−2547 = 2003 яя-товара были неактивны и остались неактивными.
- Поле `original_name` сохраняет префикс — сырое поле для матчинга 1С, на витрину
  не идёт (подтверждено кодом в CAT-07 §4.3).
- Чистка/склейка дублей (59+141 коллизий из CAT-07 §4.4) — не потребовалась:
  товары скрыты, а не переименованы.
- Локальная БД рабочей копии `proff58` не синхронизирована с этой деактивацией —
  обновится следующим дампом со staging (или той же командой при необходимости).
