## 4. Задача 4 — атрибуция 262 значений (169 `length` + 93 `size`, source=regex)

**Ответ: прогон #38 — глобальный `enrich_attributes` 2026-06-29 07:03:36**
(`processed=13049`, `by_attribute: size 1687, length 1693`). Доказательная цепочка:

1. Правила извлечения для `izm-urovni`/`izm-ugolniki` появились в словаре коммитами
   `8fb20c2` и `315320a` от **2026-06-27**. До этого движок для этих типов ничего не
   извлекал — ни один прогон ≤ #37 не мог записать эти значения.
2. Между 2026-06-27 и #38 других прогонов `enrich_attributes` не было
   (#37 за минуту до — `enrich_tool_type`). Следующие прогоны — #40–42 от 2026-07-27,
   scoped (по `size` чистка 1366→1355, `length` отсутствует в `by_attribute`) — роль
   #40–42: только PRUNE по починенным правилам, не запись.
3. Значения в БД совпадают с тем, что извлекает актуальный словарь (зеркало: UPDATE=0) —
   консистентно с записью правилами той же линии.
4. `by_attribute` прогона #38 агрегирует все типы, поэтому 169+93 внутри 1693/1687
   по stats не выделяются — атрибуция по времени и причинности, не по разложению счётчика.

**Пути записи PAV мимо ImportRun не существует** (P1-опасение снято, аудит кода):

- `source=regex` присваивается только в `enrich_attributes`
  (grep `Source.REGEX` по `apps/` — единственное место записи), а команда **всегда**
  создаёт `ImportRun` до транзакции и фиксирует статус/статистику после (id=43 — тому
  свежий пример).
- Остальные писатели PAV: `catalog_enrich_product` (MANUAL), `enrichment.py` (LLM),
  `scraped_import.py` (SCRAPER), `provenance.py` (источник из sourcing-очереди с аудитом
  CatalogChange), `enrich_tool_type`/`tool_type_rollback` (только атрибут `tool_type`).
  Ни один не пишет `regex` и ни один не пишет `length`/`size`.
- У PAV нет `created_at` — прямой датировки нет, атрибуция косвенная, но цепочка
  «правила появились 06-27 → первый прогон 06-29 → значения консистентны» однозначна.
