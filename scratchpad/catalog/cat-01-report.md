## 1. Перемер дельты на staging

Метод — read-only зеркало логики `enrich_attributes` (`scratchpad/catalog/cat-01/mirror_plan.py`),
с актуальным словарём из `dev` (`data/attribute_rules.json`, md5 `525b9a82…`, залит в
контейнер `/tmp/cat01`). UPDATE считается только при **различии** значений (same-value
перезаписи команды обновлением не являются).

**Валидация зеркала на локальной БД** (та же, что у оркестратора): на общем срезе
атрибутов воспроизведены его числа точно — `CREATE` 169+68+17+9 = **263**, `UPDATE` **0**,
`PRUNE` **347**. (Полный локальный CREATE=683 отличается на +420 значений по атрибутам
`tape_length/tape_width/measuring_range/max_distance/…` — в локальной БД нет самих
`Attribute`, поэтому все их значения посчитались новыми; на staging эти атрибуты есть.)

**Замер на staging:**

| | staging | локально (оркестратор) |
|---|---:|---:|
| Товаров с `tool_type` в scope словаря | 13 146 | 12 889 |
| **PLAN_UPDATE** | **0** | 0 |
| PLAN_CREATE | **4** | 263 |
| PLAN_PRUNE | 17 | 347 |

Состав `CREATE=4`: `length|nozhovki` 1, `nozhovka_for|nozhovki` 1, `purpose|pilki-polotna` 1,
`vorotok_type|vorotki` 1 — это **известный хвост** из отчёта rules-fix (§6, «добираются
отдельным scoped-прогоном»), **вне scope CAT-01**. Состав `PRUNE=17`: `diameter` 6,
`size` 11 — следствие того, что задеплоенный на стенде словарь (md5 `df9678b4…`)
старее словаря `dev`; данные под эти правила на staging чистились scoped-прогонами,
не покрывшими эти 17 товаров. Тоже вне scope CAT-01.

**По двум типам CAT-01 на staging: CREATE = 0, UPDATE = 0, PRUNE = 0.**

## 2. Объяснение расхождения: дельта уже на staging

Локальная БД отстаёт от staging — тот же эффект, что оркестратор зафиксировал для
перфораторов, но в полный рост:

| | length · izm-urovni | size · izm-ugolniki |
|---|---:|---:|
| Товаров типа на staging | 253 | 156 |
| PAV на staging | **169** (все `source=regex`) | **93** (все `source=regex`) |
| Из них опубликованных | 118 | 55 |
| PAV в локальной БД | 0 | 25 |
| CREATE в локальном замере | 169 | 68 |

Суммы сходятся: 169 = 0 + 169; 93 = 25 + 68. Каждое значение, которое задача должна
была дозаписать, на staging **уже записано ровно с тем значением, которое извлекает
актуальный словарь** (иначе зеркало показало бы UPDATE).

**Кем и когда записано — установить не удалось.** Последний `ImportRun` на staging —
id=42 от 2026-07-27 (раунд 3 правил); отдельного прогона под эти типы в истории нет.
Версии: (а) значения записаны глобальным `enrich_attributes` 2026-06-29 (run 38,
`length: 1693` по всем типам), если `izm-urovni`/`izm-ugolniki` и их правила уже
существовали; (б) записано без регистрации ImportRun одним из окон. Атрибуция — §7.2.

## 3. Поштучная сверка (обязательная)

Критерий отбора (воспроизводим, cherry-pick нет):

- **size угольников — все 93 значения** (на staging их 93, а не 68: 68 было числом
  *недостающих* локально; проверен весь живой набор, надмножество);
- **length уровней — каждый 4-й по `product_id`** из 169 → **43 значения** (≥ 40).

Листы: `scratchpad/catalog/cat-01/check_size.txt`, `check_length_sample.txt`;
полная выгрузка — `values_staging.json`.

| Набор | Проверено | Верно | Точность |
|---|---:|---:|---:|
| `size` · izm-ugolniki | 93 | 93 | **100%** |
| `length` · izm-urovni (выборка) | 43 | 43 | **100%** |
| **Итого** | **136** | **136** | **100%** |

**Ловушка из промпта не сработала ни разу.** Числа-не-длины в названиях уровней —
количество глазок/ампул/колб («400 мм … 3 глазка», «787 (2 колбы»), гарантия
«10 лет», модельные номера (КАПРО 787/705, art. 99А/96В, Л14, HK2015-02-0800,
SQ1022-0102) — нигде не захвачены; везде взята длина корпуса. У угольников аналогично:
диапазон «0-360°» и точность «0,3°» (11616), зернистость «P120…P320» и «Р 40»
(18398–18411), «11кг на отрыв» (11660), артикул «У-136» (23676), вторые стороны пар
«300х200», «1000х400» — всё отсеяно верно.

Замечание по составу (не по извлечению): в `izm-ugolniki` сидят товары-не-угольники —
сантехнические фитинги (11676, 47007–47010), платформа 34304, кельма 37085, кабельные
бирки 23676/36924, абразивные треугольники (18398–18411). Их `size` извлечён верно
как число из названия; вопрос классификации — к TT-контуру (§7.4).

## 4. Гейт-цикл: почему без write

Dry-run (зеркало) дал пустой план по scope: `CREATE=0, UPDATE=0, PRUNE=0`.
Записывать нечего → pg_dump и транзакция не выполнялись (дамп «перед write» теряет
смысл при отсутствии write). Вместо post-audit выполнен **read-only аудит** текущего
состояния scope:

| Проверка | urovni·length | ugolniki·size |
|---|---|---|
| Дубли PAV (product+attribute) | 0 | 0 |
| `content_locked` в scope | 0 | 0 |
| Значения не engine-источников (manual/import_1c/llm) | 0 | 0 |
| `attrs_cache` vs EAV: нет в кэше / лишний в кэше / расходится | 0 / 0 / 0 | 0 / 0 / 0 |

`attrs_cache` полностью согласован с EAV по всем 253+156 товарам — точечная
пересборка не нужна. Глобальные `enrich_attributes` / `rebuild_attrs_cache`
не запускались. Координация с TT-цепочкой не потребовалась: write не было.

## 5. Витрина (живые запросы, dev.proff58.ru)

**Карточки отдают значения** (`attributes` детального API):
`products/00005623/` «Уровень 400 мм Профи 99А…» → `Длина 400 мм`;
`products/00002695/` «Уголок столярный 250мм MATRIX» → `Размер 250 мм`.

**Фильтры отсекают выборку** (`/api/catalog/products/`):

| Запрос | Товаров |
|---|---:|
| `category=izmeritelnyy-urovni&tool_type=izm-urovni` | 159 |
| … `&attr_length_min=1000` | **31** |
| … `&attr_length_min=1000&attr_length_max=1500` | **27** |
| `category=izmeritelnyy-ugolniki-i-lineyki&tool_type=izm-ugolniki` | 58 |
| … `&attr_size_min=400` | **11** |

Контроль по БД: опубликованных с `length ≥ 1000` — 32 по всем категориям, из них в
поддереве `izmeritelnyy-urovni` — 31 (1 товар живёт вне витринного поддерева) —
**сходится с API**. Диапазон 1000–1500: 28 → 27 по той же причине.

**Фасет-панель length/size не выводится.** `categories/izmeritelnyy-urovni/facets/` и
`categories/izmeritelnyy-ugolniki-i-lineyki/facets/` отдают только панель `tool_type`.
Причина в данных, не в коде: в цепочке категорий `izmeritelnyy/*` есть единственная
строка `CategoryAttribute` — для `tool_type`; `length`/`size` к дереву не привязаны
(двойной гейт `is_filterable` + `CategoryAttribute.is_filter`, `queries.py:41`).
Фильтрация при этом работает — она идёт через `ProductFilter`, а не через построитель
фасетов. Это пред-существующий пробел кураторства, не следствие CAT-01 → §7.1.

## 7. Требует решения владельца

1. **Фасеты length/size в измерительном дереве.** Значения на витрине есть в карточках
   и фильтры работают, но фасет-панель не показывает length/size: нет строк
   `CategoryAttribute` для категорий `izmeritelnyy-urovni`,
   `izmeritelnyy-ugolniki-i-lineyki` (и, вероятно, всего дерева `izmeritelnyy`).
   Привязка — кураторская операция (`catalog_seed_filters` или руками), **вне границ
   CAT-01** («новые Attribute/AttributeOption не создавать», фасетные связи не входили
   в задачу). Делать отдельной задачей?
2. **Атрибуция записи.** Кем/когда записаны 169+93 значения — по БД не видно (нет
   ImportRun, у PAV нет created_at). Если атрибуция важна — искать по логам стенда;
   если нет — закрыть как «применено ранее, качество подтверждено сверкой 100%».
3. **Хвосты вне scope** (без изменений с прошлых отчётов): `CREATE=4`
   (nozhovki 2, pilki-polotna 1, vorotki 1) и `PRUNE=17` от расхождения задеплоенного
   словаря с `dev`. CAT-01 их не трогал.
4. **Классификация в `izm-ugolniki`**: фитинги, платформа, кельма, бирки, абразивные
   треугольники (список в §3) — к TT-контуру. На значения `size` не влияет.
