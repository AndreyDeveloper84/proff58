## 3. Ловушки (поимённо, с критериями отсечения)

1. **`леска` 102 + `яялеска` 88 = один кластер 190.** Критерий TT-08
   (`name ILIKE '%леска%'` + «товар — сама леска») покрывает оба — `яя` регистр
   не мешает. **Пересечение разведено: CAT-07 леску не планирует** — TT-08
   (`tt-08-report.md` §2) забрал 190 + 2 из `izm-ugolniki`; на staging применение
   TT-08 — отдельная авторизация. Оставшиеся в типе 3 триммерные головки со
   словом «леска» — НЕ леска, идут в `golovki-trimmernye`.
2. **19 бензокос в `bp-trimmery`** со словом «леска» в характеристиках — не
   трогать (TT-08 подтвердил).
3. **«набор», «аксессуары», «комплект»** — слова-обманки: «Набор съёмников» идёт
   со съёмниками (контент однороден), «Набор аксессуаров…»/«Набор для…» — нет,
   остаётся в прочем. Критерий: переносить набор только если однотипное содержимое
   в названии (`набор съемников`, `набор гайкорезов`).
4. **Запчасти** (`втулка` вне [103], `оправка`, `кожух`, `патроны`-запчасти) — их
   место в `zapchasti`, но это перенос по дереву, не смена типа; вне scope разбора.
5. **Омонимы:** `кран` — гаражный гидравлический (→ грузоподъёмное) vs сантехнический
   (`hoz-krany` НЕ подходит); `шпильковерт` ≠ `krep-shpilki` (это крепёж);
   `siz-vysota` ≠ грузовые стропы; `zap-katushki` ≠ катушки триммера;
   `hoz-tachki` vs `obor-telezhki` — два типа про тележки, выбрать один при разборе.
6. **«Категория [181] Триммеры» ≠ тип `bp-trimmery`**: там расходка, машин нет.

## 4. Находка `яя` — проверено и доложено

### 4.1. Цифры (подтверждены своим запросом)

`name` начинается с `яя`: **4550 товаров, 2547 опубликовано** — точно как у
оркестратора. Префикс стоит в **обоих** полях (`name` и `original_name`, 4550/4550).

### 4.2. Влияние на витрину (проверено живыми запросами)

- **Сортировка — подтверждена.** Дефолт `order_by("name")`: последние страницы
  `osnastka-sverla` (1308 товаров) — сплошь `яяСверло…`. `яя`-товары в конце
  алфавитной выдачи.
- **Поиск — НЕ подтверждён в сильной форме.** API-поиск (`icontains` + trigram,
  `filters.py:97`) `яя`-товары **находит**: запрос «леска» → 178 результатов, из
  них 51 с префиксом (`live_search_leska.json`). Но ранг ниже: медианная позиция
  `яя` — 115 против 89 в целом (точное вхождение в `name` весит 10.0 +
  TrigramSimilarity, префикс сходство размывает). Итог: товар находится, но
  проседает в выдаче; в категории прячется в хвост.

### 4.3. Перезапишет ли 1С очищенное название — подтверждено ЧТЕНИЕМ КОДА

`apps/sync_1c/product_writer.py:update_existing` (строки 100–114): при обмене
обновляются цена/остаток и `original_name` («витринное name НЕ трогаем», комментарий
в коде), **`name` не записывается**. Запись `name=item.name` есть только в путях
создания товара (строки 60–72, 167–168). API витрины отдаёт `Product.name`
(`serializers.py:43`), поиск и сортировка работают по `name`. Кода, который
пересинхронизировал бы `name` из `original_name`, нет (grep по `apps/`).

**Вывод: чистка `Product.name` обменом не откатывается.** `original_name` префикс
вернёт — и должен: это сырое поле для матчинга/логов, на витрину не попадает.
Оговорка: вновь создаваемые из 1С товары с префиксом получат его в `name` снова —
чистку делать периодической или на хуке создания.

### 4.4. Дубли после снятия префикса

- **59 товаров** после снятия `яя` совпадут по `name` с уже существующим другим
  товаром (пример: «бур 12х460 SDS+ ЗУБР» — id 3167 `яя` и 2751 без: похоже,
  дубль заведён в 1С дважды);
- **141 товар** дублируется внутри самого `яя`-множества.
Итого ~200/4550 требуют разрешения коллизий (склейка/суффикс), а не простого
снятия префикса. Массовая правка 2547 видимых названий — за авторизацией владельца,
отдельной задачей.

## 5. Первая очередь разбора — рекомендация

**Кластер «смазки» → `str-smazki`**: 88 товаров, 32 опубликованных.

- тип **уже существует** в манифесте и в БД staging (проверено) — не нужен TT-контур
  для новой опции, маршрут recat-операции как в TT-08;
- критерий тривиален и воспроизводим: `tool_type='prochaya-osnastka' AND
  name ILIKE '%смазка%'` — все 88 начинаются со слова «Смазка», глазная выборка
  ложных не нашла;
- наибольший pub среди кластеров с готовым типом (после лески, которая у TT-08).

Следующими по очереди: `lebedki-tali` (82/16), `yashchiki-sumki` (81/16),
`obor-telezhki` (41/9) — тот же класс риска. Кластеры §2.2 (стропы, съёмники,
патроны, головки триммерные) — после заведения новых типов в манифест (TT-контур).
