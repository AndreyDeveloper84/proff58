## 0. Путь по ограничению `skip_if` (решение окна)

Выбран **вариант 1** (рабочий по умолчанию из промпта): движок не правим,
диапазоны вида `М6-М24` закрыты тем, что regex диаметра/шага якорится на
формат «М d х p» — в диапазоне между числами стоит `-`, а не `х`, поэтому
матча нет в принципе. Слова-стопы (`набор`, `держател`, `воротк`) выразимы
штатным `skip_if`.

Что вариант 1 **не ловит** (явная пометка по требованию промпта): диапазон,
записанный **через** «х» и не содержащий стоп-слов, например гипотетическое
«Плашки М6х1,0-М24х3,0» без слова «набор» — правило возьмёт первое значение
(`6`). В выборках CAT-14A таких названий не встретилось (все диапазоны —
у держателей/наборов, они закрыты `skip_if`). Если владелец захочет закрыть
и этот случай — это вариант 2 (`skip_if_regex`, правка
`attribute_extract.py`, смежного с CODE-01) — **вопрос вынесен, самостоятельно
не принят**.

## 1. `metchiki-plashki` (399 товаров, P0)

Схема: `diameter` (number, мм, regex 40, filter+seo), `thread_pitch`
(number, мм, regex 40, filter), `thread_type` (select, keyword 30,
filter+seo, с derive «metric» при наличии `diameter`), `material` (select,
keyword 30, filter+seo), `tool_kind` (select, keyword 30, filter+seo —
опциональный атрибут промпта, извлекается детерминированно).

- `skip_if = ["набор", "держател", "воротк"]` на всех четырёх
  характеристиках сущности (не на `tool_kind` — для него держатель/набор/
  вороток как раз значения). Основание: у держателей/воротков/наборов нет
  одного конкретного диаметра и шага — правило не применяется целиком
  (формулировка владельца). `thread_type` через derive без `diameter` не
  выводится, так что двойной защиты не требуется — но `skip_if` добавлен и
  туда, чтобы keyword-часть («метрическ», DIN) не срабатывала на наборах.
- `tool_kind`: порядок опций важен — «плашкодержатель»/«метчикодержатель»
  содержат «плашк»/«метчик», поэтому `derzhatel`/`vorotok`/`nabor` стоят
  раньше `plashka`/`metchik`. `unknown` ключевыми словами не матчится —
  выставляется derive-фолбэком с пустыми условиями (источник `inferred`,
  слабейший приоритет), как предписано промптом.
- В `material` добавлен keyword `9хc` (латинская «c») — реальный вариант
  написания «9ХC» в названиях 1С (товары 19254, 19236). «9х» без «с»
  осознанно НЕ добавлено: «М 9х1,25» давало бы ложный материал.
- «комплект 2 шт» НЕ в `skip_if`: у комплекта «Метчики ручные (комплект
  2 шт) М6х1,0» одно конкретное значение есть — извлекаем.

**Судьба старых блоков** (прямое требование владельца — не оставлять вторым
источником истины): блоки `metchiki` и `plashki` **удалены** из
`attribute_rules.json`, схемы перенесены в единый блок `metchiki-plashki`.
Выбор «удалить, а не оставить»: оба старых слага имеют 0 товаров, схемы
были идентичны — оставление создавало бы ровно запрещённое состояние
«две схемы на одну сущность». Зафиксировано тестом
`test_old_metchiki_plashki_blocks_removed` (`rules_for` старых слагов
пуст). Существующие 6 тестов metchiki/plashki мигрированы на новый слаг
без изменения утверждений — обратная совместимость схем подтверждена.
Словарь tool_type (`tool_type_rules.json`, слаги `metchiki`/`plashki`) —
вне периметра окна, не трогали.

Покрытие на выборке (20 реальных названий) против оценки CAT-14A:

## 2. `nabory-instrumenta` (157 товаров, P0)

Схема: `piece_count` (number, шт, regex 20, filter — slug переиспользован
из `nabory-otvertok`), `drive` (select, keyword 30, filter+seo — slug
переиспользован из `golovki`), `set_kind` (select, keyword 30, filter,
seo=false).

- `piece_count`: «пр / предметов / шт» — одна величина. Паттерны:
  `N предмет…`, `N пр[.]` с lookahead на пробел/пунктуацию/конец,
  `N шт`. Латинские модельные коды («1006PR», «F-41421R») не ловятся —
  «пр» кириллическое. Найдено при проверке: «25 пр, 1/4"» требует
  lookahead с запятой — учтено.
- `drive`: комбинированные приводы — отдельные значения (`1/4"+1/2"`,
  `1/4"+3/8"+1/2"`), опции упорядочены комбо-раньше-одиночных, т.к. select
  матчится подстрокой («1/4, 1/2"» содержит «1/4»). Ограничение владельца
  «число предметов ≠ размер привода» закрыто непересекающимися якорями
  («пр/предмет» vs дробь) + негативным тестом.
- `set_kind`: экстракторы / выколотки / торцевые / биты / универсальный.

| Атрибут | Выборка 20 | CAT-14A (популяция) |
|---|---|---|
| `piece_count` | 20/20 = 1.00 | 0.92 |
| `drive` | 8/20 = 0.40 | 0.32 |
| `set_kind` | 20/20 = 1.00 | — |

Известный шероховатый край: keyword «1/4» как подстрока ловил бы и «11/4»
(«1 1/4"») — в выборках не встречается; при появлении — потребует
regex-select (та же правка движка, что в §0/§5).

## 3. `krep-bolty` (194 товара, P1)

Схема: `thread_diameter` (number, мм, regex 40, filter+seo), `length`
(number, мм, regex 40, filter, seo=false — slug `length` переиспользован
общий «Длина»), `head_type` (select, keyword 30, filter+seo: шестигранная/
потай/полукруглая/с фланцем), `coating` (select, keyword 30, filter+seo:
цинк/чёрное).

- Размеры — **только явный «Мd×L»**: regex требует букву «М» (кириллица
  или латиница — «M6X20»), цифру, «х», цифру. `skip_if = ["набор"]`
  (наборы для выворачивания болтов — не болт с размером).
- «Винт 4х55» **без буквы «М»** — размер не назначается (строгое прочтение
  ограничения владельца). В выборке таких 5/20 — все винты («потай»/
  «полукруг.»); они получают `head_type` и `coating`, но не размер.
  **К владельцу:** если «Винт 4х55» считать явным форматом — добавить
  второй паттерн `винт\s+(d)×(L)`, это +5/20 (по выборке) к покрытию
  размером. Самостоятельно не расширял.
- Размер в артикуле (`B800A06X008`) не извлекается (латинская «X» внутри
  кода не матчится якорю «М») — backlog CAT-15, по CAT-14A таких 97/194.

| Атрибут | Выборка 20 | CAT-14A (популяция) |
|---|---|---|
| `thread_diameter`/`length` | 13/20 = 0.65 | 0.50 |
| `head_type` | 17/20 = 0.85 | — |
| `coating` | 5/20 = 0.25 | — |

Backlog CAT-15 из выборки: 1 товар с размером в артикуле (8010) + 5 винтов
без «М» (если владелец подтвердит строгое прочтение) + 1 набор (22654).

## 5. `zap-shchetki-ugolnye` (165 товаров, P2)

Схема: `dim_a`/`dim_b`/`dim_c` (number, мм, regex 40, filter, seo=false —
три габарита AxBxC отдельными числами), `compat_brand` (select, keyword 30,
filter+seo: HITACHI/MAKITA/BOSCH).

- Габариты — только формат «AxBxCмм» линейки «АНАЛОГ» (якорь «мм» сразу
  после третьего числа). Запись «7*13*23» без «мм» (коллекторные 699)
  осознанно не ловится — формат другой, владелец указал «мм».
- `skip_if = ["пылесос", "держател", "крышк"]` на всех правилах: щётки
  пылесосов (2/20 в выборке) — иная сущность, аксессуары (держатель/крышка
  щёток) — не щётки.
- **`analog_code` не выражается движком**: значения вида «13-102» — не
  Decimal (number отпадает), множество кодов открытое (select отпадает).
  Требование владельца «хранить отдельно от габаритов» тем самым выполнено
  тривиально — поля нет. Для ввода `analog_code` нужен text-kind в движке
  — **вынесено владельцу** вместе с вопросами §0/§4 (все три — кандидаты
  в одну правку `attribute_extract.py` после CODE-01). По CAT-14A код есть

  (`test_zu_vacuum_brush_skipped`);
- болт без «Мd×L» не получает размер — артикул (`test_kb_article_code_no_size`)
  и винт без «М» (`test_kb_vint_head_coating_no_size`);
- класс вязки не попадает в size перчаток — не применимо: правил перчаток
  нет (задача 4 стоит), тест появится вместе с правилами после утверждения
  таблицы;
- число предметов не попадает в `drive`, дробь привода — не в
  `piece_count` (`test_ni_pieces_and_drive_do_not_overlap`);
- обратная совместимость: 6 мигрированных тестов metchiki/plashki без
