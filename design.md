# MASTER.md — Дизайн-система «Профессионал — территория инструмента» (v3, светлая тема)

Единый источник истины по визуальному языку магазина **penzainstrument.ru**:
профессиональный электро- и ручной инструмент, оснастка, садовая техника, оборудование.
Пенза и область. Гибрид B2C + B2B. Первый экземпляр **переиспользуемого движка** —
магазинная специфика (бренд, зоны, реквизиты) живёт в `SiteSettings`, а не в коде.

> **Тема — светлая, бренд — наследуется.** Фирменные цвета взяты с визитки
> (Визитка.jpg): чёрно-графитовое поле, электрический зелёный, белый. В светлой теме графит
> уходит из фона в текст и в тёмную шапку/подвал (узнаваемость визитки), холст — белый/светлая
> сталь, зелёный остаётся сигналом действия и наличия.
>
> **История версий:** v1 — ошибочный придуманный бренд (отозван). v2 — тёмная тема из
> `SiteSettings`. **v3 (актуальная)** — светлая тема, направление **«Чистая мастерская»**,
> на фирменном зелёном с визитки. Токены — дефолты движка, перекрываются из `SiteSettings`.

---

## 0. Режим работы (как принимаются решения)

- Сначала выводим из контекста, спрашиваем только блокеры. Допущения проговариваем и идём дальше.
- Реальный бренд/токены/стек **наследуем и достраиваем**.
- Экран — **контракт состояний**, а не картинка: без состояний/адаптива/доступности не готов.
- Смелость тратим в **одном** signature-приёме («Инструментальный кант»), остальное тихое.

## 1. Аудитория, роли, KPI

**Аудитория.** Профессионалы (стройка, ремонт, производство, сервис) и домашние мастера —
B2C; закупщики юрлиц — B2B. Боль: быстро найти инструмент по характеристикам и понять —
в наличии ли, когда заберёшь.

**Роли.** Гость · Покупатель B2C · Юрлицо B2B · Менеджер · Кладовщик · Контент-менеджер ·
Администратор · системная роль 1С.

**Главное действие / KPI.** B2C — оформленный и **оплаченный** заказ; B2B — **запрос счёта**
на юрлицо (PDF). Guardrail — доля отказов/возвратов и брошенных корзин не растёт.

## 2. Бренд и тема — светлая (реальные цвета визитки, перекрываются из `SiteSettings`)

Белый холст, графитовый текст, тёмная шапка/подвал «как визитка». Зелёный — действие и
доверие (наличие, ссылки, иконки). Семантика статусов — отдельно от бренда.

```css
:root {
  /* Поверхности — светлые */
  --bg:             #FFFFFF;   /* холст страницы */
  --surface:        #F5F7F8;   /* карточки, поля, секции */
  --surface-raised: #FFFFFF;   /* приподнятые карточки (на --bg) — отделяются тенью/границей */
  --surface-inverse:#0D0F0E;   /* тёмная шапка/подвал — преемственность визитки */
  --border:         #E2E7EA;   /* hairline-границы */
  --border-strong:  #CBD2D7;   /* hover/активные границы */

  /* Текст */
  --text:           #16191B;   /* графит (как «ПРОФЕССИОНАЛ» на визитке) */
  --text-secondary: #545C62;
  --text-muted:     #8A9298;
  --text-inverse:   #FFFFFF;   /* на тёмной шапке/CTA */

  /* Бренд (фирменный зелёный визитки) */
  --green-500:      #07B453;   /* электрический изумруд — иконки, бренд-марк, акцент */
  --green-600:      #0B8A43;   /* бренд-зелёный */
  --green-700:      #097A3C;   /* CTA по умолчанию (белый текст — AA) и ссылки */
  --green-800:      #085C2E;   /* active/pressed */
  --green-50:       #E8F6EE;   /* tint: «в наличии», подсветка */
  --lime-500:       #6CB52F;   /* травяной лайм с канта визитки — только сигнатура/иконки */

  /* Семантика статусов (НЕ бренд) */
  --danger:         #D7322B;   /* нет в наличии, ошибка, отмена */
  --danger-50:      #FCEAE9;
  --warning:        #C77A12;   /* под заказ, предупреждение */
  --warning-50:     #FBF1E0;
  --rating:         #E6A93A;   /* звёзды рейтинга */
}
```

> На проде `:root` инжектится из `SiteSettings`. Второй экземпляр движка меняет только конфиг.

### 2.1 Производные (вычисляются из бренда, новые «вкусовые» цвета не вводим)

|---|---|---|
| `--green-cta-hover` | `--green-800` `#085C2E` | hover CTA |
| `--green-cta-active`| `#074D27` | pressed CTA |
| `--green-tint` | `--green-500` @ 10% на `--bg` | фон выбранного, фокус-фон, активный фасет |

| `--overlay` | `#0D0F0E` @ 55% | подложка модалок/drawer |
| `--skeleton` | `--surface` → шиммер к `#ECEFF1` | загрузка |
| `--instock-bg` | `--green-50` | фон «в наличии» |

## 3. Архитектура токенов

Три слоя. Компоненты ссылаются **только** на семантику. Сырой hex в компонентах запрещён —
это и даёт перекраску темы из `SiteSettings`.

```
Бренд/примитив (SiteSettings)  →  Семантика (назначение)  →  Компонент
--green-700 #097A3C            →  --color-action: var(--green-700) → --btn-primary-bg
```

### 3.1 Семантический слой

```css
:root {
  --color-bg:            var(--bg);
  --color-surface:       var(--surface);
  --color-surface-raised:var(--surface-raised);
  --color-surface-inverse:var(--surface-inverse);
  --color-border:        var(--border);
  --color-border-strong: var(--border-strong);

  --color-text:          var(--text);
  --color-text-secondary:var(--text-secondary);
  --color-text-muted:    var(--text-muted);
  --color-text-inverse:  var(--text-inverse);

  --color-action:        var(--green-700);   /* «В корзину», главный CTA */
  --color-action-ink:    var(--text-inverse);/* белый текст на CTA */
  --color-action-hover:  var(--green-cta-hover);
  --color-action-active: var(--green-cta-active);
  --color-brand:         var(--green-500);   /* лого, иконки, акцент (не мелкий текст на белом) */

  --color-link:          var(--green-700);   /* ссылки — AA на белом */
  --color-instock:       var(--green-700);
  --color-instock-bg:    var(--instock-bg);
  --color-backorder:     var(--warning);
  --color-backorder-bg:  var(--warning-50);
  --color-outstock:      var(--danger);
  --color-outstock-bg:   var(--danger-50);

  --color-success:       var(--green-700);
  --color-warning:       var(--warning);
  --color-danger:        var(--danger);
  --color-rating:        var(--rating);
}
```

### 3.2 Контраст (светлая тема — проверяем честно)

| Пара | ≈ Коэффициент | Вывод |
|---|---|---|
| `--text #16191B` на `--bg #FFFFFF` | 16.1:1 | AAA |
| `--text-secondary #545C62` на `--bg` | 7.0:1 | AA+ |
| `--text-muted #8A9298` на `--bg` | 3.5:1 | только крупный/utility ≥ 16px |
| `--text-inverse #FFF` на CTA `--green-700 #097A3C` | 4.6:1 | AA — белый текст на CTA читается |
| `--color-link #097A3C` на `--bg` | 4.6:1 | AA для текста/ссылок |
| `--color-brand #07B453` на `--bg` | 2.5:1 | **только иконки/бренд/крупное** — не мелкий текст |
| `--text-inverse` на шапке `#0D0F0E` | 18:1 | AAA |
| `--danger #D7322B` на `--bg` | 4.8:1 | AA |

> Правила: CTA и ссылки — `--green-700` (не изумруд `--green-500`). Изумруд `--color-brand`
> только для иконок/лого/крупных акцентов. «В наличии» — зелёный **+ иконка-точка** (цвет
> не единственный носитель смысла).

## 4. Типографика

Характер задают условные капс-заголовки (трекинг как «ТЕРРИТОРИЯ ИНСТРУМЕНТА» на визитке) +
нейтральный Inter для интерфейса и данных.

```css
:root {
  --font-display: "Oswald", "Saira Condensed", system-ui, sans-serif; /* заголовки, КАПС */
  --font-body:    "Inter", system-ui, -apple-system, "Segoe UI", Roboto, sans-serif;
  --font-utility: "Inter", system-ui, sans-serif; /* данные, артикул — tabular-nums */
}
```

- Заголовки `--font-display`: `text-transform: uppercase; letter-spacing: .01–.03em;` вес 600–700.
- Цены, остатки, артикул, размеры: `--font-utility` + `font-variant-numeric: tabular-nums`.

## 5. Отступы, радиусы, тени, границы

**Spacing (база 4px):** `0·4·8·12·16·20·24·32·40·48·64·80` → `--space-0…--space-20`.

**Радиусы:** `--radius-sm 4` · `--radius-md 6` (дефолт: кнопка/карточка) · `--radius-lg 10` ·
`--radius-xl 14` · `--radius-full 9999`.

**Тени (светлая тема — мягкие, холодные):**

```css
--shadow-e1: 0 1px 2px rgba(13,15,14,.06);   /* карточка в покое */
--shadow-e2: 0 2px 10px rgba(13,15,14,.08);  /* карточка hover */
--shadow-e3: 0 10px 28px rgba(13,15,14,.12); /* поповер, дропдаун */
--shadow-e4: 0 18px 48px rgba(13,15,14,.16); /* модалка, drawer */
--shadow-focus: 0 0 0 3px var(--focus-ring);
```

**Границы:** `1px var(--color-border)` дефолт; hover-интерактив — `--color-border-strong`;
выбранное/активное — `2px var(--color-action)`. На белом холсте `--surface-raised` карточки
отделяются тенью `e1` + границей, секции `--surface` — сменой тона.

## 7. Иконки, фото, моушн

- **Иконки:** линейные, штрих ~2px, единый набор (Lucide/Tabler). Размеры 16/20/24.
  Бренд-иконки и «инструментальный кант» (§10) — в стиле гравированных глифов визитки.
- **Фото товара:** на `--surface`, **1:1** в каталоге, объект по центру. Реальные фото
  инструмента/схемы/размеры — без стоковой глянцевости.
- **Моушн:** `--motion-fast 120ms` · `--motion-base 200ms` · `--motion-slow 320ms`;
  `--ease-out cubic-bezier(.16,1,.3,1)`. Уважать `prefers-reduced-motion: reduce`.

## 8. Контракт состояний (обязателен для каждого экрана)

**Базовые:**
- **Loading** — скелетоны в форме контента (`--skeleton`, шиммер), не спиннер на весь экран.
- **Empty** — приглашение к действию. Поиск без результата → «Ничего не нашли по “…”.
  Проверьте артикул или сбросьте фильтры» + кнопки reset / в каталог.
- **Error** — голосом интерфейса, без извинений, с выходом: «Не удалось загрузить. Повторить».
- **Offline** — баннер «Нет сети. Показаны последние данные»; действия, меняющие заказ, блокируются.

**Доменные состояния (учитывать всегда):**

| Состояние | Поведение в UI |
|---|---|
| **Нет в наличии** | Бейдж `--color-outstock` + иконка; CTA → «Уведомить» / «Под заказ». |
| **Под заказ** | Бейдж `--color-backorder` «Под заказ, ~X дн.»; покупка доступна, срок проговорён. |
| **Цена изменилась** | В корзине/checkout — плашка «Цена обновилась: было → стало», явное подтверждение, не списываем молча. |
| **Гость vs авторизован** | Гость видит розницу; B2B-цена и счёт-PDF — после входа как юрлицо. Гость может привязать MAX на «Спасибо». |
| **Цена по роли** | Одна карточка: `pricing.price_for(product, user)`. Слот B2B-цены заложен всегда. |
| **Частичная доступность корзины** | Помечаем недостающие строки; checkout: «оформить доступное» / «убрать недоступное». |
| **Резерв истёк (expired)** | Бронь 15 мин при онлайн-оплате; по истечении — статус expired, плашка «Бронь истекла», пере-проверка остатка/цены. |

## 9. Компоненты

Состояния — часть компонента. Все цвета — через токены.

### 9.1 Кнопки

```css
--btn-h-sm:32px; --btn-h-md:40px; --btn-h-lg:48px;
--btn-radius: var(--radius-md); --btn-weight:600; --btn-pad-x: var(--space-4);
```

**Primary — «В корзину» / «Оформить заказ»:**

| | Default | Hover | Active | Disabled | Loading |
|---|---|---|---|---|---|
| Фон | `--color-action` | `--color-action-hover` | `--color-action-active` | `--surface` | `--color-action` |
| Текст | `--color-action-ink` | белый | белый | `--text-muted` | белый + спиннер |
| Тень | `--shadow-e1` | `--shadow-e2` | none | none | `--shadow-e1` |

**Secondary** — фон `--bg`, текст `--color-action`, граница `1px --color-action`; hover-фон
`--green-tint`. **Ghost/tertiary** — прозрачный, текст `--text-secondary`, hover-фон `--surface`.
**Link** — текст `--color-link`, подчёркивание по hover. **Danger** — текст `--danger`,
граница `--danger`, hover-фон `--danger-50`. Фокус всем: `--shadow-focus`. Тач-таргет ≥ 44px.

### 9.2 Статус наличия (цвет + иконка + текст)

| Статус | Иконка | Текст | Фон |
|---|---|---|---|
| В наличии | ● `--color-instock` | «В наличии · N шт» | `--color-instock-bg` |
| Под заказ | ◷ `--color-backorder` | «Под заказ · ~X дн» | `--color-backorder-bg` |
| Нет в наличии | ○ `--color-outstock` | «Нет в наличии» | `--color-outstock-bg` |
| Есть в магазине | ⌂ `--color-link` | «Самовывоз сегодня» | `--green-tint` |

### 9.3 Бейдж статуса заказа (3 оси → 1 человекопонятный)

Оси (обработка · оплата · выгрузка в 1С) сводятся в `Order.display_status`. **Не использует
бренд-зелёный в смысле «действие»** — наличие/статус и CTA визуально разведены:

| Display-статус | Цвет |
|---|---|
| Новый / Ждёт оплаты | `--warning` |
| Оплачен / В сборке | `--text-secondary` на `--surface` (нейтрально-инфо) |
| Готов к выдаче / В пути | `--color-instock` |
| Выполнен | `--text-muted` |
| Отменён / Возврат / Бронь истекла | `--danger` |

### 9.4 Блок цены (по роли)

```
30 990 ₽            (--price-lg/md, 800, tnum, --text)
36 990 ₽   −16%     (--price-old зачёркнута muted + бейдж скидки)
1 549 ₽ / шт        (--text-xs muted — цена за единицу)
B2B: 27 400 ₽       (слот; виден юрлицу — --color-link, иконка)
```

Текущая цена — крупнейший числовой элемент. Слот B2B присутствует в разметке всегда
(скрыт для розницы). Скидочный бейдж — фон `--lime-500`/тёмный текст ИЛИ `--danger` для
распродажи (выбираем одно, по умолчанию — нейтральный graphite-бейдж со скидкой текстом).

### 9.5 Карточка товара (PLP)

`--surface-raised` фон, граница `--border`, радиус `--radius-md`, тень `--shadow-e1`,
padding `--space-3`. Сверху вниз: фото 1:1 (+ бейджи: скидка/хит/новинка) → бренд (utility
muted) → название (2 строки clamp, `--text-sm`) → 2–3 ключевые ТТХ (`--text-secondary`) →
статус наличия → блок цены → «В корзину» + степпер. Hover: тень `e2`, граница `--border-strong`.
Карточка — ссылка; кнопка/степпер — отдельные зоны.

### 9.6 Степпер количества

`[ − ] [ N ] [ + ]`, высота = высоте кнопки, поле с tabular-nums, граница `--border`,
кнопки 40×40, hover-фон `--surface`. Ограничение по остатку с подсказкой.

### 9.7 Поля ввода / поиск / фасеты

- Инпут: фон `--bg`, граница `--border`, focus — `2px --color-action` + `--shadow-focus`,
  error — `2px --danger` + текст ошибки под полем (`aria-invalid`, `aria-describedby`).
- **Поиск:** по артикулу / модели / бренду + подсказки в поповере `--shadow-e3`. Крупное
  поле в шапке (h 48 десктоп). Перспектива — AI-подбор/сравнение (точка входа, см. 9.10).
- **Фасеты (EAV) со счётчиками:** цена (двойной слайдер, активная дорожка `--color-action`),
  наличие, бренд, мощность, энергия удара, тип патрона, назначение. Активный чип:
  `--green-tint` фон, текст `--color-action`, крестик. «Сбросить всё» — link.

### 9.8 Таблица характеристик (PDP)

Зебра чётных — `--surface`. Ключ — `--text-secondary` (~40%), значение — `--text` вес 500.
Hairline `--border`. `--text-sm`, размеры/единицы — tabular-nums.

### 9.9 Шапка / подвал (тёмные — преемственность визитки)

- **Шапка** на `--surface-inverse #0D0F0E`, текст `--text-inverse`, sticky. Верх: телефон,
  режим, адрес магазина, вход / «Войти как юрлицо». Низ: лого (зелёный бренд-марк) + крупный
  поиск (светлое поле) + корзина (счётчик — бейдж `--color-action`). Кнопка «Каталог» →
  мегаменю (`--shadow-e3`, на светлом). Левый край шапки — «инструментальный кант» (§10).
- **Подвал:** `--surface-inverse`, разделы, контакты, реквизиты, зоны доставки, иконки
  оплаты (ЮKassa/СБП/наличные/счёт-юрлицу) — сигнал доверия.

### 9.10 MAX-бот и AI-консультант (реальные точки входа, не декор)

- **«Отслеживать в MAX»** — обязательная кнопка-deep link на «Спасибо за заказ» и в кабинете.
  Бот не пишет первым → ведём сами. Сохраняет `max_chat_id` (в т.ч. для гостя). OTP —
  `request_contact` + «Скопировать код». Стиль: secondary-кнопка с иконкой MAX + микротекст
  «Статусы и чек — в MAX».
- **AI-консультант** на PDP и в боте — контракт `ai.services.assist` (старт — заглушка,
  V2 — реализация). Реальная панель: поле вопроса, состояния loading/empty/error, дисклеймер
  «подбор по характеристикам». Кнопка «Спросить о товаре», не баннер-декор.

## 10. Signature-элемент — «Инструментальный кант»

Один запоминающийся приём, взятый **прямо с визитки**: вертикальный зелёный рейл с
гравированными line-art иконками инструмента (дрель, пила, болгарка, гайковёрт).

- Используется как **единый брендовый акцент в одном месте**: левый край тёмной шапки
  (и опционально — тонкая полоса-разделитель крупных секций / hero категории).
- На светлом холсте — `--color-brand` глифы на тёмном `--surface-inverse` (контраст визитки),
  либо очень тихие muted-глифы как фон-паттерн hero (низкая непрозрачность).
- Смелость потрачена здесь; весь остальной интерфейс — белый холст + графит + один зелёный CTA.
- Уважает reduced-motion (без «протяжки» глифов при reduce).

> Самокритика §4 пройдена: светлая тема + зелёный — реальный бренд, не дефолт. Чтобы не
> скатиться в «кремовый + акцент», холст держим нейтрально-стальным, зелёный строго
> ограничен (CTA, наличие, ссылки, бренд-марк, кант). Лайм `--lime-500` — только в канте/
> бейдже, не разливаем по интерфейсу. «Убран один аксессуар»: декоративные свечения под
> зелёным не вводим.

## 11. Карта экранов (цель · контекст · следующий шаг · что может пойти не так)

| Экран | Цель | Откуда | Ведём к | Риск/edge |
|---|---|---|---|---|
| Главная | Вход в каталог/поиск + доверие | реклама, прямой, повтор | Категория/Поиск | перегруз промо → фокус на поиске |
| Каталог (дерево) | Сориентировать по разделам | главная, меню | PLP | глубокое дерево → крошки + поиск |
| Категория (PLP) | Отфильтровать до нужного | каталог, поиск | PDP | пустая выдача → empty с reset |
| Поиск | Найти по артикулу/модели/бренду | шапка | PDP/PLP | опечатка/нет результата → подсказки |
| Карточка (PDP) | Решиться и добавить в корзину | PLP/поиск/бот | Корзина | нет в наличии → «под заказ»/«уведомить» |
| Корзина | Проверить состав и цену | PDP, шапка | Checkout | цена изменилась/частичная доступность |
| Checkout | Оплатить (B2C) / запросить счёт (B2B) | корзина | Спасибо | отказ оплаты, истёк резерв |
| Спасибо / Отслеживание | Подтвердить + привязать MAX | checkout | MAX, кабинет | гость без аккаунта → deep link MAX |
| Кабинет B2C | История/статусы/повтор | вход | повтор заказа | — |
| Кабинет B2B | Счета-PDF, юрлицо, цены | вход B2B | запрос счёта | несколько юрлиц/доверенностей |
| Опс-панель | Менеджер/кладовщик/контент/админ | внутр. | обработка | права ролей, статусы по осям |

Детальная проработка экрана: 4 ветки флоу (happy · альтернатива · ошибка · пограничный) +
полный контракт состояний (§8).

## 12. Измеримость (часть каждого флоу)

| Флоу | Событие успеха | Шаг воронки | Guardrail | Гипотеза A/B |
|---|---|---|---|---|
| Покупка B2C | `order_paid` | checkout → оплата | рост брошенных корзин | «Купить в 1 клик» на PDP ↑ конверсию без роста возвратов |
| Запрос счёта B2B | `b2b_invoice_requested` | PDP/корзина → запрос | время до счёта | предзаполненные реквизиты юрлица ↑ долю запросов |
| Поиск → товар | `search_result_click` | поиск → PDP | доля пустых выдач | подсказки по артикулу ↓ нулевые выдачи |
| Привязка MAX | `max_linked` | Спасибо → deep link | — | явный микротекст-выгода ↑ долю привязок |
| Фасетный подбор | `add_to_cart` после фильтра | PLP → корзина | глубина без покупки | счётчики у фасетов ↑ переход в PDP |

## 13. Этика и конверсия (с границей)

- Срочность/дефицит — только настоящие (остаток из 1С, реальный срок брони 15 мин).
- Запрещено: ложные таймеры, скрытые предвыбранные допы, тихие подписки, искусственная
  скудость, навязанные шаги.
- Конфликт «польза vs краткосрочная конверсия» → пользователь и LTV, проговариваем.

## 14. Контент и тон

Sentence case, активный залог, без воды. Кнопка говорит результат («Оформить заказ»,
«Запросить счёт», «В корзину») и сохраняет имя через весь флоу. Ошибки — без извинений и
размытости, с выходом. Пустой экран — приглашение. Язык пользователя («патрон», «энергия
удара»), не схема системы. Реальный текст, не lorem.

## 15. Хендофф в код

### 15.1 CSS-переменные
Бренд-токены (§2) инжектятся из `SiteSettings` в `:root`. Семантика (§3.1), производные
(§2.1), типографика (§4), spacing/radius/shadow (§5), моушн (§7) — в
`frontend/src/styles/tokens.css`. Компоненты используют **только** семантические токены.
На старте — вёрстка на дизайн-системе и фикстурах в форме будущего каталожного API.

### 15.3 Правила
1. Сырой hex в компонентах запрещён — только токены (перекраска из `SiteSettings`).
2. CTA/ссылки/наличие — `--green-700` (AA). Изумруд `--color-brand` — иконки/лого/крупное.
3. Статусы заказа/наличия — своя семантика, визуально разведены с CTA.
4. Цены/коды — tabular-nums; слот B2B-цены присутствует всегда.
5. Тёмная шапка/подвал — обязательны (преемственность визитки).
6. Источник истины — этот MASTER.md.
